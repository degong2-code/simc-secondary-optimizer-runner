# P3-AA — 사용자 최종 교정: 환경 DB 구축 엔진 단일화와 기존 자료 없는 새 시즌 통제실험

**기준일:** 2026-11-02 KST. **정책 지위:** 사용자 최신 직접 결정. 다른 문서의 "SimC-only 통제실험에서는 Wago/Blizzard/WCL 등의 외부 신규 수집을 금지한다"는 표현보다 **우선**한다. 기존 v1.4.3 시즌별 G/J/F/O 자동 구축 및 기타 비충돌 정책 유지.

## 1. 사용자가 검증하려는 실제 능력

실제 새 시즌 출시 시 일반 사용자는 프로그램에서 **「새 시즌/확장팩 환경 구축」**을 한 번 요청한다. **하나의 실사용 Environment DB Build 엔진**이 현재 시즌/확장팩·게임 빌드·SimC revision을 식별하고, 승인된 외부 자료를 새로 수집·교차검증하여 대표 일반 장비·무기·티어, 검증된 장신구·특수장비·제작장비·장식, 최고 품질 보석·영약·음식·물약, 영구 마부와 지원되는 무기 기름을 찾아 내부 환경을 준비한다. 시즌별 G/J/F/O를 원본/SimC·필요한 범위의 Native 증거로 정합하고 B=G+J+F, T=B+O, L/E/O 중복 방지 및 수동 T 우선을 적용한다. 확인된 항목은 정책 A로 자동 등록하고 미확정 선택지만 보류하며, version/manifest/session/cache identity와 SimC 프로필 생성 경로를 연결한다. 사용자가 별도로 Start하면 기존 적응형 SimC DPS/SEM/95%/대안 엔진을 실행한다. 새 gear recommendation DB·새 optimizer·proc 재구현은 하지 않는다.

## 2. 왜 통제실험을 하는가

현재 시즌의 환경 DB는 이미 수집되어 있으므로 단순히 기존 엔진이 설치된 파일을 다시 읽는 것으로는 **새 시즌의 제로베이스 자동 구축 능력**을 검증할 수 없다. 따라서 완성된 제품 엔진을 **현재 시즌에 대한 모든 사전 수집·관측 결과가 없는 빈 환경**에 넣고, 현재 시즌을 처음 발견한 새 시즌처럼 실제 수집·결합·검증·구축하도록 한다. **엔진 자체와 실행 진입점, 정상 제품의 데이터 수집·검증 경로는 바꾸지 않는다.** 통제는 데이터 상태와 비교 시점에 적용하는 **시험 하네스**에만 둔다. 구축 완료 출력은 사전 봉인하고, 그 후 별도 평가자가 기존 구축된 시즌 환경과 비교한다.

## 3. 반드시 구분할 허용/금지 범위

| 대상 | 최종 통제실험 적용 |
|---|---|
| 정상 제품이 사용하는 SimC 소스/실행 파일과 새로운 동일 빌드 원본 다운로드 | **허용** |
| Wago.tools DB2, Blizzard 게임 데이터 API, WCL 시즌 콘텐츠 정보, 검증된 공개 GitHub/Localbots 및 정상 제품의 기타 승인된 신규 외부 데이터 수집 | **허용**. 원본 URL, 시즌/빌드, 버전, HTTP·원본 SHA와 수집 시각 기록 |
| 현재 시즌의 기존 `data/current_season_*` 파일, 511개 기존 후보 DB, 선별 ID seed, 설치된 v213/v191 결과물, 기존 G/J/F/O 숫자·v089 참조표, 옛 프로필 및 역사 Native·DPS 영수증 | **입력·근거·후보 필터·비교 정답으로 사용 금지**. 빈 출력 상태에서 새로 산출 |
| 기존 SimC 정적/DPS 캐시 및 이전 세션·GitHub Actions 산출물 | **읽기·복원·검증 증거로 사용 금지**. 실험 실행 중 새로 생성한 출력·캐시만 사용 가능 |
| 엔진 프로그램 코드, 보편적인 파서·수집기·분류기·SimC 실행기·증분 갱신기 | **사용 필수**. 실험 전용으로 복제·간소화·우회하거나 특정 기존 시즌 결과를 코드에 심어서는 안 됨 |
| 구축 이전의 기존 시즌 DB와 자동 비교·부족한 ID 보충 | **금지**. 시험 결과 봉인 및 무결성 기록 **후** 독립 평가자가 참조 가능 |

**중요:** "SimC-only"는 이전에 수행한 **제한된 SimC 원본 조사 실험의 역사적 명칭**일 뿐, 사용자가 승인한 **최종 통제실험의 접근 권한이나 제품 모드가 아니다.** 외부 Wago/Blizzard/WCL/공개 GitHub 신규 다운로드를 제한하면 사용자가 검증하려는 **완성된 정상 엔진**과 달라져 통제실험의 타당성을 해친다. 테스트 하네스는 **과거에 가지고 있던 자료의 접근을 차단**해야지 **정상 신규 수집 경로를 차단**해서는 안 된다.

## 4. 단일 엔진 계약 / 완료 판정

1. **동일 Build 진입점과 동일 오케스트레이터**: 일상적인 새 시즌 구축과 최종 제로베이스 시험은 같은 설치·수집·프로필·예산·출력 흐름을 실행한다. 런타임에 `SimC-only` 분기, 별도 제품, 다른 대표장비 선택기가 있어서는 안 된다. 기존 v229~v237 등 실험용 코드는 필요한 범위에서 공통 수집기/파서/Native 보조 컴포넌트로 재사용하며 그 자체가 Build 엔진은 아니다.
2. **새 원본 수집**: 시즌 식별→Wago DB2/Blizzard/WCL/공개 자료 및 SimC 실시간 요청→ID·tier/normal gear/weapon·선택지 관계 조인. 구 확장팩 ID라도 현 시즌 쐐기 로테이션이라면 유효할 수 있으므로 ID 대소/원본 ilvl만으로 배제하지 않는다. 현재 시즌 이미 알려진 ID/값을 입력으로 넣지 않는다.
3. **G 포함 전 항목**: 같은 시즌 대표 일반 장비·무기·4pc, 목표 ilvl의 G 산출/유효 시즌 참고 근거, 검증된 J/F/O 및 마부 E·선택 L·최고 품질/효과·옵션을 증거에 따라 결정한다. G=2847 같은 정확한 Native 정적 관측값과 특정 시즌의 장비 출처 적합성은 구별하되, 적법한 같은 시즌·같은 조건의 근사 참조도 사전에 승인된 회계에 따라 사용할 수 있다. 실험 초기에는 예전 참조를 몰래 가져오지 않는다.
4. **신뢰성/효율**: 같은 실행 내 중복 HTTP/Native 제거, 최소 필요한 정적 Native, 요청 간 신원 및 증분 의존성 추적, 실패 원문 보존. 실험의 새 캐시는 허용하지만 과거 캐시 히트는 금지.
5. **결과와 증거**: 생성한 시즌 환경 DB·UI 목록·입력과 동일한 SimC 프로필·G/J/F/O/B/T·검증/미확정 항목·로그·빌드/commit/sha/옵션/호출 수·캐시 identity를 **비교 전에 봉인**하고 그 뒤 기존 시즌과 차이를 대조한다. 완전 재구축 여부뿐 아니라 SOURCE_INSUFFICIENT/적용 미확정/수치 차이/캐시 침해도 범주별 판정.
6. **사용 시점**: 전체 Environment Build 엔진과 일반 제품 경로가 실질적으로 완성된 후 한 차례 통합 인수시험으로 실시한다. 지금까지의 v229/v235/v237 원본·Native 시험이나 CI 279 PASS는 제한된 컴포넌트의 범위 증거이며 **최종 통제시험 PASS가 아니다**.

## 5. 실제 구현 현황과 변경 권한

현재 `v160~v171` 정상 소스 수집, `v191` 단편 통합, `v213` 설치 산출물, `v216` 기존 설치 환경 재사용, `v220/v222` 등록·예산 계약, `v229~v237` 실험용 SimC 원본/Native 경로는 각각 구현된 범위가 있다. **현재까지 신규 시즌 원본 수집→G/J/F/O 자동 산출→B/T→정책 A 자동 발행→환경 설치를 같은 Build 요청으로 완주한 증거는 없다.** 완성이라고 주장하지 않는다.

이 문서와 충돌하는 `P3-U/W/X/Y/Z`의 과거 "최종 SimC-only", "Wago/Blizzard 차단" 표현은 **당시의 잘못된 요구 해석 및 역사 기록**이다. 최신 사용자 직접 결정 및 본 교정이 우선한다. 기존 실험 증거/코드의 사실관계는 보존하며 역사적 영수증을 사후 수정하지 않는다.

변경은 `degong2-code/simc-secondary-optimizer-runner` **격리 브랜치**의 문서/설계 기록만 대상으로 한다. `main`, v003 immutable, 원본 v016, Project Sources/Instructions UI, Work OS 공식 승격·MAIN/WORK 권한은 별도 승인 없이 변경하지 않는다.
