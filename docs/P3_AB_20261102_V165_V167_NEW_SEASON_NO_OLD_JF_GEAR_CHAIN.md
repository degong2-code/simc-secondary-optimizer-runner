## Objective and actual defect removed

An already implemented regular-product source path exists: v161/v163/v162→v165→v166→v167→v168/v169→v191/v211/v213→v216/v098. But v165 eagerly loaded `data/current_season_chmv_consumables.json` at Python module import. This creates an unjustified **dependency on previously installed J/F numeric source** even for a newly installed build whose Wago/Blizzard/WCL data was independently acquired. Before the fix, the same code could not truly process a fresh source with historic references inaccessible.

**Changed the original modules, not a new engine:**
- `runner/v165_current_season_gear_pool.py` has *no import-time installed-budget read*. `compile_pool(..., budget_source=None)` permits real source-derived gear classification while explicitly keeping J/F unknown (`NEW_SEASON_J_F_BUDGET_EVIDENCE_PENDING`, `consumable_budget_reference=null`). CLI `--fresh-source-only` does the same. `--budget-source <path>` accepts an explicit source-provided same-build budget candidate after internal shape/J/F arithmetic checks, without declaring source identity, top quality or true Native effect/authentication. The existing compatibility default reads the old installed same-season file **only when no new source mode was requested** to avoid breaking already installed product flows.
- `runner/v166_compact_product_gear_db.py` and `runner/v167_product_season_gear_adapter.py` propagate the J/F source-state through the original compact and user candidate paths. **Neither** promotes the numeric J/F candidate nor claims G/B/T. Distinct original gear source IDs, physical slot/role and unresolved WorldState/crafted-effect conditions remain unchanged.
- `tests/test_v165_current_season_gear_pool.py` checks a different build with missing prior season JSON; J/F explicitly pending and accepted new-build source candidate (different numerical value) with mismatched build/incomplete candidate rejected. `tests/test_v166_compact_product_gear_db.py` and `tests/test_v167_product_season_gear_adapter.py` check that pending source mode is preserved.
- `tests/test_v238_fresh_product_gear_chain.py` exercises **actual existing** v165→v166→v167 functions in one offline synthetic new-build Wago+Delve Item/ItemSparse/ItemXItemEffect source chain, while the previously installed budget path is deliberately nonexistent. Four current candidate IDs are carried, one WorldState-unresolved older item excluded, no previous J/F value inserted and no Native/API activity. Another test tries a stale same-build J/F budget and ensures rejection without changing any source file.
