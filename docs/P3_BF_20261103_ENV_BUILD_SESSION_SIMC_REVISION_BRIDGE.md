# P3-BF — Environment Build engine: reuse static season source after SimC runtime update

**Date:** 2026-11-03 KST. **Ownership:** existing primary product chat; isolated branch `probe/chat-cache-v035-20261024` only. No changes to main, v003 immutable, v016 original, Project UI, official Work OS or WEQUIP authority.

## Scope and priority

The project remains the **Environment Build Engine**, not a new optimization algorithm. User goal is 26 DPS specs, target ilvl (default 334) or manual final T, future optimal absolute CHMV ratings using the already existing adaptive SimC DPS engine. Mandatory season G/J/F/O automatic discovery, B/T reconciliation, quality-aware options and actual user profile integration remain core unfinished milestones. Manual T always takes precedence and oil O is non-distributable; no previous season's fixed J/F/O/79x2 may be automatically promoted to a new season.

Same-season frequent SimC balance/APL updates must **not** force another full season gear/consumable data collection. Source catalogue version (source-pinned SimC revision) and actual executing SimC binary SHA/revision are separate identities.

## Actual newly discovered blocker and corrected implementation

P3-BE revised the `v212` environment manifest source vs runtime revisions. However **the normal user entry point still failed before v212**: `runner/v106_user_session_controller.py::source_catalog_identity` rejected a valid v213 immutable source merely because its `simc_revision` differed from the current user-requested executable revision (`V106_V213_SOURCE_CATALOG_SESSION_IDENTITY_MISMATCH`). This was demonstrated by an **actual integration regression** `tests/test_v212_environment_manifest.py::test_v216_normal_build_reuses_static_source_with_new_simc_runtime`; initial Actions [#41538243862](https://github.com/degong2-code/simc-secondary-optimizer-runner/actions/runs/41538243862) FAILED with precisely this blocker. The subsequent fix is not an assumption.

Changed the v106 source identity validator to require original `v213` source schema and verified immutable source digest/metadata, `native_calls==0`, `network_calls==0` and `automatic_ui_promotion is false` **without comparing the source commit against the runtime commit**. The exact static source revision/build/SHA remain in `identity.current_season_source_catalog`. The original `session_key` separately binds `identity.simc_revision`, **actual executable bytes SHA**, profile policy, static-cache bytes, source catalog hashes, selected equipment and user controls. Existing same-version session identities are unchanged; new SimC versions necessarily get a different session key and distinct DPS cache.

Did not loosen actual SimC generated-source internal build/blob checks, previous source provenance, session SHA check, the v212 source/UI contract, or the adaptive DPS 95%-only semantics. A different client-build number alone is not new-season evidence. No source data is re-labelled or repackaged to claim compatibility.
