# P3-BJ — Preserve same-display-season M+ world-state expressions as INTERNAL gear candidates
2026-11-03 · isolated `probe/chat-cache-v035-20261024` branch

## Scope and rationale
This is one continuation of the approved v1.4.3 environment-data build engine for 26 DPS specs, NOT a new optimization subsystem or full-season item database. Original `v163` classifies JournalEncounterItem with a nonzero `WorldStateExpressionID` as `UNKNOWN_WORLD_STATE_EXPRESSION` regardless of `DisplaySeasonID`. `v165` accordingly keeps unknown-world-state M+ equipment out of user-selectable `CURRENT_CANDIDATE` data. Previously `v166` reduced every conditional item to ID/slot without SimC source-facing metadata; `v167` and `v232` could not even consider a physically valid M+ ordinary item as an internal representative candidate.

A world-state expression ID is a conditional expression reference, **not the Boolean value** true or false. A nonzero ID cannot independently establish either that gear is ineligible or that it is active. No decoding or simulation of WoW server world-state/loot logic is added.

## Code delivered
- `runner/v166_compact_product_gear_db.py`: keeps an **internal-only** source record for an exact same-display-season `mplus_journal` row with WSE>0 and positive journal IDs, matching expansion, a physically plain non-set gear role and no direct item effect record. It remains in original `conditional_unverified` (never the current public candidates) and carries exact Item/ItemSparse class/subclass/slot/stat codes and the original WSE identity without copying full gear DB.
- `runner/v167_product_season_gear_adapter.py`: validates/forwards those rows as `internal_conditional_mplus_plain_candidates` with `ui_selectable:false`, `season_membership_verified:false`. Does **not** add them to `items` or `public_options`. A fresh season with zero public current candidates and one or more internal WSE candidates is allowed to advance source-only collection without claiming Environment READY. Existing legacy v166 catalogs with absent optional fields remain usable; prior package/source/old session values not rewritten.
- `runner/v232_simc_only_ordinary_representative.py`: reuses existing one-pass pinned SimC item metadata and `v169` class/family/weapon-form selectors. Preference is explicit display-season WSE0 source, then same-display-season WSE pending, then other uncertain source; records exact selected WSE IDs and per-slot blocker. These are G-work candidate IDs only.
- `runner/v216_environment_build_coordinator.py`: same normal fresh source-stage counts conditional physical ordinary/weapon candidates as possible **source-only** candidates, without promoting their status; the existing v217 stage SHA, caching, reuse and no-extra-download behavior remain.
- `tests/test_v166_compact_product_gear_db.py`, `tests/test_v167_product_season_gear_adapter.py`, `tests/test_v232_simc_only_ordinary_representative.py`: focused same-display-season WSE handling, physical one-spec fallback, no G approval, no user publication, and **zero public catalog** case.
