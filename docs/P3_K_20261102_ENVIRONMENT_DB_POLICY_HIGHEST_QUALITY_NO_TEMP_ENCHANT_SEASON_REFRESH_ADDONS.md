# P3-K — 환경 DB 제품 범위 최신 사용자 결정 (2026-11-02)

> **2026-11-02 최종 정책 정정(P3-L):** 이 파일의 “J/F/O 자동 갱신” 제목·우선순위는 **이전 불완전한 표현**이다. 최신 사용자 승인 범위는 **G를 포함한 시즌별 G/J/F/O 전체 자동 구축 → B/T 재계산**이며 [v1.4.3 최신 보충 기준](./SIMC_SECONDARY_OPTIMIZER_Developer_Notes_v1.4.3_SEASON_GJFO_AUTO_BUILD_APPROVED_20261102.md)을 우선 적용한다. 이력에 남은 이전 단계 서술은 당시 개발 상태 증거일 뿐 새 시즌 G가 불필요하다는 뜻이 아니다. 사용자 제공 프로젝트 지침은 등록됐다고 보고됐으나 GitHub 문서만으로 Project Sources 원본 등록을 확증하지 않는다.


**지위:** 사용자의 이번 대화 직접 결정. 기존 v1.4.2 이하 비충돌 정책과 26 DPS, 목표 절대 CHMV, SimC 책임, 정책 A(검증된 신규 선택지 자동 등록) 유지. 이 문서는 GitHub 격리 브랜치의 기록이며 Project Sources/Instructions UI가 바뀌었다는 뜻은 아니다.

## 1. 최고 품질만 사용자 선택지로 표시

- 보석·영약·음식 등 **품질/등급이 나뉜 아이템**은 **정확히 동일한 효과·사용 조건·적용 범위**를 갖고, 특정 고품질 버전이 관련 모든 효과·정적 수치에서 열등하지 않고 하나 이상에서 우월하다는 근거가 확인될 때만 낮은 품질을 사용자 카탈로그에서 제외한다.
- 사용자 화면에는 그러한 동치 집합당 **가장 높은 검증 품질만** 제시한다. 같은 최대 품질 안의 완전히 동일한 대안은 안정적 ID 기준으로 대표 하나만 표시할 수 있으나, 다른 효과/스탯 조합/적용 부위는 동일하지 않다. 비슷한 이름, 높은 ilvl, 등급 명칭만으로 우월성을 추정하지 않는다.
- **원본 소스 행/ID/검증 영수증은 출처 재현·관계 확인에 필요한 범위에서 보존**하되 일반 사용자가 보게 할 필요는 없다. 미비한 비교는 보류/비교 미확정으로 기록하고 그 상태의 하위 버전도 무조건 '승인된 옵션'으로 올리지 않는다.
- 기존 v191 `highest_known_quality`(SimC token/마부 부위별 최고 source rank), `highest_effect_variants`(수치 비교 가능 시) 사용은 **부분 구현**. 실제 음식/영약/보석의 아이템↔효과↔최고 품질 선택 연결은 **미구현**.

## 2. 일반 임시 마부 제외, 무기 기름 유지

- 임시 마부 일반 카탈로그, 무기 강화 아이템의 광범위한 선택지/자동 등록은 **이번 제품 범위에서 제외**한다. 117개의 v191 원본 행 수집은 과거 소스 감사 증거이지 제품의 필수 선택 범위가 아니다. 새 범위에서 v220 `temporary_enchant` 자동 등록 후보를 거부한다. 후속 효율 개선 시 불필요한 fetch/audit/UI 경로를 중지하되 역사 증거·검증기 재사용을 깨지 않는다.
- **무기 기름(O)은 제외하지 않는다.** 사용자 명시 선택/미선택 대상이며, SimC `temporary_enchant=` 문법을 사용하더라도 내부적으로 **별도 `weapon_oil`/고정 O 영역**이다. 실제 무기 손 적용 제한·SimC token과 정적 O 정합·이중 계상 방지 유지. 현재 v091 기본 기름 하드코딩 16치명+16가속/무기는 새 시즌 자동 갱신 기능이 아니다.

## 3. 음식·영약·기름의 시즌별 수치 갱신 — 당시 범위(최신 G/J/F/O 정책은 v1.4.3 참조)

- 목표: 새 시즌의 Environment Build 1회 요청 과정에서 기존 시즌/빌드 비교, 해당 시즌의 **유효한 최고 품질 아이템** 및 효과·정적 rating을 원본에서 추출→정규화→SimC 입력 수용/CHMV 소유권 확인→시즌별 버전화된 계약으로 생성·설치한다. 예: 영약 F=165 → 신규 시즌 F=250이면 **검증한 250**을 새로운 시즌 계약에 적용하고 고정 165 가정은 새 세션에서 거부한다. 변한 영약 아이템 ID·SimC token·스탯 방향을 함께 업데이트한다. 과거 시즌 캐시/세션은 변경하지 않는다.
- **현재 구현 상태:** v190은 음식/물약의 DB2 아이템 후보를 찾아낼 뿐 소비효과 수치·품질·SimC token과 1:1 매칭하지 않는다. v191은 v165에 등록된 시즌별 F/J 참조 데이터를 읽는다. `data/current_season_chmv_consumables.json`에 현재 F=165,J=138이 기록되어 있고 `v108`은 이를 **고정 값으로 검사하며, 검증되지 않은 대체 영약을 거부한다**. v091은 기름 1무기당 crit16+haste16 및 `thalassian_phoenix_oil_2`로 고정된다. v216 로컬 Environment Build는 **이미 설치된** v213 source artifact를 읽을 뿐 새 시즌 원본 fetch를 실행하지 않는다. **F=250 자동 수집→검증→업데이트는 미구현**; 현재 165가 새 시즌에 계속 적용되는 것은 금지하고 빌드 불일치 시 차단한다.
- 구현 방향: 기존 v161/189/190/191/211/213/216에 증분 갱신/정량 ID join과 버전화된 consumables J/F/O 계약 생성·적용을 통합한다. 최종 사용자에 새 수치 입력/수동 보정 강요하지 않는다. 모든 아이템을 Native 전수 검사하거나 SimC effect/proc를 우리 쪽에서 재구현하지 않는다. 필요한 선택 범위의 SimC/JSON2 확인만 수행한다.

## 4. 옴니움 장서 같은 시즌·확장팩 전용 콘텐츠는 선택형 모듈

- 시즌별로 생기고 사라지는 고유 시스템(예: Omnium Folio)을 **핵심 환경 DB와 분리한 독립 선택형 add-on**으로 다룬다. 사용자는 간단한 적용/미적용 토글을 제어한다. 적용 시 모듈의 버전/옵션/SimC 입력·고정 CHMV 영향이 세션·캐시 identity에 포함되며, 미적용 시 원본 대표 프로필·예산에 모듈 효과가 남지 않아야 한다. SimC가 실제 효과를 계산한다.
- 환경 DB 구축 완료 화면에서는 **'이번 확장팩/시즌의 별도 특수 콘텐츠는 별도 갱신이 필요할 수 있으므로 GPT를 통해 모듈 업데이트를 요청해 주세요'** 정도의 안내를 띄우는 것으로 충분하다. 별도 GPT 자동 호출·모델 의존·비밀/프로필 전송·항상 켜지는 업데이트 감시는 만들지 않는다.
- **현재 구현 상태:** `v108`의 `omnium_talents`는 기본 대표 프로필 및 source-pinned preset에 **직접 결합**돼 있다. 별도 add-on 설치/켜기/끄기/자동 메시지는 **아직 미구현**이다. 새 모듈로 분리할 때 기존 사용 프로필 및 Native 수용/캐시와 구별해 검증하되 이전 세션의 sealed profile을 변경하지 않는다.

## 우선순위 / 검증

1. **최신 정책은 G/J/F/O 전체**: 장비 G 계산/시즌 참조 + 최고품질 J/F + 기름 O 자동 생성, B/T 통합 재계산(당시 작성 문구를 교정; 상세 v1.4.3 참조)
2. 검증된 최고 품질만 UI 발행하며 정책 A 수직 연결
3. 불필요한 일반 임시 마부 경로 축소(기름 O 유지)
4. Omnium 등 전용 옵션의 독립 토글/적용 뒤 사용자가 선택할 수 있는 GPT 업데이트 안내
5. 소스 통합 및 사용자 Windows Build→Start→결과 최소 수용검증; 기존 DPS 엔진, 95% 통계, 최소 Native, 캐시·취소·재개 보존

정책 문서 저장은 기능 완성·실제 새 시즌 검증 성공·Project UI 승격이 아니다. `main`, v003 immutable, v016 원본, 다른 채팅 소유권은 별도 승인 없이는 변경하지 않는다.
