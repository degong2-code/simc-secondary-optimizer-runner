# P3-Q — v224 G/J/F/O cross-season evidence inventory and core-source preflight
**Date:** 2026-11-02 (KST)  
**Authority:** isolated development branch only; approved v1.4.3 + newest G/J/F/O season policy. Not a Project Sources/Instructions UI change or main promotion.

## Purpose and exact scope
Continue implementing the **reusable Environment DB engine**, not an item-by-item recommendation DB or a replacement optimizer. Existing flow is v191 (source candidates) → v211 (source classification) → v213 (catalog handoff) → v196 (eligible choices) → v098/v216 → adaptive SimC. This change adds a shared **v224 mandatory G/J/F/O source inventory** and a source-only preflight that does *not* require all season-specific v211/v213 enchant classification to be finished.

`runner/v224_season_gjfo_evidence_inventory.py` now supports two read-only, versioned modes:

1. `--core-only` — consumes **new season-supplied gear/tier/budget JSON files**, validates their common build, schemas, equipment/tier structural counts and prior-build drift, pins exact file SHA256, and lists separately missing proofs for **G, J, F and O**. This can operate before the current-season fixed-38-enchant v211/v213 catalog is rewritten. No source discovery/downloading itself is implemented in this mode; it cannot certify that a supplied file is authoritative. Its output retains `requires_v191_source_pinning=true`.
2. Without `--core-only` — additionally verifies exact v191/v213 artifact identity, v191 event, source input hashes, source build and SimC generated-table build metadata; produces a small sealed G/J/F/O evidence-inventory receipt in the existing v191→v213 request-scoped workflow output directory. v191/v213's current item counts and seasonal classification still constrain when this full path can execute.

Both modes are **fail-closed**: every component has explicit pending validation requirements, `G/J/F/O/B/T=null`, new user option admission false, environment budget publishing false, Native/network/cache mutations zero. In particular G representative gear IDs are not a measured G rating; gems' DB2 IDs do not prove top-quality/effect equivalence or J, flasks' item names do not prove F, and temporary enchant source rows do not prove hand applicability or O. The existing 79×2 reference and J=138/F=165/O16+16 from Midnight S2 are **not copied into future season budgets**. Manual T continues to override an eventual completed automatic budget, via the existing v222/v098 accounting path. No generic temporary enchants are added; weapon oils stay separate. Optional Omnium module remains a distinct unfinished feature.

## Efficiency
Pure read-only input inspection, bounded file reads and constant-size summary receipts; no new retrieval provider, Native calls, repeated 26-spec sweeps, new caches or revisions of static item cache. The new preflight runs even before expensive source classification, so a bad build/unchanged old season can be rejected early. CI checks only the touched contracts; an expensive complete source refresh was intentionally not repeated solely to test this receipt.
