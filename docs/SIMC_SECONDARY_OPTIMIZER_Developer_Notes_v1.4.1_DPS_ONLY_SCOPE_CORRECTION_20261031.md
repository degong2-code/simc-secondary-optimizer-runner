# 1. 프로젝트의 최종 목적

## 1.1 핵심 목표

SIMC SECONDARY OPTIMIZER는 World of Warcraft의 캐릭터에 대해 **목표 장비 수준과 전투 조건에서 DPS를 최대화하는 2차 스탯 절댓값을 찾는 프로그램**이다.

최적화 대상은 다음 네 가지다.

- CH = Critical Strike, 치명타
- H = Haste, 가속
- M = Mastery, 특화
- V = Versatility, 유연성

프로그램은 사용자가 설정한 CHMV 총량을 네 스탯에 분배하면서 SimulationCraft를 실행하고, DPS가 높은 조합을 찾아낸다.

핵심 결과는 비율 자체가 아니라 **목표 CHMV rating 절댓값**이다.

비율은 사용자가 실제 장비를 파밍하거나 스탯 총량이 목표와 다를 때 참고하도록 함께 제공한다.

## 1.2 실제 사용 목적

사용자는 최종 파밍 목표가 되는 장비 수준을 정한다.

예를 들어 아이템 레벨 334에 해당하는 CHMV 총량에서 DPS가 가장 높은 스탯 분배를 찾는다.

이후 사용자가 직접 장비·보석·영약 등을 조정하여 추천 스탯에 접근한다.

프로그램은 그 장비를 어떻게 구할 것인지까지 계산하지 않는다.

**일반 사용자의 기본 목표는 향후 파밍 목표 rating을 정하는 것이다.** 현재 착용한 모든 장비의 스탯을 읽어 합산한 뒤 재분배하는 기능이 기본 제품 사용 방식이 아니다. 사용자는 **전체 장비 목록을 입력하지 않는다**. 직업·전문화·종족·특성, 목표 아이템레벨(기본 334) 또는 수동 최종 T, 장신구 2개, 선택 특수효과 장비, 장식 최대 2개, 보석·소모품·전투조건 등을 선택한다. 일반 장비·티어·무기 등 나머지 대표 입력은 프로그램이 내부적으로 구성한다.

이는 장비 파밍 **경로 추천**을 뜻하지 않는다. 최종 CHMV 절대 rating 및 통계적으로 성립하는 가까운 분배 대안을 사용자가 장비 파밍의 **목표**로 활용하는 것이 핵심이다.

## 1.3 프로그램의 범위

**포함**

- 목표 장비 수준에서 CHMV 예산 산출
- CHMV 절댓값 최적화
- SimC 자동 실행과 JSON2 결과 분석
- 통계 오차를 고려한 후보 평가
- 최상위 CHMV 및 근접 성능 대안 탐색
- 대체 후보별 예상 DPS와 성능 차이 표시
- 특성·종족·특수 장비·장신구·소모품·전투 조건 반영
- 효율적인 SimC 실행, 캐시, 중단 및 재개

**제외**

- 시즌의 모든 일반 장비를 수집하는 대규모 DB
- 장비 조합 자동 탐색
- 장비 추천 및 파밍 경로 생성
- 보석·영약의 실제 조합 자동 추천
- 전문화별 새로운 딜사이클/APL 개발
- 사용자가 지정하지 않은 복잡한 전투 전략 최적화

이 프로젝트는 장비 최적화 프로그램이 아니라 **목표 2차 스탯 최적화 프로그램**이다.

# 2. 기본 설계 원칙

## 2.1 목표 총량 고정

한 번의 최적화 작업에서는 하나의 CHMV 총량을 기준으로 탐색한다.

총량이 달라지면 최적 분배가 달라질 수 있지만, 이를 보정하기 위한 총량 민감도 검사는 기본 기능으로 요구하지 않는다.

사용자는 최종 파밍 목표 총량에서 나온 결과를 활용한다.

총량이 다른 경우 새로운 최적화를 수행할 수 있다.

## 2.2 절댓값 우선, 비율 보조

최종 결과에는 다음을 모두 표시한다.

1. 권장 CHMV 절댓값
2. CHMV 비율
3. 예상 DPS
4. SimC 계산 오차
5. 최고 후보 대비 DPS 차이
6. 성능이 비슷하면서 스탯 분배가 충분히 다른 대체 목표

## 2.3 설정 변경 가능성

현재 정한 설정은 프로그램의 기본 계약이지 영구적으로 수정할 수 없는 제한이 아니다.

장비 레벨, CHMV 총량, 스탯 상한, DPS 허용 오차, 반복 횟수, 전투시간 등은 개발 및 검증 과정에서 조정할 수 있다.

설정 변경 때문에 핵심 탐색 알고리즘을 재작성하지 않도록 구성한다.

## 2.4 경량성과 실행 효율

불필요하게 크고 복잡한 프로그램을 목표로 하지 않는다.

가능한 한 적은 SimC 실행으로 유용하고 신뢰할 수 있는 최적화 결과를 얻는 것이 중요하다.

완전히 동일한 결과를 반복 계산하지 않으며, 통계적으로 충분하지 않은 경우에만 추가 계산을 수행한다.

# 3. 캐릭터 입력 방식

## 3.1 사용자 기본 입력

프로그램은 다음 항목을 지원한다.

- 직업: 드롭다운
- 전문화: 드롭다운
- 종족: 드롭다운
- 특성 코드: 문자열 입력
- 목표 아이템 레벨: 선택
- 목표 CHMV 총량: 직접 입력 가능

기본값은 빈 선택 또는 명시적인 초기값으로 제공할 수 있다.

사용자 SimC 프로필 업로드는 필수가 아니다.

## 3.2 SimC 프로필

SimC 프로필 업로드는 선택 기능이다.

업로드한 경우 직업·전문화·종족·특성 등을 추출하는 데 활용할 수 있다.

기본 실행은 프로그램 내부에서 생성하는 표준화 프로필을 사용한다.

**선택 업로드한 프로필에서 직업·전문화·종족·특성 등의 캐릭터 정보는 가져올 수 있으나, 현재 착용 장비 전체나 현재 CHMV 총량을 기본 파밍 목표로 채택하지 않는다.** SimC 원본 프로필 내 장비/소모품이 사용자 목표 대표 장비와 충돌하면 목표 선택이 우선하고 내부 대표 장비로 대체하며, 사용자가 명시적으로 선택한 특수장비·장신구·장식·전투 조건만 고정 반영한다. 완전한 프로필 텍스트와 전체 filler 목록을 요구하는 v096~v097 manifest는 **내부 실행용 준비 자료이며 최종 사용자 UI의 필수 입력 요구가 아니다.**

**현재 사용자가 착용한 장비의 CHMV 총량을 최적화 기준값으로 삼지 않는다.**

## 3.3 APL

사용자가 별도로 지정하지 않으면 해당 SimC 버전의 기본 APL을 사용한다.

사용자 지정 APL은 향후 고급 설정으로 지원할 수 있다.

프로그램이 자체적으로 새로운 전문화별 딜사이클을 개발하거나 최적화하는 기능은 범위에서 제외한다.

# 4. 목표 장비 및 대표 프로필

## 4.1 목표 아이템 레벨

기본 선택값은 아이템 레벨 334이다.

다른 장비 레벨(예: 331, 321 등)과 CHMV 총량 직접 입력을 지원한다.

아이템 레벨 334는 현재 목표 시즌에 대한 기본 제안값이며, 시즌이 바뀌면 변경할 수 있다.

## 4.2 표준화 대표 장비

프로그램은 목표 아이템 레벨에 해당하는 **대표 장비 프로필**을 생성한다. 이 장비는 실사용 시 사용자가 부위별로 전수 선택하는 것이 아니라, 목표 레벨의 표준화된 장비·무기·티어 구성으로 프로그램이 자동 준비한다. 사용자의 선택은 고정해야 하는 **특수효과 장비, 장신구 2개, 장식 최대 2개** 및 캐릭터·전투 조건 중심이다. 대표 장비의 개별 일반 2차 스탯 분배를 최종 목표로 잠그지 않는다.

대표 프로필에는 다음을 반영한다.

- 목표 레벨에 해당하는 주 능력치
- 표준화된 무기 성능
- 장비 부위별 기준 스탯 예산
- 해당 시즌 티어 세트
- 사용자가 선택한 특수효과 장비
- 장신구 두 개
- 장식 두 개
- 기타 고정 설정

일반 장비는 가능한 한 고유 특수효과가 없는 표준 장비로 구성한다.

대표 장비의 개별 CHMV 분배는 **DPS 계산에 필요한 효과를 갖춘 프로필의 초기 상태**일 뿐 최적화 후보의 분배 제약이 아니다. 보석의 실제 +16/+7 배분과 영약의 최초 스탯 종류도 자유 CHMV 목표로 덮어쓸 수 있으며, 장비·세트·무기·장신구·특수효과·장식·보석 색상 등 **비스탯 효과와 특수 장비 고정 스탯 하한**은 유지한다. 실제 SimC 주입에서 정적 스탯을 중복 가산하지 않도록 최종 출력으로 대조한다.

## 4.3 티어 세트

해당 시즌의 **티어 4세트 착용이 기본**이다. 실제 티어 아이템 ID·부위·아이템레벨을 대표 프로필에 전달하고, 장식·선택 특수장비가 티어 부위를 무단으로 덮어쓰지 않도록 슬롯 충돌을 검사한다. **티어 효과 자체는 SimC가 계산**하며 자체 4세트 효과 엔진 또는 별도 효력 인증 Gate를 만들지 않는다. 입력 누락·슬롯 교체·SimC 실행 실패는 우리 쪽의 입력 오류로 구분한다.

## 4.4 특수효과 장비

장신구 외에도 시즌별 제한된 특수효과 방어구·무기가 존재한다. 사용자가 선택한 아이템 ID·옵션·레벨을 고정하고 해당 부위의 표준 장비와 교체한다. **장비 조합 추천 기능으로 확장하지 않는다.**

선택한 특수장비의 **Native SimC 기준 고정 2차 스탯**은 일반 장비를 대체한 해당 부위의 실제 스탯으로 `G`에 **한 번만 포함**하고, 최적화 후보의 **스탯별 최소 하한 `L`**으로 잠근다. 정적 스탯 정보가 없는 경우 숫자를 임의 생성하지 않는다. 효과 구현·발동 및 DPS는 **그대로 SimC에 위임**한다. 특수효과 검증 실패를 이유로 정상 입력 선택을 금지하지 않는다.

## 4.5 장신구

사용자는 장신구 **2개**를 직접 선택한다. 장신구 ID·레벨·옵션은 SimC에 전달하고 최적화 작업 동안 고정한다.

장신구의 고정 2차 스탯은 **자유 CHMV 예산 `G`의 바깥**에 있으며, 실제 SimC 실행에는 적용한다. 따라서 장신구의 정적 스탯을 나타내는 JSON2 `gear` 레코드가 **미출력**되어도 선택 및 SimC 실행을 막지 않는다. 미출력 상태는 `미관측/알 수 없음`이지 **스탯 0으로 실측 완료**가 아니다. 이 경우에도 장신구는 그대로 SimC에 장착시킨다.

실례: `Mindpiercer's Sigil` (`item_id=250224`)은 정적 gear 레코드 없이도 선택·Native SimC 실행 성공(v056). `Permafrost Essence` (`250244`)는 기본 후보에서 제외해도 무방하나 사용자 명시 선택은 차단하지 않는다. **개별 발동 효과의 구현 상태를 판정하려고 새 연구 작업을 시작하지 않는다.**

## 4.6 장식 및 제작장비

사용자는 **장식을 최대 2개까지 선택**할 수 있으며, 선택한 장식은 CHMV 탐색 동안 고정한다. 이를 SimC 프로필에 구현할 장비가 필요할 경우 **천·가죽·사슬·판금 제작 방어구 및 제작 무기, 망토·방패·장신구 외 공용 부위**를 대표 장비에 사용할 수 있다. 제작장비는 장식 선택 구현을 위한 기반이며 **장비 조합·레시피 최적화 대상이 아니다**.

제작 시 선택하는 두 2차 스탯의 초기 비율(일반적으로 50:50)은 **CHMV 최적화의 고정 하한이 아니다**. Native SimC가 반환한 해당 아이템/레벨/옵션의 **정적 2차 스탯 총량**을 `G` 예산에 포함하고 그 배분은 최적화할 수 있다. 스탯의 정수 반올림·총량 동등성은 해당 Native 변형에서 확인한다. 장식 효과 자체는 SimC에 위임한다. 제작 스탯 토큰 `crafted_stats=49/36` 등의 숫자는 **rating 값이 아닌 선택 스탯 식별 코드**다.

시즌 2 메타데이터로 **제작 레시피 ID 51종**을 확보했으나 시즌 전체 제작 레시피 완전 DB임을 증명하지 않았다. 카탈로그에 없는 장비도 사용자가 정확한 ID/슬롯/레벨/옵션을 제공하면 **SimC에 전달하는 입력은 허용**한다. 해당 비장신구의 `G` 산출에 필요한 정적 수치가 없다면 선택 아이템의 exact 변형만 Native로 지연 조회하고, 조회 실패 시 *예산 산출 미완료*로 표시한다. 이를 *효과 미지원*으로 오판하지 않는다.

## 4.7 무기

기본적으로 목표 레벨의 표준화 무기를 사용한다.

고유 특수효과가 있는 무기는 사용자가 별도로 선택할 수 있다.

무기 공격력 등 DPS에 중요한 비스탯 수치는 목표 레벨에 맞춰 반영한다.

# 5. CHMV 총량 계산 규칙 — v1.3 공식 승인 (2026-10-26)

## 5.1 공식 총량과 기준표

**공식 승인 산식: `T = G + J + F + O`**. 하위 호환을 위해 **기본 예산**을 `B=G+J+F`로 따로 정의하며, 따라서 `T=B+O`이다.

- `G`: 목표 ilvl의 **표준 대표 비장신구** 정적 CHMV 총량을 정의하는 회계 항목이다. 정확한 Native G 경로도 보존하지만, **일반 제품 흐름은 기존 79×2 Native 유래 아이템레벨별 반올림 참조표 B를 사용하여 총량을 자동 결정**할 수 있다. 사용자가 실제 착용한 전체 장비를 고르고 개별 스탯을 수집할 필요는 없다. 사용자 수동 최종 T가 지정되면 그 값이 우선한다. 참조 B는 실제 Native 산출값 대비 10 rating 단위 근사(해당 기준표의 원 측정값 기준 최대 ±5)임을 표시하며, 모든 전문화·사용자 선택 장비에서 일치하는 정밀 G라고 주장하지 않는다. 정확히 선택된 특수장비 고정 CHMV `L`은 G/B 내 포함되어 있으므로 중복 추가하지 않는다.
- `J`: 현 S2 대표 시나리오의 일반 보석 6개×23 = **138**.
- `F`: 현 S2의 명시된 대표 영약 정적 기여 **165**; 조건이 바뀌면 재확인한다.
- `O`: **선택하여 실제 적용하는 기름의 정적 고정 2차스탯 총합**. 현 Thalassian Phoenix Oil 최고 품질 기준, 무기당 `o=(치명16, 가속16, 특화0, 유연0)`. 기름 없음 `O=0`, 하나 `O=32`, 무기 2개에 각각 적용 `O=64`.

**334 공통 참조 `B=3150`**, 분노 전사 양손무기 쌍수 참조 `B=3350`(실제 ilvl별 두 트랙 조회값이며 모든 레벨에 일괄 +200하지 않는다). **최종 총량**은 기름 없음/1개/2개: 공통 3150/3182/3214, 분노 전사 양손쌍수 3350/3382/3414. 기존 79×2 기준표의 수치는 **기름 적용 전 B**로 보존하며, O를 영구 가산해 덮어쓰지 않는다. 특화/유연에는 기름 추가 고정치가 없다.

## 5.2 자유 최적화의 경계

**최종 T가 늘어도 O는 자유 분배할 수 없다.**

- 특수장비 고정 하한 `L`은 **B에 이미 포함**되어 있으므로 이중 추가 금지.
- 기본 분배 `c_base=L+x`, `sum(c_base)=B`, `x_i>=0`, `sum(x)=B-sum(L)`.
- 기름별 고정 벡터 `o`; 최종 rating 후보 **`c_final=c_base+o`**, `sum(c_final)=T`.
- 최종 후보 하한은 최소 **`L+o`**, 사용자 상한/하한은 최종 기준 적용인지 기본 B 기준인지 타입을 명시해 충돌 없이 일관되게 해석한다.
- 장신구 미관측 정적 gear 레코드는 장비 선택 차단 요건이 아니며, 모른다고 0으로 추론하지 않는다. 음식·마법부여 등 기타 외부 고정치/전투 버프를 무단으로 O에 포함하지 않는다.

## 5.3 수동 목표·하위 호환

신규 **사용자 수동 총량**의 기본 명세는 **기름 포함 최종 `T`**이며 scope는 `INCLUDES_G_J_F_O`이다. 이미 존재하는 `v061` 스키마의 `manual_total_scope=INCLUDES_G_J_F_EXCLUDES_EXTERNAL` 및 `budget.T`, `v062.budget.T_official`, v089~v090 `resolved_T`는 역사적으로 **B를 뜻하는 내부 레거시 호환 필드**다. 절대로 사용자에게 최종 공식 T라고 표시하지 않는다. v092 정책 어댑터는 사용자 입력 최종 `T`에서 고정 O를 **한 번만 차감하여 레거시 B**로 넘기고, 최종 SimC 후보에는 다시 O를 포함한다. 구형 입력을 조용히 새 의미로 재해석하지 않는다.

## 5.4 SimC 정적 주입, 실제 Native 검증과 중복 방지

SimC의 `gear_crit_rating`, `gear_haste_rating`, `gear_mastery_rating`, `gear_versatility_rating`은 적용된 장비·보석·무기 기름 등 정적 장비 기여를 **덮어쓰는 동작**을 한다. 기존 v091에서는 `temporary_enchant` 문자열을 정확히 전송했지만 주입된 `gear_*`가 기름 O의 수치 기여를 대체해 JSON2 rating이 0/1/2기름에서 동일했다.

**2026-10-26 실제 Native 확인:** 동일한 334 분노 전사 입력, SimC rev `7bc10711b5` 바이너리 SHA `64089f2f917d552ab392ba311d128aa1b7ec559ead52b3546e2cc328ab479b8e`에서 `gear_*`를 쓰지 않았을 때 기름 개수당 치명+16/가속+16이 실측됐다. 기존 베이스 정적 주입에서 `gear_*`를 고정 O만큼 가산한 결과, 최종 2차 rating이 0개 3350, 1개 3382, 2개 3414로 일치했다(각 정적 rating 전용 1 iteration; **DPS 우열 입증 아님**).

구현 원칙: 기존 v090의 분배 `c_base`와 영약 귀속 F 벡터로 산출한 `gear_*` 기본 주입에 **정확히 1회** `o`를 반영한 값을 SimC에 전달한다. 그 결과 `raw_gear+F=c_final`이다. 이미 보정한 O를 이후 JSON2 또는 결과 표시에서 또 가산하지 않는다. 실측 `buffed_stats`와 정적 목표는 전문화별 특성/버프 차이로 달라질 수 있으므로 구분해 기록한다. SimC 자체 효과/APl/proc 엔진을 재구현하지 않는다.

## 5.5 기름 및 캐시 identity

- 실제 무기 없음/1개/쌍수 2개의 사용자 적용 선택을 엄밀하게 기록하고, 비무기 보조장비(방패·보조장신 등)에 오일을 억지로 추가하지 않는다.
- 미사용 시 **`temporary_enchant=disabled` 명시**: 줄을 생략하면 SimC 기본 기름을 상속할 수 있다(v090 기록의 기존 ‘기름 없음’ 표기는 정정).
- SimC 입력의 `temporary_enchant` 문자열과 JSON2 파싱 결과를 일치시킨다.
- DPS 캐시는 프로필 전체 SHA, 장비 ID/레벨/옵션, 캐릭터·전투조건, 기본 B, 고정 벡터 O, 최종 T/c, SimC revision/바이너리 SHA, 반복횟수별로 구분한다. 기름 0/1/2는 서로 다른 캐시 케이스다.
- 정적 아이템 캐시의 기존 시즌/교정 정책은 바꾸지 않는다.

**실증과 미완료의 구분:** 격리 v092 경로는 Fury334 정적 JSON2/소모품 입력 검증; 원본 v015/v016 제품 완전 통합, DPS 26개 전문화의 전체 적응형 최적화, 근접 대안 및 사용 UI는 별도 후속 작업이다. 사용자가 이 변경을 공식 승인했다고 해서 미완료 시험을 PASS로 승격하지 않는다.

# 6. 보석 규칙

## 6.1 소켓 수

현재 시즌의 기본 모델:

- 최대 소켓 7개
- 특수보석 1개
- 일반보석 6개

시즌 변경 및 아이템 규칙 변경에 대응할 수 있도록 데이터화한다.

## 6.2 일반보석

최고 품질 일반보석 기준:

- 첫 번째 2차 스탯 +16
- 두 번째 2차 스탯 +7
- 총 +23

6개를 장착하면 총 CHMV는 `23 × 6 = 138`이다.

단일 스탯 +17 보석은 총량 효율이 낮으므로 기본 최적화 예산 계산에서 제외한다.

사용자는 최적화 전에 일반 보석의 전체 종류와 조합을 개별 결정할 필요가 없다. 대표 프로필에는 보석 효과 구현을 위해 최고 품질 보석 6개를 실제로 배치할 수 있지만, **그 장착 보석의 CHMV 분배는 자유분배 후보를 제한하지 않는다.**

`주능력치 +23` 특수보석을 선택했을 때 일반 보석의 서로 다른 색상을 네 종류 이상 배치하는 구성은 **v1.1 후보에 제시된 입력 사례**다. 색상은 CHMV 네 스탯의 등장 여부와 같지 않으며, 이 구성을 **모든 시즌·모든 효과의 확정 규칙으로 승격하지 않는다**. SimC에서 요구되는 실제 아이템/색상 옵션을 프로필에 그대로 전달한다.

최적 CHMV 결과를 확인한 이후 사용자가 실제로 어떤 보석을 사용할지 결정한다.

단, 보석의 +16/+7 조합은 이산적인 실제 장착 제약을 가지므로, 자유 분배 예산 138이 모든 스탯 조합의 정확한 구현 가능성을 보장하지는 않는다.

이 차이는 프로그램의 허용된 추상화이며 필요하면 결과에 안내한다.

## 6.3 특수보석

현재 고려할 유형:

**유형 A**

- 주 능력치 +32

**유형 B**

- 주 능력치 +23
- 서로 다른 보석 종류/색상에 따른 치명타 피해 효과
- 종류당 치명타 피해 +0.15%
- 최대 +0.6%

특수보석의 주 능력치와 치명타 피해 효과는 CHMV 예산에 포함하지 않는다.

그러나 실제 DPS에 영향을 주므로 SimC에는 정확히 반영해야 한다.

특수보석 두 유형은 **사용자가 선택**하며, 선택한 실제 특수보석 Item ID 하나를 대표 프로필에 장착한다. 치명타 피해량 증가의 DPS 효과는 별도 자체 공식으로 계산하거나 SimC DPS에 덧씌우지 않는다. **SimC가 장착 보석과 색상 조건을 인식해 직접 계산**하도록 구성한다.

실제 보석 ID·소켓·색상 옵션의 **입력 정합성**과 정적 CHMV 중복 가산 여부는 우리 쪽에서 확인한다. 특수보석의 치명타 피해 발동 등 **전투 효과 판정은 SimC에 맡기며 독자적 구현/지원 인증 Gate를 두지 않는다**. CHMV 최적화 결과는 실제 보석 6개의 이산적 배치 가능성을 보장하지 않는다.

# 7. 영약·음식·물약·마법부여

## 7.1 공통 원칙

품질이 존재하는 소모품과 제작 효과는 최고 품질을 기본으로 한다.

단, 실제로 존재하는 품질 단계와 효과값은 시즌 데이터로 확인한다.

## 7.2 영약

영약의 고정 2차 스탯 총량은 CHMV 예산에 포함한다.

사용자가 최적화를 시작하기 전에 영약의 스탯 종류를 반드시 선택할 필요는 없다.

엔진은 고정 스탯 예산을 배분하고, 사용자는 최종 결과를 참고해 실제 영약을 선택한다.

이는 영약 아이템 조합 추천 기능을 만든다는 뜻이 아니다.

## 7.3 마법부여

부위별 마법부여는 사용자가 선택할 수 있다.

고정 스탯을 제공하더라도 자유 CHMV 예산에는 넣지 않는다.

단, 실제 DPS에는 영향을 주므로 SimC에 반영한다.

## 7.4 음식·물약·증강 룬·임시 강화

사용자가 사용 여부와 종류를 선택할 수 있다.

품질이 있는 경우 최고 품질을 기본으로 한다.

물약 사용 시점은 기본 APL을 우선 따른다.

무기 기름 등 무기 임시 강화의 고정 rating은 §5 공식 승인 총량식 `T=B+O`에 따라 처리한다. 무기당 치명+16·가속+16은 고정 벡터 O이며 자유 재분배하지 않는다. SimC 원본 설정과 최종 정적 주입을 정합시키되 아이템 효과를 재구현하지 않는다.

# 8. CHMV 탐색 제약

## 8.1 스탯별 범위

초기 실험에서는 다음 범위를 사용한다.

- 치명타: 0~50%
- 가속: 0~50%
- 특화: 0~50%
- 유연성: 0~50%

사용자가 각 스탯의 최소·최대 비중을 변경할 수 있게 한다.

이 제한은 현실적인 분배를 찾기 위한 경험적 제약이다.

실제 장비로 구현 가능한지를 증명하는 조건은 아니다.

## 8.2 탐색 단위

초기에는 큰 rating 이동 단위로 탐색한다.

유망 구간이 발견되면 이동 단위를 줄여 정밀 탐색한다.

스탯 변화량을 무조건 작게 만드는 것보다 좋은 후보를 빨리 찾는 것을 우선한다.

## 8.3 경계값 처리

최적 후보가 설정된 최대 또는 최소 스탯 제한에 도달한 경우 결과에 명시한다.

제약 밖에 더 높은 DPS 후보가 존재할 수 있음을 안내한다.

여러 시나리오를 실행한다면 결과를 독립적으로 관리한다.

서로 다른 시나리오의 DPS를 별도 가중치 정의 없이 임의로 합산하지 않는다.

## 9.4 레이드 버프

기본 레이드 버프 스위치와 외부 지원 버프는 구분한다.

버프의 정확한 포함 목록은 사용 중인 SimC 버전에서 실제 활성 효과를 확인해 기록한다.

직업별 버프나 대상 디버프, 블러드가 어떤 방식으로 적용되는지 결과에서 확인 가능해야 한다.

## 9.5 블러드와 APL

기본적으로 SimC의 기존 APL을 사용한다.

블러드 시점은 변경할 수 있지만, 시점 변경만으로 주요 쿨기가 자동으로 완벽하게 동기화된다고 가정하지 않는다.

SimC 기존 APL에서 해당 조건을 지원한다면 활용할 수 있다.

별도의 전문화별 블러드 동기화 APL을 새로 작성하는 기능은 기본 개발 범위에서 제외한다.

# 10. 지원 직업·전문화

**딜러(DPS) 정확히 26개 전문화만 지원 대상으로 한다. 증강 기원사, 모든 탱커 및 모든 힐러 전문화는 지원 범위에서 제외한다.**

**탱커·힐러 전문화의 지원과 개발은 범위에서 제외한다.** 이는 2026-10-26 사용자 최신 직접 결정에 따른 것으로 과거의 전 전문화(탱커·힐러 포함) 지원 의무를 철회한 것이다.

지원하는 DPS 전문화의 목적함수는 **SimC DPS 최대화**다. 탱커 생존성·힐러 치유량 최적화도 제품 범위에 포함하지 않는다.

일부 전문화에서 SimC DPS 실행이나 JSON2 결과가 불가능하면 그 **실행 실패/미지원 사실을 표시**한다. 다만 전문화 APL이나 게임 효과 자체를 우리 프로그램이 만들거나 보수하는 작업으로 확장하지 않는다.

전문화별 차이는 데이터·APL·설정으로 처리하며 핵심 최적화 엔진은 가능한 한 공통으로 유지한다.

# 11. 최적화 알고리즘

## 11.1 기본 흐름

1. 목표 총량과 제약 조건 확인
2. 초기 CHMV 후보 생성
3. 기존 실측 캐시 확인
4. 미계산 후보만 SimC 실행
5. DPS·오차·실제 적용 스탯 검증
6. 유망한 영역으로 탐색 확장
7. 근접 후보 재검증
8. 결과 수렴 여부 판단
9. 최고 및 대체 목표 산출

## 11.2 적응형 계산

모든 후보에 동일한 iterations를 무조건 사용하지 않는다.

초기 탐색은 상대적으로 적은 반복으로 수행하고, 유망한 후보에 계산량을 집중한다.

명확히 열세인 후보는 추가 실행을 피한다.

## 11.3 과도한 반복 방지

SimC는 확률적 전투 모델이므로 동일한 조건에서도 DPS가 완전히 같지 않을 수 있다.

통계 오차가 0이 될 때까지 반복하지 않는다.

사용자가 허용한 실행 예산에 도달했거나 충분한 비교 근거를 확보한 경우 종료한다.

우열이 불명확하면 해당 상태를 인정한다.

## 11.4 반복 횟수

일반 사용자에게 매번 iterations를 요구하지 않는다.

엔진의 자동 결정이 기본이다.

고급 설정에서는 다음을 변경할 수 있다.

- 초기 iterations
- 정밀 검증 iterations
- 최대 추가 실행 예산
- 종료 오차 기준
- SimC threads
- 난수·재현성 정책

## 11.5 통계 비교

단순 DPS 평균이 가장 높다고 최적 후보를 확정하지 않는다.

후보별 오차, 반복 조건, 비교 횟수 및 통계적 불확실성을 고려한다.

정밀 시험을 추가해도 구별할 수 없다면 동등하거나 미확정인 후보군으로 표시한다.

통계적으로 우열을 확정한 것과, 단순히 DPS 차이가 작게 관측된 것은 구분한다.

# 12. 근접 성능 대체 목표

## 12.1 기능 목적

사용자가 장비를 파밍할 때 최고 CHMV 절댓값을 정확하게 맞추지 못할 수 있다.

따라서 최고 후보와 성능이 비슷하면서도 **스탯 분배가 실질적으로 다른 후보**를 찾아야 한다.

예를 들어 다음과 같은 후보가 유용하다.

- 최고: 1000 / 1000 / 1000 / 200
- 대체: 600 / 1200 / 1200 / 200

반면 다음과 같이 몇 rating만 움직인 후보를 다수 나열하는 것은 우선순위가 낮다.

- 1000 / 1000 / 1000 / 200
- 990 / 1010 / 990 / 210

## 12.2 초기 기준

시험용 제안:

- 최고 DPS 대비 손실 1% 이내 우선 검토
- CHMV 총량 대비 스탯 변화량 10~15% 이상의 후보 우선 검토

이 값은 확정 수치가 아니라 실험용 기본값이다.

대체 목표는 DPS 손실과 스탯 분배 차이를 함께 고려해 선택한다.

## 12.3 결과 표시

각 대체 후보는 다음 정보를 제공한다.

- CHMV 절댓값
- CHMV 비율
- 예상 DPS
- 최고 후보 대비 DPS 차이 및 백분율
- 통계적 오차
- 최고 후보와의 스탯 분배 차이

대체 후보가 충분하지 않으면 의미 없는 후보를 억지로 생성하지 않는다.

# 13. 사용자 인터페이스 및 운영

## 13.1 기본 철학

프로그램은 복잡한 SimC 옵션을 모두 사용자에게 직접 요구해서는 안 된다.

일반 사용자는 필요한 핵심 조건만 정하고 실행할 수 있어야 한다.

고급 옵션은 별도로 제공한다.

## 13.2 진행 관리

- 한 번의 실행으로 전체 최적화 진행
- 현재 단계 및 진행률 표시
- 취소 기능
- 중단 후 재개
- 동일 조건 재실행 시 기존 결과 재사용
- SimC 오류 발생 시 원인과 로그 보존

## 13.3 두 종류의 캐시를 구별

**A. 아이템 정적 스탯 캐시**: 시즌, 정확한 item ID, itemlevel, slot, 옵션/bonus/crafted_stats 등의 variant identity를 키로 사용한다. **같은 시즌 안에서 SimC revision이 바뀌었다는 이유만으로 자동 폐기하지 않는다.** 새 시즌은 별도 캐시를 만든다. 동일 변형의 값이 달라지면 수동 교정 요청과 출처 증거 없이 덮어쓰지 않는다. 사용자 요청에 따른 정정/수정 이력을 기록한다. 캐시에 없는 비장신구 변형은 Native SimC 1회(필요 최소한) 조회로 채우고, 장신구 캐시 미스는 선택 차단 사유가 아니다.

**B. DPS 시뮬레이션 결과 캐시**: SimC 바이너리·데이터 버전, 캐릭터/특성/APL, 선택 장비 및 아이템 효과 ID·옵션, 장신구·장식, 소모품/버프/전투 시나리오, 목표 CHMV, iterations·실행 조건·입력 해시를 identity에 포함한다. 서로 다른 DPS 조건을 무단 재사용하지 않는다.

캐시 조회/저장 비용은 불필요한 SimC 재실행보다 낮게 유지하되 정확도를 희생하지 않는다. **중복 계산 방지와 취소·재개 경로**를 갖춘다.

## 13.4 결과 보존

최종 결과에는 설정과 분석 결과뿐 아니라 실제 SimC JSON2, 실행 로그, 입력 해시 및 사용한 버전 정보를 보존한다.

사용자는 결과를 다시 열어 어떤 조건으로 계산했는지 확인할 수 있어야 한다.

## 13.5 실행 환경

현재 개발 환경은 Windows와 Python 기반이다.

SimC는 사용자가 설치한 바이너리를 사용할 수 있다.

프로그램이 결과 파일을 생성하는 경우 출력 경로를 콘솔에 표시하고, Windows에서는 결과 폴더를 자동으로 여는 것을 기본 동작으로 한다.

폴더 자동 열기가 실패하더라도 계산 성공 여부에는 영향을 주지 않는다.

# 17. 지속 개발의 금지·의무 사항

1. 최종 목표는 CHMV **절대 rating 최적화**이다. 장비 조합 추천·파밍·완전 장비 DB로 확대하지 않는다.
2. 스탯 비율·DPS·SEM·대체 후보는 절대 rating과 함께 표현하되, 통계적 불확실성을 과장하지 않는다.
3. **SimC의 APL/아이템 효과/장식·장신구 proc/DPS 계산을 신뢰**한다. 별도 게임 메커니즘 엔진·지원 인증 Gate·효과 실험을 개발 목표로 추가하지 않는다.
4. 반대로 우리 책임인 **CHMV 정적 예산·고정 하한·주입 오프셋·결과 rating 정합**은 검증한다.
5. 제작장비 50:50 초기 분배는 고정하한이 아니고, 고유 특수장비의 고정 정적 CHMV만 `L`로 잠근다.
6. 장신구의 정적 gear 레코드가 없어도 선택을 막지 않는다. 미관측 수치를 0으로 단정하지 않는다.
7. 2026-10-26 사용자 공식 승인 수식 **`T=G+J+F+O`**. 레거시 기본 예산 `B=G+J+F`와 O 고정 벡터를 따로 보존하고 O는 재분배하지 않는다.
8. 정적 아이템 캐시는 **동일 시즌 SimC 버전만으로 무효화하지 않으며** 수정은 사용자 요청에 따른 명시 교정으로 관리한다. DPS 결과 캐시는 정확한 실행/SimC 버전 identity를 유지한다.
9. v015/v016 원본 제품 구현, GitHub v059 실험, Work OS M0 운영 Gate의 신분을 혼동하지 않는다.
10. MAIN/WORK 권한·제품 개발 주채팅의 소유권을 유지한다. Project Instructions·Sources·CURRENT·Shared State·v003 immutable의 무승인 변경 금지.
11. WEQUIP에서 가져온 과거 메타데이터를 단일 증거로 사용할 수 있어도 **운영 authority나 지속 런타임 의존성 금지**.
12. 이전에 통과한 Native 시험을 불필요하게 반복하지 않고 실행 상한·캐시·속도·구조 단순화와 반복 사용성을 같이 검토한다.
13. 한계가 남은 실험을 완성 제품이나 독립적으로 검증된 공식 상태로 승격하지 않는다.
14. 실제 Windows용 결과물은 출력 경로를 표시하고 가능한 경우 결과 폴더를 자동으로 열되 실패는 계산 성공과 분리한다.
15. 원래 제품 개발 채팅에서 사용자가 명시 승인한 일반 제품 SimC 시험에 반복 MAIN 승인을 요구하지 않는다. **공식 Work OS M0 실행·승격은 기존 별도 계약을 따른다.**
