### 1. 제품 불변 목표 및 사용자 경험

- **DPS 26개 전문화**만 지원(증강 기원사, 탱커, 힐러 제외). 미래 파밍의 목표 아이템레벨 기본 334(현재 구현 참조 범위 266–344) 또는 사용자가 지정한 **기름 포함 최종 CHMV T**에서 SimC **DPS 최대화**로 치명/가속/특화/유연의 **절대 rating**을 찾는다.
- 사용자는 직업·전문화·종족·특성, ilvl 또는 수동 T, 장신구 두 개, 선택 특수효과 장비, 장식 최대 두 개, 보석·영약·음식·물약·기름·전투조건 등을 지정한다. 프로그램이 대표 일반 장비/주능력치/무기/티어 4세트/SimC 프로필을 내부에서 구성한다. 현재 착용 장비 기준 재분배/장비 조합·획득 경로 추천/시즌 전체 장비 DB 구축은 하지 않는다. 업로드 SimC 프로필은 캐릭터·특성 읽기용 선택 입력이며 현재 장비를 목표 예산으로 복사하지 않는다.
- 출력은 최적 관측 rating/DPS/SEM/95% 판정, 통계적 우위 미확정 여부, 의미 있는 근접 대안, 최종 rating 비율이다. 95% 기준만 사용하며 관측 1순위와 전역 최적해 증명을 혼동하지 않는다. SimC가 아이템/특수효과/proc/APL/DPS를 계산하고 별도 효과 인증 Gate·효과 재구현·새 최적화 엔진을 만들지 않는다.

### 2. G까지 포함한 새 시즌 전체 예산 자동 구축 — 최우선 필수

```text
G = 동일 시즌·목표 ilvl의 대표 일반 장비·무기에서 구한 2차 스탯 예산
J = 검증된 기본 보석의 고정 2차 스탯 예산
F = 검증된 최고 품질 영약의 고정 2차 스탯 예산
O = 선택한 무기 기름(적용 손·무기 조건 충족)의 고정 2차 스탯 예산
B = G + J + F                   (기본 내부 자유분배 예산)
T = B + O = G + J + F + O      (사용자 표시 최종 CHMV 총량)
c_final = c_base + o          (O는 비자유분배)
```

1. 새 시즌의 **대표 방어구·무기·티어 ID, 목표 ilvl별 G 산출 또는 시즌별 유효 참조, J, F, O**를 해당 시즌의 원본·빌드·검증 영수증으로 다시 결정한다. B와 T는 변경된 값으로 **자동 재계산**한다. 이것은 단순한 “J/F/O 소모품 자동 갱신”이 아니라 **시즌별 G/J/F/O 전체 예산 자동 구축 및 B/T 통합 갱신**이다.
2. 기존 시즌 **79×2 ilvl 참조 B**, J=138, F=165, 기름의 무기당 치명16·가속16 등의 **현재 시즌 값은 새 시즌의 검증값이 아니다**. 검증 없이 복사/고정/자동 구축 완료 표시 금지. 동일 시즌·동일 조건에서 유효한 기존 측정/캐시만 재사용하고 변경으로 실제 무효화된 증거만 최소 보완한다. 전 전문화·전 ilvl Native 무조건 전수 반복 금지.
3. 사용자가 최종 T를 수동 지정하면 그 값이 최우선. `B=T-O`로 환산하고 J/F, 선택 특수장비 고정 L, 정적 영구 마부 E 및 스탯별 하한·분배 가능성을 검증한다. 새 시즌 값이 바뀌었다는 이유로 수동 T를 덮어쓰지 않는다.
4. 특수장비 정확 L은 **G/B 내부에 이미 있는 고정치**라 다시 더하지 않고 하한만 보호한다. 정적 E도 G 내부에 귀속하고 자동 ilvl **마부 없는 참조 기준**에서는 정확히 검증된 **추가 정적 E만 한 번** 반영한다. 수동 T에서는 E를 다시 더하지 않는다. 장신구 고정 스탯은 자유 G 밖이며 JSON2 정적 레코드 누락을 0으로 단정하지 않는다. 제작장비 초기 50:50을 L로 잠그지 않는다. O는 실제 적용 가능한 무기에만, `gear_*`에서 한 번만 처리한다.
5. exact Native G는 더 정확한 대표 예산을 확인하는 **선택 경로**이지 모든 전문화·장비의 전수 필수 선행 Gate가 아니다. G 참조가 근사값이면 근사값임을 유지한다. 새 시즌 G가 미검증이면 정상 환경 구축 완료를 선언하지 않는다.

### 3. 최고 품질 선택지 / 일반 임시 마부 / 무기 기름

- 보석·영약·음식 등 품질 있는 아이템은 **정확히 동일한 효과·적용 조건·범위가 검증되고 모든 관련 수치에서 높은 품질이 열등하지 않을 때만** 품질 중복을 제거한다. **검증된 가장 높은 품질만 일반 사용자 선택지에 표시**한다. 서로 다른 스탯 방향, 주문/효과 구조, 제한 조건은 별도 선택지. 이름, 아이템레벨, 품질 명칭만으로 비교/동일성 추정 금지. 소스 행/검증 증거는 내부에서 필요한 만큼 보존.
- **영구 마부는 검증·자동 등록 대상**. **일반 임시 마부는 제품 지원 범위와 일반 카탈로그에서 제외**하고 원본 전수 수집·검증을 확장하지 않는다. 단, **무기 기름은 계속 지원**한다. SimC가 `temporary_enchant=` 문법을 사용하더라도 별도 oil 입력으로 관리하고 적용 손/무기·고정 O·중복 방지를 유지한다.
- 사용자 승인 **정책 A**: 정확한 ID/게임 빌드/SimC 입력/적용 범위/CHMV 예산 소유권의 내부 검증을 모두 통과한 새 항목은 별도 항목별 수동 승인 없이 자동 발행. 불명확한 항목만 보류하되 확인된 기본 환경까지 막지 않는다. SimC 효과·proc 자체의 별도 인증 Gate는 만들지 않는다.

### 4. 음식·영약·기름과 확장팩 특수 시스템

- 목표: 사용자 한 번의 **Environment Build** 요청에 따라 시즌 원본 탐색·같은 빌드 확인 → 효과/품질/적용 범위 관계 조인 → 대표 장비 G와 최고 품질 J/F 및 기름 O 증거 확인 → B/T 정합 → 버전화된 내부 환경 데이터와 검증된 사용자 목록 자동 설치·적용 → 실제 SimC 입력 경로를 연결한다. 기존 세션과 캐시는 덮어쓰지 않는다.
- **현재 미완료임을 명시:** `v190`은 음식/물약 ID 후보만 조인, `v191`은 기존 참조 J/F를 재사용, `v108`은 J=138/F=165 고정 검사를 포함, `v091`은 `thalassian_phoenix_oil_2`와 O=치명16+가속16/무기를 고정, `v089`은 같은 시즌 79×2 참조표를 사용한다. `v216`은 이미 설치된 v213 source artifact를 재사용하고 새 시즌 원본 수집을 직접 실행하지 않는다. 새 시즌 예: F=250을 **자동 수집→검증→적용**하거나 **새 G를 자동 구축**하는 기능은 아직 끝나지 않았다. 같은 빌드/시즌 불일치 값의 무단 재사용 금지.
- **Omnium Folio 등 확장팩·시즌 전용 콘텐츠는 핵심 DB에서 분리한 선택형 애드온**으로, 사용자가 쉽게 ON/OFF. 적용하면 정확한 SimC 입력/필요한 CHMV 영향, 미적용하면 관련 입력·예산 효과 0/완전 제거. 모듈 ID/버전/활성화/옵션을 세션·캐시 identity에 포함한다. 환경 구축 완료 단계에서는 “이번 시즌 특수 콘텐츠는 GPT를 통해 모듈 갱신을 요청할 수 있음”만 안내; GPT 자동 호출·영구 의존성은 금지. `v108`의 현재 Omnium 직결 구현과 별도 add-on UX/격리는 미완료.

### 5. Environment Build 완료 판정 (필수)

1. 시즌·게임 빌드·SimC revision/바이너리와 대표 일반 장비·무기·티어 ID의 출처가 일관됨.
2. 목표 ilvl의 **G** 정확 계산 또는 유효 동일 시즌 참조값 검증.
3. 해당 시즌 최고 품질 기본 보석 **J** 및 영약 **F** 정확 수치/스탯 방향과 입력 확인.
4. 선택할 수 있는 무기 기름 **O**와 적용 가능한 무기/손/스탯 고정치 확인.
5. **B/T 통합 재계산** 및 L/E/O 이중 계상 방지, 고정 하한/수동 T 우선 정합 확인.
6. 검증된 사용자 선택지와 실제 SimC 프로필 입력 경로의 일치.
7. 원본 출처·시즌·빌드·옵션·예산·프로필·바이너리·캐시/session identity/검증 영수증 기록.

필수 G/J/F/O가 아직 미확정이면 “정상 구축 완료”로 표시하지 않는다. **선택적 항목만 미검증이면 그 항목만 보류**한다. 실제 SimC 오류는 원문 기록. 구현 코드/오프라인 테스트/재사용된 과거 Native 증거/새 Native 결과/미구현을 별도로 기록한다.

### 6. 우선순위 및 개발 소유권

**시즌별 G/J/F/O 원본·예산 자동 구축 → B/T 통합 갱신 → 최고 품질 및 정책 A 검증 선택지 자동 등록 → 사용자별 대표 프로필·기존 적응형 SimC 실행/결과/캐시/취소·재개 일체화.** 별도 새 최적화 엔진, 대규모 Native 반복, 전체 아이템 DB, 무의미한 과거 재감사 금지.

- 같은 시즌 정적 아이템 캐시는 SimC revision만으로 폐기하지 않는다(명시 교정은 사용자 요청). DPS 캐시는 바이너리/프로필/시즌/모듈/옵션/후보/O/전투조건/iterations identity에 따라 구분한다.
- 변경마다 중복 네트워크 수집·Native 호출·메모리·I/O·캐시 재사용·실행시간을 검토한다.
- 기존 주 제품 개발 채팅이 구현과 일반 제품 SimC 시험을 소유하며 이 격리 브랜치는 별도 실험/구현 허용 범위다. `main`, immutable 원본, Work OS 공식 승격, Project UI 적용을 **GitHub 커밋으로 간주하지 않는다**.
