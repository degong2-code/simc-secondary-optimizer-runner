# GEM J — 사용자 직접 확정 분류·선택·소켓·예산 정책 (2026-11-17)

> **찾기 위한 정본:** 신규 시즌 일반보석 ItemID 자동 발견, C/H/M/V 4종, 다중스탯, 4개 초과 소켓, J 총량.  
> 이 문서는 2026-11-17 최신 사용자 직접 결정의 정확한 기록이다. 이전 v548/v549 구현·역사 가정과 충돌하면 사용자 결정이 우선한다. **아래의 미결정 항목을 사용자 확정 정책인 것처럼 임의 승격하지 말 것.** Project UI/Instructions에 적용되었다고 주장하지 않는다.

## A. 사용자 확정 — 분류

1. **Primary Stat(주스탯) 상승을 포함하는 보석은 전부 특수 보석.** 이 명제는 모든 특수 보석이 반드시 주스탯을 올린다는 역명제를 뜻하지 않는다.
2. **Secondary Stat(보조스탯) 상승만 있는 보석은 일반 보석.** 다른 기능의 예외적인 효과가 명확하지 않으면 임의 분류하지 않는다.
3. 일반 보석 중 **한 종류의 보조스탯만** 올리면 *단일스탯 보석*이며 **제품에서 일반 보석으로 사용하지 않는다.**
4. 일반 보석 중 **두 종류의 보조스탯을** 올리면 *다중스탯 보석*. **최고 품질 다중스탯 보석만 사용**한다. 품질 비교는 **동일 효과·조건**에 한정해 수치가 열등하지 않은 최고품질을 택한다(기존 사용자 승인 최고품질 원칙 보존).
5. 두 종류 보조스탯의 수치가 서로 다르면 **높은 쪽을 대표/메인 보조스탯**으로 삼는다. C=치명(crit_rating), H=가속(haste_rating), M=특화(mastery_rating), V=유연(versatility_rating). 예: C20+H10 ⇒ **C 보석**.
6. **C/H/M/V는 대표 보조스탯에 따른 4개 종류**이지 모든 다중스탯 효과 조합이 딱 4개 있다는 뜻이 아니다. C+H, C+M, C+V는 모두 C가 더 높은 경우 **서로 다른 조합의 C 보석**일 수 있다. 대표스탯이 동률이면 메인 판정이 불가능하므로 현재 미결정/보류.
7. C/H/M/V 다중스탯 일반 보석을 **기본적으로 각각 최소 1개씩** 배치한다. 이유: 특정 특수 보석의 '착용한 서로 다른 보석 종류 수' 관련 추가 효과를 충족하기 위한 내부 프로필 구성. **특수 보석 효과 자체는 SimC가 계산**; 별도 효과 메커니즘/인증 엔진 만들지 않는다. 다른 특수 보석을 사용하더라도 4종 기본 배치 규칙은 유지한다.

## B. 사용자 확정 — 실제 소켓 수와 J

8. **4종 기본 배치는 '일반 보석은 정확히 4개'라는 수량 상한이 아님.** 사용자가 더 많은 소켓을 선택하면 그 **실제 장착한 전체 일반 다중스탯 보석 수**만큼 J를 계산한다.
9. 각 보석의 보조스탯 두 값의 합계가 보석 1개의 J 기여분. `J = Σ (각 실제 장착 일반 다중스탯 보석의 C+H+M+V 증가량)`이며, 보석이 반복 장착되면 **그 반복 횟수만큼 모두 더한다**. 특수 보석은 일반 J 장착 수에서 제외한다. 일반 보석 4개면 4개 합산, 6개면 6개 합산, 8개면 8개 합산. **시즌 상수 J=92, 보석 한 개 J=23를 새 시즌에 복사하지 않는다.**
10. 특수 보석이 1개인 경우 이를 일반 4종과 **별개 물리 소켓 한 자리**로 센다. 따라서 일반 4종+특수 1개 기본 배치는 총 물리 소켓 5개. 특수 보석이 없으면 기본 물리 소켓 4개. 선택된 추가 소켓은 실 보석 개수와 프로필에 동일하게 반영한다.
11. 일반 보석은 **이미 유효한 소켓이 뚫린 장비라면 장비 종류에 무관하게 장착 가능**하다. 소켓을 만들거나 소켓 수를 정하는 게임 내 장비/효과 규칙은 별개다. 일반 보석 ItemID별로 장비 종류 허가를 독립 검사하는 새로운 Gate를 만들지 않는다. 기존 소켓 수/배치 경로를 재사용한다.
12. 기름 포함 수식 **`B=G+J+F`, `T=B+O`**를 유지한다. 보석 효과는 SimC 프로필에 들어가고 CHMV는 기존 gear_* 및 예산 소유권/중복 방지 계약을 유지한다. **다른 물리 원천 수치를 J에 중복 가산하지 않는다.** 사용자가 최종 T를 지정하면 T가 우선한다.

## D. 정확한 미결정과 다음 단계

1. **대표스탯이 같은 최고품질 다중스탯 보석이 여러 개일 때**(예: C20+H10, C20+M10) 어떤 ItemID를 기본 선택할지 정책 미결정. 다른 secondary 파트너는 효과가 다르므로 '동일 효과 최고품질'만으로는 하나를 확정할 수 없다. 제품이 독립 DPS 최적화/장비 추천을 추가하는 방식으로 해결하지 말 것.
2. **4개 초과 추가 일반 보석의 유형 분배**: 기존 코드는 C→H→M→V 순환 반복; 사용자가 이번 대화에서 명시 승인한 내용은 '소켓 수에 맞춰 모든 장착 보석을 J에 합산'이며 순환 우선순위 자체는 명시하지 않았다.
3. 상승 두 값이 **동일**한 보석은 어느 대표 유형인지 이번 대화로는 결정 불가. 실제 출처에 있으면 결정받기 전 PENDING; 없으면 불필요한 Gate로 확대하지 않는다.

**ID 조사 착수 조건:** 기존 코드의 충돌·미결정 내용을 먼저 사용자에게 알리고 선택 규칙을 확인한다. 그 후 실제 보석 ItemID 원본 발견 경로를 기존 Wago v221 또는 봉인 SimC v191/v230/v275에서 순서대로 조사한다. 이미 구현된 소켓·J 합산을 신규 과제로 재개발하지 말 것.
