# v106 — Windows beta user interface on the proven v105 DPS journey

**2026-10-26 KST · isolated GitHub development only**. Product scope from latest direct user decision: **27 DPS specializations only**, not tank/healer; currently **six** source-backed input archetypes, NOT all 27 ready.

## Goal / actual implementation

- `START_SIMC_OPTIMIZER_WINDOWS.cmd` double-click starts the lightweight, stdlib-only `runner/v106_windows_simple_gui.py` (Python 3 + Tkinter required). No PyCharm or hand-built JSON/manifest needed for the **default representative gear** scenario. An installed Windows SimC executable and its accurate Git revision must be selected/entered on first use; last binary path/revision are stored in a user-local settings file. The program does **not** bundle or install SimC.
- The beta screen contains six source-backed DPS specs, character race and talents (preloaded from pinned representative source profile but editable), target ilvl 266–344, optional **manual final T including O**, two trinket IDs, main/offhand oil according to observed legal weapon topology, targets/duration/raid buffs, binary/revision fields. Item slots, complete current gear, filler, Native JSON2 and search seeds remain internal. Current beta has **no custom special-effect items, embellishment or fully user-selected gems/flask/food/potion/Omnium UI**; existing v098 supports some internally, UI selectors are future P1 work.
- Pure lightweight `runner/v106_user_session_controller.py` converts only user controls into the existing **v098 accepted JSON**. Stable session ID is SHA256 of canonical user controls + real SimC binary SHA + revision + optional static item cache SHA. Default results under `%USERPROFILE%\\SIMC_Secondary_Optimizer\\runs\\<20-char-session-key>`; changes produce a *new folder*, exact same settings resume same folder.
- Worker subprocess calls the existing `v098.run(...,execute=True) → v096.run_manifest() → v094`, never creates new Native engine/statistics or an additional expensive optimizer. It reads previous durable `V094_PROGRESS.json` / `V094_RESULT.json`, updates progress every ~450ms, presents absolute four CHMV T ratings **plus percentages**, observed DPS + SimC SEM, selected pair 95%-only direction, observed material alternatives, and explicitly **does not claim global optimality**.
- Clicking **취소** creates existing `generated/CANCEL` marker. Existing v094 checks this between or during Native jobs; prior Native JSON2 and source-locked receipts are **not removed**. **재개/실행** clears that flag and reuses the same session identity; existing verified Native cache is reused (as proven in prior v105 real user test). The UI process avoids blocking by launching a worker child, and follows its existing log/status. A per-session Windows `msvcrt.locking` / Unix `fcntl.flock` OS lock rejects duplicate concurrent workers and automatically unlocks after process exit/crash; lock file is constant-sized. Results are saved atomically, with semantic drift protection when a cache replay's *metadata* (cache-hit count) changes but actual Native 95%-result remains constant.
- Windows native folder auto-opening uses `os.startfile` through existing runner; GUI's '결과 폴더' button also opens session folder. Windows UI close during active run requests cancellation (does not delete running state). The tool does not autonomously run in the background after ChatGPT response.

## Windows beta usage

1. Clone/download this isolated branch, install Python 3 with Tkinter and obtain a legitimate Windows-compatible SimC executable. Double-click `START_SIMC_OPTIMIZER_WINDOWS.cmd`.
2. Choose a **source-backed DPS specialization** from 6 options. Pinned race/talents and two trinket IDs populate automatically; edit them if desired. Choose target ilvl or manual **inclusive final T**, oil and combat settings.
3. On first use, browse to installed Windows `simc.exe` and enter the **verified matching Git revision** of that executable. Use the exact revision, not the historical Linux binary's revision for a different installed build. Subsequent launches reuse saved binary path/revision.
4. Click **실행 / 동일 설정 재개**. Watch Native progress (max 6 calls for current default), stop by **취소**, return later with exact same user options/binary/revision to resume. Changing input intentionally gets a **different** session and Native cache identity. Click **결과 폴더** to inspect Native JSON2/reports.
