**Date:** 2026-10-26 KST. **Branch:** isolated `probe/chat-cache-v035-20261024`. Latest direct user scope remains **27 DPS specializations only**, tank/healer out. Six source-backed DPS user input profiles presently active. **Zero new SimC Native calls in this version.**

## Implemented P1 — no invented effect mechanics

- `runner/v108_native_consumable_inputs.py` adds a **bounded, verified SimC syntax** adapter for `food=`, `potion=`, `augmentation=`, `flask=`, `omnium_talents=` and existing `head=...,gem_id=` with one exact source-backed representative profile. These original assignment names exist in all six **pinned SimC** fixtures. Exactly one assignment per option; duplicates / invented token names are refused. All actual effects, APL use and damage stay owned by real SimC.
- v098 accepts an **optional** `consumable_choices` field and applies it to existing source-backed gear, then recomputes SHA and hands the profile unchanged into existing `v091` oil adapter and `v096/v094` Native pipeline. Older v098 inputs without the field still work; no new optimizer, manifest structure, stat-proc model or full item catalog.
- `runner/v106_user_session_controller.py` carries source-default or explicit choices in the canonical user/binary/revision/cache session key. `runner/v108_user_consumable_dialog.py` adds a small Windows user selector. It does not expose source manifest, filler or seed. The primary user can choose source-observed food (3 existing tokens or disabled), potion (2 existing tokens or disabled), augmentation rune (2 existing tokens or disabled), one of two Eversong Diamonds, and **six complete source-observed Omnium Folio loadouts**. Actual number of selectable alternatives is bounded, not the full combination of five Folio rows.
- **Diamond `240983`** (Indecipherable Eversong Diamond) and **`240967`** (Powerful Eversong Diamond) are **primary stat + special effect** gems, no static secondary rating; replacing the head primary-only gem between these two does not change fixed `J=138`. The exact item ID is serialized into `gem_id=` and `consumables.special_gem_id`, so SimC can apply the actual bonus. If the user selected a special head with *no* gem, the source-default diamond is not silently invented; one may select an explicit primary-only diamond subject to exact special-item variant cache preflight.
- **Flask:** known class-specific `flask=` token and exact historical **`F=165`** vector are retained. User cannot freely change to an alternative flask yet: it would require a verified new F vector and would misallocate the CHMV B budget if silently kept at 165. Such requests fail before Native. Changes to food/potion/augmentation and Omnium are SimC-owned external effects. Default target ilvl334 general `B=3150`; one oil `O=16 crit+16 haste=32` -> user-visible `T=3182`. Fury dual-TG reference is the known separate `B=3350`, not recomputed for consumables.
- **Omnium discovery/correction:** the six existing upstream MID2 SimC fixtures already provide an exact valid `omnium_talents=136822:1/.../.../.../136814:1` structured **five-row trait configuration**. This is NOT `augmentation=` (which means augment rune). The six original full strings are stored as `OMNIUM_PRESETS`, and one may select a **whole pinned loadout**; arbitrary mutations, unverified rune ids, ranks or 5-row combinatorial enumeration are blocked. Their *cross-spec* Native DPS effects when swapped are **not verified here**. This corrects the initial inference that the Omnium token was unavailable. See upstream addon `core.lua` listing `omnium_talents` as an exported additional trait system.
- The built-in existing user-selected specials/embellishments continue to retain exact L once and catalyst original effects as SimC source, not an independently certified proc. Head gem option changes alter the full profile SHA and static special item cache identity. No recalculation of effects.
- A requested absent oil remains explicitly handled by existing v091 at final Native input preparation; v098's *pre-oil* displayed `profile.simc` is not proof that the oil was omitted from the v096 Native input. This distinction is preserved in offline tests.
