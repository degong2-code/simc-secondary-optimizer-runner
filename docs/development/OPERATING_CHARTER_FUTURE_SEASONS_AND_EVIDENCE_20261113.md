## 1. 세 계층을 혼동하지 않는다

1. **ENGINE / 시즌 독립:** 수집·소스 계약·컴파일·검증·캐시·대표 장비/프로필 구성·G/J/F/O 회계·SimC 실행·적응형 최적화·중단/재개·오류 처리. 시즌별 하드코딩을 최소화한다.
2. **SEASON / 시즌별 검증 환경:** 정확한 시즌·지역·게임 빌드·원본 SHA·대표 방어구/무기·티어 5개 ID·G/J/F/O 및 마부/아이템/선택지·적용 조건·동일 빌드 SimC 정체성. 매 시즌 새로 판정한다.
3. **USER / RUN / OPTION:** 사용자 전문화·특성·목표 ilvl 또는 수동 최종 T·장신구/특수장비/장식/보석·영약·기름·전투 조건·시즌 모듈 및 실제 설치된 변형·최적화 결과. 다른 사용자 조건으로 증거를 자동 확장하지 않는다.

**독립 판정:** ENGINE의 계약 테스트 성공 ≠ 새 SEASON의 READY. 과거 SEASON의 Native 성공 ≠ 다른 SEASON의 READY. SEASON BASE READY ≠ 모든 USER/OPTION 변형 READY. 코드의 함수 존재 ≠ 실제 제품 호출 경로 연결.

## 2. 현재 시점에서 증명 가능한 것과 불가능한 것

| 대상 | 현재 허용하는 증거 | 금지되는 주장 |
|---|---|---|
| 범용 계약·오류 처리 | 시즌 값/ID/품질/소켓/무기/기름/모듈 변경을 가정한 오프라인 합성 계약 시험 | 미래 시즌 실제 소스/아이템 인증 완료 |
| 현재 실제 시즌 | 같은 시즌·빌드 원본·필수 소스·SHA, 실제 Native JSON2 및 제품 E2E | 한 시나리오 성공으로 26 DPS·모든 선택지·모든 시즌 READY |
| 미래 시즌 대응 **엔진 기능** | 현재 실제 시즌 완전 ZERO-SOURCE 자동 식별·원본 확보·필드 관계 검증 PASS + 하드코딩 방지 변형 회귀 → **ENGINE_AUTODISCOVERY_PASS** | 실제 출처/키 없이 합성 코드만으로 PASS, 미공개 시즌 데이터/ID·아이템 수치 선인증 주장 |
| 기존 증거 | 정확한 적용 범위의 봉인 영수증·Native·캐시 재사용 | 다른 시즌/바이너리/프로필로 무단 외삽 |

범용성은 모든 아이템을 미리 알거나 모든 시즌을 선제 검증한다는 의미가 아니다. 신규 원본을 **수집·해석·소비·차단·재실행하는 일관된 계약**이 있다는 의미다.

## 3. 제로베이스 시험은 목적과 엄격도를 분리한다

- **ZERO-CONTRACT:** 가상 미래 시즌·누락 필드·충돌·품질 변경·O 손 변경 등의 합성 입력으로 ENGINE 규칙을 시험. 실제 시즌 수치 인증이 아니다.
- **ZERO-INSTALL:** 새로운 설치/캐시 작업공간에서 제품의 기본 수집·설치 경로를 실행. **동일 시즌 검증된 패키지 내 원본/바이너리 번들**을 썼다면 그 의존성을 영수증에 명시한다. 이 경우 '외부 원본 완전 무이력 재수집'이라고 부르지 않는다.
- **ZERO-SOURCE / 엄격한 실제 신규 원본 시험:** 역사 시즌 DB·고정 G/J/F/O·완성 매니페스트·이전 정답을 입력으로 주입하지 않고, **실제 시험 시점의 현재 시즌**을 승인된 원본과 정상 제공된 OAuth/API 키·pinned SimC에서 코드 자체가 자동 발견·수집하여 BUILD→예산→설치→프로필/Native까지 진행. 올바른 결과와 재현 가능한 출처/빌드·관계·SHA를 대조한다. 이 **범용 자동 발견 기능의 실제 성공은 미래 시즌 미출시와 무관하게 엔진 기능 PASS**다. 인증/수집 권한이 없는 별도 시험은 BLOCKED/미검증으로 기록하고, 정상 권한을 가진 ZERO-SOURCE PASS를 대신할 수 없다. 역사 증거는 **사후 독립 대조**만 가능.
- **USER-E2E:** 검증 설치 manifest와 정확한 사용자 변형에서 실제 SimC JSON2 정적 rating → DPS/SEM/95%·대안·캐시·중단/재개·결과 화면을 연결. ZERO-INSTALL 또는 ZERO-SOURCE인지 구분하여 보고.

**실행 빈도:** 모든 코드 커밋에 ZERO-SOURCE나 Native를 요구하지 않는다. 소스·설치 경계 수정/핵심 마일스톤·새 시즌에는 필요한 강도로 시험하고, UI/문서·국소 기능 수정은 해당 범위의 회귀를 우선한다. 과거 성공을 삭제하거나 처음부터 전수 재연구하지 않는다.

## 4. 78개 원장은 증거 범위와 준비 상태를 따로 기록한다

- A 11 / B 12 / C 14 / D 9 / E 9 / F 7 / G 10 = 환경·사용자 경로 72개; H 6 = 최적화, 총 78개. **78개 독립 인증 Gate·Native 78회가 아니다.**
- 적용 범위는 BASE / USER / RUN / OPTION. 기본 환경 필수 항목은 실제 소비하는 원본으로 READY를 판정하고, 미선택 옵션 미해석은 BASE를 차단하지 않는다.
- **증거 수준:** CODE_IMPLEMENTED, OFFLINE_PASS, ACTIONS_PASS, NATIVE_PASS, E2E_PASS 및 각각의 조건·SHA·실시 여부를 별도 기록. Actions PASS와 실제 Windows/사용자 PC Native PASS도 구별한다.
- **준비 판정:** PENDING_SCOPE, READY_SCOPED, BLOCKED_EXACT, NOT_APPLICABLE_SCOPE 등 적용 범위를 명시해 별도 기록한다. 단순 코드 존재·역사적 제한 범위 PASS로 새 READY를 자동 선언하지 않는다.
- **요소별 확인 항목:** (a) 제품이 실제 소비할 필드/조건 (b) 원본 소유자/빌드/SHA (c) 기존 구현 및 실제 호출 연결 (d) 예산·프로필·JSON2 정합 (e) 최소 시험/영수증 (f) 차단 이유 (g) 다음 의존성.
- 상태 변경 시 [78개 추적표](ENVIRONMENT_READINESS_78_ELEMENT_TRACKER_20261113.md)에 **증거 링크와 적용 시즌·빌드·ilvl·사용자 조건**을 기록한다. 미실증/미구현/실제 재현 결함을 섞지 않는다.

## 5. 원본 및 계산의 소유권과 READY 계약

1. **수집·인증 근거:** 제품 자동 경로가 실제 반환받은 Blizzard API, 승인 WCL API, 같은 빌드 DB2, pinned SimC 및 봉인 영수증. GPT 검색·공식 웹페이지 수동 추론·가상 fixture는 런타임 인증 근거가 아니다.
2. **필수 최소 증거:** 실제 선택/기본 실행에서 사용하는 아이템의 정확한 ID·시즌/빌드·효과 구조·적용 범위·SimC 입력·예산 소유권. 전 아이템/모든 시즌 후보/무관한 WSE/일반 임시 마부 수집을 기본 Gate로 요구하지 않는다.
3. **시즌 예산:** G=대표 일반 장비·무기 보조 스탯, J=검증된 기본 보석, F=검증된 최고 품질 영약, O=선택 무기 기름의 고정 스탯; **B=G+J+F; T=B+O; c_final=c_base+o**. 새 시즌에서는 G까지 해당 시즌 원본/유효 시즌 참조로 결정한다.
4. **수동 T:** 사용자가 명시한 T가 우선하며 B=T-O로 환산. J/F/L/E 고정 하한과 분배 가능성을 검증하고, 과거 자동 예산으로 덮지 않는다.
5. **고정치:** L은 G에 포함되어 스탯별 하한으로 한 번만 보호; 정적 E는 해당 승인 회계에 따라 한 번만 처리; O는 gear_*에 한 번만 반영하고 결과 재가산 금지. 장신구 정적 스탯은 자유 G 밖, 미관측은 0이라고 단정 금지. 제작 초기 50:50은 L 잠금 금지. F 고정 하한이 존재해도 기어 자유 배분 0 후보는 허용.
6. **대표 장비/티어:** 목표 ilvl·전문화/무기 형태·주능력·무기 성능 일관. 같은 시즌 정확한 5티어 원본을 확보하고 실제 4세트를 유동 유지; 기존 v101/v098 구현 재사용.
7. **선택지:** 동일 효과·조건·적용 범위와 품질 수치 비열등성이 원본으로 증명될 때 최고 품질만 사용자 노출. 항목별 검증 후 Policy A 자동 등록, 미검증 선택지만 보류. 무기 기름과 일반 임시 마부는 제품 개념상 구별; 확장팩 전용 시스템은 ON/OFF 별도 모듈.
8. **책임 분리:** SimC가 아이템 효과·proc·APL·DPS를 계산한다. 제품은 입력과 JSON2 정적 rating·DPS/SEM·캐시를 검증한다. 독립 효과 메커니즘 재구현·신규 효과 인증 Gate 금지.

**필수와 선택의 경계:** BASE 환경 READY는 검증된 기본 G/J/F/O·대표 장비/소스/설치로 판정. 실제 사용자에게 선택된 다른 영약/기름/소켓/특수장비 등의 검증 설치 SHA가 없으면 **그 USER 변형만 fail closed**하고 과거 BASE 숫자로 대체하지 않는다. O0는 명시적으로 검증된 미사용 값이어야 한다.

## 6. 실패를 발견하면 바로 새 시스템을 만들지 않는다

아래 순서로 **첫 실제 실패 경계**를 특정한다.

1. 요청 정체성: 시즌·빌드·지역·ilvl·전문화·사용자 BASE/USER/OPTION·SimC 버전.
2. 봉인 원본 및 캐시: 기존 유효 소스·영수증·공급자 출력·missing 필드.
3. 소유자 대조: 카탈로그 컴파일 입력 부족과 숫자 G/J/F/O 인증 부족을 분리. 실제 v216의 **source_compilation.missing** 및 **required_core_source_owner_report**를 확보하기 전 누락 원인을 추측하지 않는다.
4. 설치 경계: 기존 v274/v275 카탈로그 → v222 수치·하한 → v212 설치의 정확한 소비/차단 관계. 필수 숫자·소스 검증을 억지로 우회하지 않는다.
5. USER 연결: v101 티어 유동, v098 개별 사용자 프로필, v350 설치 변형/HTTP422 조건과 정확한 manifest SHA.
6. Native/결과: JSON2 실제 정적 rating, DPS/SEM/명목95%, 선택쌍 우위/전역 미입증, v290/v291/v293 캐시와 취소/재개.

**미확보된 증거 ≠ 발견된 실제 결함.** 미선택 소스가 BASE READY를 차단한다면 실제 소비 관계를 조사해 최소 분리 수정할 수 있지만, 인증·정합성을 약화시키는 우회는 허용하지 않는다.

## 7. 수직 제품 경로 우선 로드맵

- **M0 복원/병목 확정:** 실제 HEAD와 최신 봉인 영수증을 확인하고 A10 원본 컴파일·A11 원본 영수증·G2 시즌 실행 중심으로 첫 missing/source owner를 실측. 기존 구현 범위를 정확히 복원.
- **M1 BASE:** 필수 시즌 소스→대표 일반 장비/무기·티어5→G/J/F/O→B/T·L/E/O 회계→기존 v212 VERIFIED 설치. 유효 동일 시즌 증거 재사용.
- **M2 USER:** 정확한 장신구2/선택 특수장비·장식 최대2/보석·영약/기름/수동T·유동4pc→v098 프로필→JSON2 정적 CHMV 일치. 미검증 개인 선택은 해당 변형만 422 차단.
- **M3 RUN:** 기존 v290/v291/v293 적응형 SimC DPS·SEM·관측1순위·명목95% 확정 여부·실질적 근접 대안·스탯 비율·캐시·취소/재개·결과 출력의 한 정확한 조건 E2E.
- **M4 범용 확대:** 26 DPS·선택 변형·새 시즌 입력·경계/오류 복구를 **변경된 증거 범위만** 증분 검증. 미래 시즌 실제 READY는 공개 후 별도 판정.

각 단계는 78개를 순서대로 재구현하는 작업이 아니라 **최소 연결 묶음의 수직 경로**를 완성한다. M3 한 조건 성공은 전체 제품·전문화·시즌 완성을 의미하지 않는다.

## 8. 재사용·자원 비용·검증 빈도

- 매 변경을 **REUSE / CONNECT / EXTEND / REPLACE / NEW / STOP** 중 하나로 분류. 먼저 INDEX→FILE_MAP→EVIDENCE_INDEX→실제 코드를 확인하고, 동일 기능 신규 작성 금지.
- 실제 변경 영향에 필요한 최소 오프라인/Actions/Native만 실행. Native 호출수, SimC iterations, 기존 캐시 적중, HTTP·DB2 다운로드, CPU·메모리·I/O·실행시간·중복 수집과 시즌별 리빌드 비용을 검토한다.
- 동일 시즌 정적 아이템 캐시는 SimC revision 변경만으로 폐기하지 않는다. DPS 캐시는 정확한 SimC 바이너리·프로필·장비/옵션·후보·기름·전투 조건·iterations identity로 분리한다.
- 기존 최고 후보/완성 프로필을 새 사용자 제로베이스 실행의 숨은 입력으로 주입하지 않는다. 알고리즘 연구를 P1 제품 연결보다 우선하지 않는다.
- 신규 실제 증거는 코드/설치/실행 조건을 재현할 수 있는 범위에서 보존. 개인 API 비밀키·토큰은 GitHub·영수증·채팅에 기록하지 않는다.

## 11. 최신 사용자 결정 — 78개 감사 증거와 최종 ZERO-SOURCE 인수 Gate (2026-11-13)

**판정 축 2개:** (1) 78개 요소별 `READY_SCOPED` 증거·적용 조건·선택 범위 정리 완료와 (2) 실제 현재 시즌의 **최종 엄격 ZERO-SOURCE→USER-E2E PASS**는 별도 Gate다. 전자가 끝났다고 후자가 PASS가 되는 것은 아니다. **최종 제품 완료 선언에는 두 조건을 모두 요구**한다. 78개를 전체 시즌의 모든 미선택 아이템·모듈 인증으로 해석하지 않는다.

### 11.1 READY_SCOPED 결정의 재현 가능한 증거 의무

각 ID마다 아래를 기록하거나, 원본에 없는 필드/원본 바이트는 **NOT_OBSERVED**라고 명시한다.

1. **의도/계약:** ID, 정확한 기능, 소비 필드·고정 예산 소유권, BASE/USER/RUN/OPTION과 해당 적용·비적용 조건.
2. **출처/정체성:** 최초 구현·변경 커밋, 실제 테스트 HEAD, 시즌/게임빌드/지역, SimC revision·바이너리 SHA, 전문화/ilvl/보석·영약·기름 등 세션 조건, 원본 단계/아이템/설치 매니페스트 SHA. 중요한 증거를 여러 서로 다른 실행에서 혼합하지 않는다.
3. **절차:** 어떤 입력→어떤 **기존** 수집/컴파일/검증/설치 코드 경로→어떤 명령·Actions job→어떤 출력에 도달했는지; 재사용한 기록과 이 차례에 새로 실행한 작업을 분리.
4. **관측/판정:** 기대값·실제값, v217 봉인/원본 SHA 검증, G/J/F/O/B/T·L/E/O 중복/JSON2 정합, PASS/FAIL/차단 코드를 **실제 확인한 수준만** 표시. 로그 문구·축약 compact·파일 존재를 원본 단계 전체 인증이나 재실행으로 과장하지 않는다.
5. **한계/재검증 트리거:** 미관측 항목, 역사 자료의 조건 범위, 바뀐 시즌/빌드/기름/소켓/장비/바이너리/프로필, 후속 연결을 깨는 코드 변경, 최초 확인할 증거 필드, 연관 다른 ID.

**증거 체인:** `요청 입력·게임빌드·소스/바이너리 ID → 원본 stage 영수증(있는 범위) → source_compilation/status/missing → G/J/F/O owner → v222 B/T → v212 설치 manifest → v098 프로필 → Native JSON2/DPS·SEM·95% → 웹 결과`. 각 결과는 78개 원장의 해당 ID에서 정본 코드/노트/영수증 링크로 역추적 가능해야 한다. 소스별 영수증이 빠졌으면 지금 확보된 성공 범위만 인정하고 누락을 감춘 채 강화된 READY를 선언하지 않는다.

**역사 성공의 판정:** 과거 동일 조건이 실제로 성공했다면 `READY_SCOPED — HISTORICAL_<조건>`으로 보존할 수 있으나 **현 HEAD 범용 준비 완료 수에 자동 합산하지 않는다**. 원장은 **78개 요소의 존재/처리 상태**, **과거 범위한정 증거**, **현재 제품 해당 범위 READY**, **최종 인수 Gate**를 네 층으로 표현한다.

### 11.2 최종 ZERO-SOURCE 시험의 인수 조건

**실행 시점:** 78개 각각에 대해 현재 지원·적용 범위의 필요한 작업과 증거 검토를 마친 다음 통합 최종 인수 시험을 시행한다. 각 ID는 `READY_SCOPED` 또는 **정당화된** `NOT_APPLICABLE_SCOPE`여야 하고, 현재 선택된 기본/개인/RUN 경로에 `BLOCKED_EXACT`나 필수 `PENDING_SCOPE`가 있으면 통합 준비 완료가 아니다. 78개 순차 작업 중에도 최소 국소/경계 테스트를 수행하여 마지막에 첫 오류를 발견하는 일을 줄인다.

**빈 출발 환경:** 아직 존재하지 않는 미래 시즌으로 이동하는 대신 **실제 시험 시점의 현재 시즌**으로 시작한다. 깨끗한 작업 root에 이전 시즌 DB·봉인 source stage·완성 source catalog/매니페스트·G/J/F/O 정답·이전 개인 프로필·DPS 캐시/최고 CHMV를 주입하지 않는다. 사용자가 승인한 외부 원본 API/DB2, pinned SimC 소스/빌드 및 합법적 인증 키·실행 바이너리는 **수집 수단/런타임 의존성**으로 허용하되, 사전 완성 정답을 몰래 넣지 않는다. 외부 접근·승인 자격증명·현재 빌드가 없으면 `BLOCKED_EXTERNAL_EXACT`로 기록하고 PASS를 만들지 않는다. 패키지에 동시즌 사전 검증 소스가 들어 있다면 이 시험을 **ZERO-INSTALL**로만 보고하고 ZERO-SOURCE로 오표기하지 않는다.

**실제 정상 경로:** (a) 현재 빌드·시즌·필수 사용 소스 식별 → (b) 5티어 ID/대표 무기·방어구 및 시즌별 G/J/F/O 원본 취득 → (c) 소스 단계·예산 B/T·고정 L/E/O 정합/Policy A 확인 → (d) v212 기본 설치와 선택 USER 변형 manifest·프로필 정확 일치 → (e) SimC Native JSON2 정적 rating → (f) v290/v291/v293 DPS/SEM·관측 1순위·명목95%/대안·결과 → (g) 취소·재개·캐시 동일성/중복 실행 회피. **제품과 동일한 사용자 입력→실제 수집→설치→실행 경로**를 시험한다; 별도 모의 검증기를 성공 경로로 바꾸지 않는다. 원본 수집 및 Native 비용 때문에 모든 아이템 조합/26전문화 전수는 요구하지 않되, 명시한 기본·개인 시나리오 및 대표적인 변화·실패 경계를 인수 조건으로 정의한다.

**음성/복구:** 필수 원본 결손·SHA 변조·다른 빌드·미검증 개인 F/O·다른 소켓/장신구 설치 SHA·캐시 identity 충돌에 대해 정확한 단계에서 fail closed, 이후 올바른 원본 복구 시 계속/재사용 가능한지 확인. 검증 실패를 과거 시즌 숫자·미관측0·수동 UI 검색으로 덮지 않는다.

**실패해도 원인 신속 발견:** 한 실행에 `scenario/build/source-manifest/SHA + stage status/missing + original GJFO source owners + v222 B/T + v212 install SHA + profile SHA + Native JSON2/worker receipt + step elapsed/Native/HTTP/cache counters`를 보존한다. 실패하면 **마지막 성공 경계 → 최초 불일치 경계 → 관련 78개 ID → 기존 성공 artifact/커밋/입력 identity 차이** 순으로 비교한다. 본인이 볼 수 없는 실제 로그·외부 실패 원인을 추측해 결함으로 분류하지 않는다.

**최종 판정:** 78개 항목별 현재 ZERO-SOURCE 범용 엔진 검증 `ENGINE_AUTODISCOVERY_PASS`(해당하는 요소만)와 `TRACKER_78_APPLICABLE_SCOPES_RECONCILED` 및 전체 `CURRENT_SEASON_ZERO_SOURCE_USER_E2E_PASS`를 **구별**해 보고한다. 둘 중 하나라도 미달하면 `PRODUCT_FINAL_ACCEPTANCE_PENDING`. 실제 미래 시즌 공개 시에는 같은 엔진으로 새 원본을 다시 검증하여 그 시즌의 READY를 별도 생성한다. 이 절은 새로운 79번째 기능 항목/78개 독립 Native Gate가 아니다.

## 12. 최신 사용자 확정 — 미래 시즌 대응 기능의 합격 판정은 **현재 ZERO-SOURCE**로 종료 가능

[정식 판정·인계 정책](POLICY_ZERO_SOURCE_AUTODISCOVERY_GENERALIZATION_20261113.md)의 전체 조건을 필수 적용한다. **미래 시즌의 실제 아이템/수치가 아직 존재하지 않는 것**과 **그런 시즌을 자동으로 찾는 범용 코드 기능의 검증**을 혼동하지 않는다. 정상적인 연결 출처 접근·API 키/권한이 제공된 제로베이스 환경에서, 현재 시즌/확장팩 이름·ID/레퍼런스 예산·기존 캐시·GPT 판단을 주입하지 않은 실제 제품 경로가 현재 확장팩·시즌 및 필요한 출처/자료를 정확히 자동 식별·봉인했다면, 해당 기능의 `ENGINE_AUTODISCOVERY_PASS`를 **현재 검증 완료**로 인정한다. 본 정책은 이미 A1이 성공했다는 선언이 아니며, 개별 시즌 환경 READY·사용자 E2E·제품 최종 인수는 각각 별도의 실제 수락 조건을 가진다.

식별은 **현재/활성 선언, 구조상 시즌·확장팩 ID, 적용 시점/버전/업데이트 날짜, 실제 콘텐츠 조인·동일 빌드/원본 SHA** 등 출처의 의미를 이용한다. **시즌 이름/ID/레이드명 하드코딩, 과거 시즌 예산 복사, GPT 검색 결과를 runtime 증거로 쓰는 방식**은 PASS 불가. 여러 후보/조건 충돌 시 관련 범위를 fail closed한다. 다른 시즌 이름/ID·날짜·공급자 누락 등의 합성 회귀로 우연히 현재만 맞힌 구현을 탐지하되 합성 테스트만으로 실제 ZERO-SOURCE PASS를 대체하지 않는다.

모든 A~H 78개 요소에서 이 원칙을 적용하고 각 성공의 실제 필드·출처/HTTP/DB2·시즌 빌드/옵션·SHA·실행 HEAD·재현 명령·PASS 범위·남은 의존성을 원장에 기록한다. 현재 역사 `3/78 READY_SCOPED`는 해당 70783 한 조건의 성공 기록으로 보존하며, **새 판정 기준을 적었다는 사실로 현재 범용 PASS를 올리지 않는다**. 78개가 정리되면 여전히 엄격한 최종 현재 시즌 ZERO-SOURCE→USER-E2E 통합 PASS를 요구한다.
