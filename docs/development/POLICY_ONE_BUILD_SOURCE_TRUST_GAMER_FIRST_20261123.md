# SIMC SECONDARY OPTIMIZER — 제로베이스 1회 구축·원본 신뢰·게이머 중심 UX

2026-11-23 최신 사용자 직접 결정. 기존 2026-11-14 제품 우선 최소 검증 정책과 11-15 실제 소비 감사 및 승인 v1.4 계열의 비충돌 부분은 유지한다. 문서 자체는 실제 기능 완료/Project UI 적용의 증거가 아니다.

## 1. 수락 단위는 '새 시즌 한 번 준비해서 사용할 수 있느냐'

사용자는 목표 ilvl(기본 334) 또는 수동 최종 T·26개 DPS 전문화·특성·장신구·선택 장비/보석·소모품/기름·전투 조건을 입력한다. 프로그램은 현재 시즌 대표 일반 장비/무기/티어4pc와 G/J/F/O·B/T 및 정적 L/E/O를 구성하고 기존 SimC 적응형 엔진으로 최적 절대 CHMV rating, 관측 DPS/SEM/95%/대안을 제공한다. 현재 착용 장비 재분배/장비 추천/시즌 전체 일반 장비 DB/효과 재구현은 범위 밖.

**환경 구축 엔진에서 비롯된 오류는 특정 설치본/품목의 임시 패치가 아니라, 다음 새 시즌에도 제로베이스 구축 한 번으로 해결되는 엔진 기능으로만 수정한다.** 한 번은 사용자 작업 단위이며 내부 단계는 캐시/봉인/재사용을 포함할 수 있다. 사용자가 음식·물약·영약·마부마다 별도 검증을 반복하는 것은 불합격.

동일 빌드에 이미 확보한 봉인 원본·측정 캐시는 재사용한다. 새 시즌은 해당 시즌 G까지 포함한 G/J/F/O를 다시 결정하며 자동 T=B+O, B=G+J+F, 수동 T 우선·B=T-O를 보존한다. 필수 G/J/F/O·대표 장비/티어가 미확정이면 환경 구축 완료로 표시하지 않는다. 선택형 미확정은 해당 항목만 이용 불가로 하되 BASE 실행은 보호한다.

## 2. 권위: Wago DB2와 SimulationCraft

- Wago DB2: 해당 시즌·빌드의 아이템 물리 ID, 분류, 장착 조건/품질/원본 정적 속성의 데이터 권위. 최초 수집의 빌드·ID·영수증/캐시 정체성을 기록한다.
- SimulationCraft: 같은 대상의 입력 문법, 아이템/소모품 효과, proc, APL 및 실제 DPS의 권위. 원래 SimC 입력과 오류를 이용한다. 자체 SpellEffect 연쇄/발동 구현, 모든 아이템에 대한 별도 효과 인증 Native Gate는 만들지 않는다.
- 앱은 두 원본의 대상 빌드·아이템 ID·적용 조건·사용 토큰을 서로 연결하고, G/J/F/O/L/E의 소유권·중복 방지, 생성된 실제 SimC 실행 프로필 및 캐시/세션 입력 정합만 책임진다. 동일 원본에 대한 의미 검증을 별도 Gate로 중복 수행하지 않는다. 원본 무결성 SHA 검사는 유지하되 같은 바이트를 불필요하게 다시 읽는 비용도 확인한다.
- 동일 효과+사용 조건이 원본에서 확인되고 높은 품질이 전 항목에서 열등하지 않은 경우에만 최고 품질을 노출한다. 이름/등급/아이템레벨만으로 동일 효과 추측 금지. 서로 다른 스탯/효과/조건은 별도 항목으로 보존한다. SimC가 인식하지 못하는 실제 입력은 해당 선택만 차단하되 자동 재인증 과제로 확대하지 않는다.

## 3. 실제 현재 구조적 원인 및 개편 목표

실제 코드 확인: v216은 v189/v190의 Wago/SimC 음식·물약 원본을 이미 수집·봉인한다. v484는 v190/v217/v230의 정확한 ID/품질 후보를 연결하지만 source-only로 종결한다. v218.current_season_approved_optional_choices는 현재 시즌 구축 결과를 소비하지 않고 상수 source_default만 반환한다. v113.options는 그 상수를 사용자 목록으로 전달하고 결국 v218→SimC disabled가 된다. v679은 UI에서 실 미사용을 표시했지만 엔진 근본 해결은 아님.

**설계 목표**: 기존 v216 제로베이스 원본 획득 → Wago 아이템 ID/품질/조건 + SimC 지원 입력의 동일 빌드 결합 → 기존 v212 계열 설치 환경에 사용자 선택 목록과 미지원 항목 사유를 함께 저장 → v113 웹 선택지와 v218의 실제 프로필 검증, v098 실행 프로필, 캐시 identity가 **동일한 설치 레지스트리**를 소비한다. 별도 영구 서비스/기존 엔진 복제/효과 인증 Gate/시즌 전체 장비 DB 없이 구현한다.

검증 단위는 빈 환경→시즌 1회 준비→예산/대표 프로필/기본 소모품 선택지→UI→실제 SimC 입력(소스/정적 회귀) 연결. 기본 필수와 선택형 상태 분리, 수동 T 우선 및 최고 품질 원칙을 함께 검사. 새로운 Native/HTTP/DB2가 필요한 경우 기존 원본 재사용 가능 여부를 확인한 뒤 최소 범위만 실행한다. 기존 역사 Native 영수증은 새 테스트로 재실행한 것처럼 주장하지 않는다.

## 4. 게이머용 자연어와 사용자가 직접 해결할 수 있는 일

일반 화면에는 G/J/F/O, B8, v212, native, SHA, receipt, source-only, Policy A, 정적 rating 정합, SimC disabled 등 개발자 용어를 노출하지 않는다. 필요 시 '고급 진단 정보' 아래에 보존한다. 대신 첫 문제 하나·계산 영향·실제 가능한 사용자 조치 하나를 명확하게 표시한다.

- 환경 준비 완료: "이번 시즌 장비·보석·영약 준비가 끝났습니다. 최적 스탯을 찾을 수 있습니다."
- 음식 데이터 없음: "이번 시즌 음식을 아직 가져오지 못했습니다. 음식 효과 없이 계산할 수 있습니다." 사용자가 실행 가능한 '시즌 데이터 다시 확인' 기능이 있을 때만 해당 버튼 제공.
- SimC 미지원(실제 오류 시): "현재 SimulationCraft에서 이 아이템을 사용할 수 없습니다. SimulationCraft를 업데이트하거나 다른 아이템을 선택해 주세요."
- 기름 적용 불가: "이 무기에 사용할 기름 정보를 찾지 못했습니다. 다른 기름을 선택하거나 '사용 안 함'으로 바꿀 수 있습니다."
- 장신구/아이템 목록 누락: 지원되는 ID 직접 입력 기능이 실제로 구현된 경우에만 "아이템 번호 직접 입력" 안내.
- 필수 기본 소스 없음: "이번 시즌 장비·보석·영약 준비가 끝나지 않아 계산할 수 없습니다." + 실제 가능한 인터넷/시즌 데이터 갱신 동작.

자동 복구가 가능하면 앱이 처리한다. 사용자에게 요청하는 것은 접속 확인, SimC 업데이트, 앱이 실제 지원하는 아이템 번호/빌드/원본 파일 직접 입력 등 쉽게 해결할 수 있는 부분만. 원본 SHA/filler/Native 프로필·내부 영수증을 일반 사용자가 준비하게 만들지 않는다.

상태는 '준비 완료/일부 선택만 이용 불가/계산 불가'로 나누되, 예외 항목 하나 때문에 BASE 실행을 막지 않는다. 버튼은 실제 존재하는 행동만 제안한다. 이전 사용자가 불가능하다고 밝힌 PC 실측은 여전히 보류한다.

## 5. 구현 우선순위와 보고 경계

최우선은 v216/v217/v189/v190/v230/v484에서 v212 설치 옵션 목록을 생성하고 v113/v218/v098에서 그 목록을 바로 소비하도록 연결하는 것. 다음으로 한 번의 제로베이스 환경 구축 계약과 실제 유저 입력→프로필/캐시 결합 시험. 실패 시 정확한 첫 원인과 수동 회복 경로를 확정하고 자연어 UI 적용. 음식·물약 두 품목만 별도로 하드코딩하거나 v679의 UI-only 수정만 반복하지 않는다.

신규 코드 PASS, 오프라인 회귀, 재사용 역사 Native, 새 실 Native, PC E2E 미확인을 분리 보고한다. 공식 full_product_e2e=PENDING과 78 계약은 임의 승격 금지. 격리 브랜치에서만 작업하고 main/v003/v016/Project UI/Work OS/주 제품 개발 채팅 권한은 변경하지 않는다.
