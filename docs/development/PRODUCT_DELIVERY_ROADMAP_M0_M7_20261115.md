## 0. 공통 목표, 실행 대상, 증거 구분

**제품:** 26개 DPS 전문화(증강 기원사·탱커·힐러 제외). 사용자 목표 ilvl(기본 334) 또는 수동 최종 CHMV 총량 `T`를 기준으로 치명·가속·특화·유연의 **최적 관측 절대 rating**을 기존 SimC DPS로 탐색한다. 사용자는 일반 장비 전체를 고르지 않는다. 프로그램이 시즌 대표 일반 장비·무기·주능력치·티어4pc·SimC 프로필을 구성하고, 선택한 장신구2/특수·제작장비/장식 최대2/보석·영약·기름·음식·물약·영구 마부·전투 설정만 적용한다. 출력은 절대 rating·비율·DPS·SEM·95% 판정·관측 1순위·실질적으로 다른 근접 대안, 그리고 전역 최적성 미입증을 구분한다.

**예산:** `G` 대표 장비·무기, `J` 기본 보석, `F` 영약, `O` 선택 고정 무기 기름; `B=G+J+F`, `T=B+O`, `c_final=c_base+o`. 수동 최종 T가 우선하여 `B=T-O`로 환산. 선택 특수 고정 L은 G 안, E는 승인 회계에 한 번, O는 gear_*에 한 번, 장신구 정적 스탯은 자유 G 밖. 초기 제작 50:50을 L로 잠그지 않는다. 다른 시즌의 F/J/O·79×2 참조를 새 시즌 원본으로 복제하지 않는다.

**항상 구분할 증거:** (1) 구현한 코드/자동 오프라인 회귀, (2) **정확한 동일 시즌·조건**의 기존 원본/Native/Actions 재사용, (3) 이번 변경에서 새로 실행한 Native·실사용 E2E, (4) 정식 78 계약 및 전체 빈 환경 ZERO-SOURCE→USER-E2E 수락. 회귀 PASS를 신규 Native·26전문화 입증·완제품으로 과장하지 않는다.

**사용자 가치 평가(매 작업):** 사용자가 어떤 입력으로 현재 무엇을 못 하는가 → 실제 값 생성자·소비자/세션·캐시·UI → 기존 증거/원본 재사용 → 미선택 선택기능만 분리 → 중복 HTTP/DB2/Native/CPU/메모리/I/O 제거 → 변경한 경계만 최소 회귀 → 확인된 장애를 해결했으면 STOP. 순서는 **STOP → REUSE → CONNECT/FIX → 필요한 최소 EXTEND → 최후 NEW**.

## 2. 단계별 작업과 완료 판정

### M0 — 기존 원본·개발 계약·실증 인벤토리 (운영 기준)

- **REUSE:** 원본 `v016_SCENARIO_CONTRACT`는 사용자 보고 최신 원본 기준선이나 직접 원본 바이트·통합 확인 전 공식 합본이라 하지 않는다. 격리 코드 `v216/v217/v212`, `v222`, `v098/v096/v094`, `v106/v290/v291/v292/v293/v113`, 실제 Native·Actions와 소스 봉인 영수증을 근거 범위별 재사용.
- **이전 개선 보존:** v441의 78개 수락조건 감사(54 완화/24 유지) 및 11월 15일 제품 소비 감사. 별도의 역사 감사나 78개 실행 티켓 신규 생성 금지.
- **완료 조건:** 해당 기능의 owner/원본·실제 소비 경계와 완료·합성·부분 Native·미구현이 명확. HISTORY/PASS와 current/실사용을 혼동하지 않음.
- **STOP:** 새 증거가 기존 제품 판정을 바꾸지 않는다면 더 이상 과거 실험을 반복하지 않음.

### M1 — 시즌 Environment Build (기본 필수)

- **필요 기능:** 현재 확장팩·시즌/게임빌드 감지, 실제 필요한 Blizzard/WCL/DB2/SimC 출처와 소스 범위 결합, 시즌 대표 일반 장비·무기·4pc ID, 원본 봉인과 동일 시즌 캐시 재사용.
- **기존 경로:** `v155/v161/v163/v165~v167`, `v191/v211/v213`, `v216/v217`, 설치 `v212`. 한 번의 정상 Build에서 생성; SimC-only 별도 제품 엔진 금지.
- **검증:** 필요한 동일 시즌·빌드 원본 ID/해시, 변경 시즌·빌드의 무효화 경계, 이미 확보한 v343 70783 같은 실제 Windows 결과; 신규 시즌 값은 새로 검증.
- **완료 조건:** 필수 원본이 정확하면 다음 예산 계산으로, 없으면 실제 원본 오류·PENDING. 옛 시즌 값/캐시를 대신하지 않음.
- **STOP:** 전체 시즌 아이템DB, WSE 효과 의미 추측, 모든 SpellEffect/모든 26스펙 Native 수집 금지.

### M2 — 대표 G/J/F/O + B/T + 최종 프로필 (기본 필수)

- **필요 기능:** 목표 ilvl 대표 `G`(같은 시즌 참조 또는 선택 exact Native), 최고 품질 기본 J/F, 선택 O의 물리 ItemID·무기손·고정 스탯, `B/T` 재계산, 수동 `T` 권한, L/E/O 중복방지·스탯별 하한, 대표 주능력치/무기·4pc·SimC 정적 rating 비교.
- **기존 경로:** `v222`, `v432` 선택 수정, `v098/v096`, `v046` static 캐시, `v281/v278` 필수 F/O 범위. `v222.retarget_verified_install`의 `B=T-O` 구현 재사용. exact G는 기본 전수 선행 Gate가 아님.
- **검증:** 자동 T와 사용자 수동 최종 T, O0/O>0, 4기본 보석, 서로 다른 F/J 설치본, 동일 시즌 캐시의 올바른 분리. 저장된 v343/v439 실증은 동등 범위에서 재사용.
- **완료 조건:** 사용자 계획에서 `G/J/F/O/B/T`와 최종 `gear_*`가 같은 권한 있는 설치본을 나타내며 실제 SimC JSON2와 일치. 미관측 고정치=0 추정 금지.
- **STOP:** 79×2 테이블을 모든 시즌·전 전문화의 정확 Native G로 과장하거나, SEM 미세화/새 예산 엔진 개발 금지.

### M3 — 기본 사용자 USER→SimC→결과 (우선순위 1)

- **기본 시나리오:** 26 DPS 중 사용자 직업/전문화·종족·특성 선택, 목표 ilvl 기본334 또는 수동 최종T, **장신구2**, 대표 일반 장비/4pc, 검증된 기본 소켓·보석 J, 기본 최고 품질 영약 F, 기름 O 또는 선택 없음(검증된 조건), 전투 설정.
- **실제 소비 체인:** `v113`의 plan/start/longrun/restore → 정확한 `v216/v217/v212` 설치 SHA·F/J/O 선택 → `v222`·`v218/v098` 프로필 → `v096` 실행 원본 검증 → 기존 `v094/v290/v291` SimC 및 `v292/v293/v106` 결과/캐시/중단·재개.
- **검사 항목:** exact build + ilvl + installed SHA + F/J/O/소켓 + 사용자가 정한 T와 프로필·캐시 identity; 잘못된 옛 세션/카탈로그 fallback, 요청/서버·UI 불일치, session 중복 생성, 동일 캐시 우회, 완료 결과 재Native 발생 여부.
- **완료 조건:** 실제 사용자 단일 기본 시나리오의 선택→프로필→실 SimC DPS·SEM·95%→결과/재조회/캐시·취소·재개까지 일관되고 기존 코드/영수증과 합치. 모든 변형·전문화 독립 Native 전수 실행은 조건이 아님.
- **첫 작업:** 이미 실증된 정상 M3 경로에 재현 가능한 사용자 장애가 있는지 검색. 없으면 **REUSE/STOP**하고 신규 옵션보다 기본 M1/M2 필수 미완성으로 전환. 추가 64 Native가 실제로 필요한 신규 경계만 계수 제한 후 실행.

### M4 — 선택형 소모품·장비·마부·시즌 모듈 (증거 있을 때만)

- **군집:** 소켓/특수보석, 영약 변형, 실제 무기 기름/O, 음식·물약·증강룬, 영구 마부·정적 E, 정확한 장신구2·특수장비/제작장비 L·장식 최대2, 확장팩 특수 ON/OFF 모듈. 일반 임시 마부는 지원하지 않음.
- **경로:** 기존 봉인된 실제 선택 물리 ID·빌드·슬롯/손·use scope·효과 품질·SimC 입력 후보 → 동일 효과/조건에서 최고품질 확인 → 기존 `v220` 네 내부 증거 family → `v196/v212` 버전화 원본 설치 → `v218/v098/v096` 사용자 세션·프로필·예산·캐시 소비 → UI. 등록 후 개별 수동 승인 불필요.
- **현재 경계:** `v484/v485` 음식/물약 DB2↔SimC generated ItemID는 **source-only 미승인**. `v281` F/O 봉인 코드·SHA를 임의 수정하지 않음. 기본 v113/v218에서는 미검증 소모품 토큰을 source_default/disabled 외 선택할 수 없음. 원본 item ID/품질/적용/CHMV 미관측이면 신규 선택지 0종 유지.
- **완료 조건:** **실제로 선택한** 각 등록 옵션의 Native 입력과 고정 예산·적용 범위를 검증·연결한 뒤 원본과 사용자 표시/실행이 정확히 같음. 미확정인 항목만 개별 잠금, 기존 BASE 실행에는 영향 없음.
- **STOP:** 원본 전체 품목/effect chain 독립 재구현, 미사용 추가 소켓·시즌 기능을 제품 READY 선행 Gate로 만들기 금지.

### M5 — 26 DPS 범용성 및 통계/탐색 품질

- **범위:** 지원 정확히 26 DPS의 직업/전문화/종족/특성·무기 형태(예: Titan's Grip)·주능력치·티어·APL/SimC 입력·CHMV 절대 rating. SimC가 APL/발동/effect/DPS를 책임진다.
- **재사용:** 기존 냉기 마법사 수동 T, 풍운/조화 자동 T, 생존 v343/v417/v439/v440 등의 실제 Native·95% 판정. 26개 전체 Native 일괄 실행 없이 **실제 서로 다른 무기/프로필 형태·현재 미검증 소비 경계**만 선택.
- **완료 조건:** 모든 지원 전문화 경로에서 프로필 생성·정적 rating·실행 옵션·결과 contract가 유효; 실제 SimC 경계에는 필요한 대표 Native와 음성/회귀 증거. 관측 1순위·95% 우위와 전역 최적성 구별.
- **STOP:** 새 탐색 엔진, 별도 효과 인증, 최적해의 수학적 전역증명, 불필요한 SEM 미세연구 중단.

### M6 — UI/배포/복구 (M3~M5와 병행)

- **필요 기능:** Windows/브라우저 사용자의 시즌 갱신·초기 Build·지원 선택지·프로필 업로드(현재 장비 복사 금지)·장신구/보석/마부/기름·진행상황·실행/취소/재개·캐시·결과·오류원문·한국어 공식 용어·SimC 바이너리 업데이트.
- **검사:** UI/API에서 **동일** exact installed SHA/build/ilvl/F/J/O 및 승인된 optional 토큰만 사용; 세션 복원은 과거 값 조회와 현재 RUN 승인을 분리; 구 파일·기존 캐시 호환. 기존 v477/v478 UI/서버 guard는 정상 사용자 차단 반례 발견 전 KEEP.
- **완료 조건:** 일반 사용자가 Windows에서 일관된 선택/환경 구축/실제 SimC/복구 결과에 도달하고 잘못된 입력의 설명이 정확함. 필요할 때만 실 GUI 통합 확인; 별도 앱/플랫폼 엔진 신규 개발 금지.

### M7 — 최종 ZERO-SOURCE→USER-E2E / 출시 판정

- **실행 환경:** 신규 시즌처럼 기존 DB·시즌 seed·참조값·과거 영수증·static/DPS 캐시·사용자 세션을 시험 입력에서 격리하고 **정상 단일 v216 Environment Build**를 사용한다. Wago/Blizzard/WCL/공식 공개 SimC 등 정상 실시간 신규 원본 수집 허용. 전용 SimC-only 제품 엔진/특례 로직 금지.
- **검증:** 원본 출처/시즌/빌드·대표 장비/티어/G/J/F/O→B/T→설치/선택→실 사용자 프로필→적응형 실제 SimC→JSON2/95%/결과/캐시/취소·재개. 먼저 원본 바이트·실행 영수증 봉인, 그 후 과거 결과와 독립 대조.
- **완료 조건:** 공식 78 JSON 각 요소의 `generic/current_source/product_integration` 세 축이 유효 PASS 또는 증빙된 N/A, 별도 `full_product_e2e` 실제 PASS. 과거/native/합성만으로 정식 완료 승인 금지.
- **권한:** main 병합, v003 immutable, 원본 v016 통합/바이트, Project Sources/Instructions 실제 적용, Work OS M0·Shared State, 공식 제품 승격은 사용자 별도 지시 없이는 실행하지 않음.

## 3. 진행 운영: 고정 순서가 아닌 사용자 가치 우선

1. **매 작업 시작:** 실제 HEAD + CURRENT/78 + 관련 producer→consumer + 실증/호출자 확인. 진행 목표를 *사용자가 무엇을 할 수 있게 되는가?* 한 문장으로 기술.
2. **한 번에 하나의 가장 작은 결함:** 먼저 M1~M3 BASE 경로. 실제 결함이 없으면 해당 범위 STOP·REUSE. M4는 정확한 소비 항목/증거가 있는 경우에만. M5/M6는 실제 사용자 피해를 일으키는 회귀를 병행 수리.
3. **작업 전 비용 예상:** 신규 Native 호출·DB2/HTTP 수집 수, 전체 I/O/캐시 재사용, 가중 파일 파싱, 메모리/CPU, 테스트 범위. 승인 없이 Native 전수·전체 원본 재수집 금지.
4. **작업 후 검증:** 수정 코드와 직접 연결된 오프라인 회귀→기존 유효 시즌 Native/Actions 재사용→실제로 새로운 Native 경계가 필요한 때만 타깃 실증. 실패 로그 원문·원인·수정 재검증 이력 보존.
5. **보고 형식:** `마일스톤/사용자 기능 변화`, `코드 파일·커밋`, `신규 합성 PASS`, `기존 실제 Native 재사용`, `신규 실제 Native`, `HTTP/DB2·캐시·세션 비용`, `선택 보류 vs BASE 차단`, `78 정식 상태`, `다음 실제 장애 1개`를 간결히 기록. 현재 최신 상태 포인터는 [CURRENT](../CURRENT_PRODUCT_DEVELOPMENT_STATE.md) 한 곳에서 관리한다.
6. **우선순위 변경:** 신규 실제 사용자 장애, 시즌 변경, 보안·프로필·예산 오류가 확인되면 재정렬. 로드맵을 재작성하거나 과거 기능을 다시 만드는 근거가 아니며 변경 이유만 CURRENT에 기록한다.
