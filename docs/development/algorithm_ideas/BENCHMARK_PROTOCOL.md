# 알고리즘 통합 비교 계획 — 아직 실행하지 않은 평가 계약

**적용 범위:** 기존 기본 v290, 기존 opt-in v312, IDEA-001·002·003·004·005·006·007 및 앞으로 별도 파일로 추가되는 후보. 아이디어는 구현·실측 결과가 나올 때까지 벤치마크 점수를 비워 둔다.

| 평가 차원 | 모든 정책에 요구할 동일 조건 | 증거 |
|---|---|---|
| 신규 프로필 | user-control → 검증된 시즌 장비/환경 → 새 SimC source 생성; 각 케이스 ID/SHA 고정 | 원본 source SHA, 게임빌드/바이너리/전투 설정 |
| 다양성 | 8개 DPS 전문화 × 각기 다른 2개 수동 최종 T/상한 = 16개 | 케이스당 원본 프로필·고정 L/O/E |
| 공정 계산 | Native 호출 수, 실제 누적 SimC iterations, precision 재확인 수, 오차 목표 기록 | 원본 input.simc+JSON2+receipt, 로그·SHA |
| 공정 시간 | 탐색 전체 5분/10분 각 cut-off에 대한 확인 DPS/SEM; 준비 시간은 분리 | 시점별 elapsed와 정밀 확인 journal |

**필수 오해 방지:** 원형 v290의 1008회는 실제 약 7만 iterations, v312의 1008회는 39,840으로 달랐던 실험이 있다. 호출 수가 같은 표를 공정한 **총 계산량 동일** 비교로 표시하지 않는다. 95%는 명목 비교와 다중선택/가족단위 보정 여부를 분리한다. 전역 최적 입증은 하지 않는다. 전문화 간 DPS 원값 평균을 내지 않는다.

**통합 표를 채울 때:** 실행 정책 ID | 시나리오 ID | 새 source SHA | binary/build | wall 5/10분 최고 정밀 DPS/SEM | Native/scout/precision/iterations | nominal 95 | 상대 DPS 개선% | 상태(PASS/BLOCKED/PARTIAL) | 원본 Native 증거 링크. 완료 전 행은 `NOT_RUN`.

**현재 상태:** 프로토콜 문서만 작성됨. IDEA-001/002/003/004/005/006/007 비교 실행 **0회**, 16개 신규 전문화 실측은 사용자 요청 v314 단계에서 별도 실행 대기 중. v290 기본값과 v313/v314 Actions 일정 변경 없음.

## 개발·합성 비교의 단계적 검증 규약 (2026-11-11)

- **첫째, 개선 아이디어 심사:** `README.md`의 이유·장점·단점·중복·통합/기각 기준을 통과한 후보만 실험 비용을 배정한다. 같은 v303/v312 기능을 복제한 독립 엔진을 동시에 개발하지 않는다.
- **둘째, 단독 부품 제거 시험(ablation):** 동일 신규 프로필과 동일 탐색 정책에서 **반경만**(IDEA-002), **전역 reserve만**(IDEA-003), **승급 일정만**(IDEA-001), **획득함수만**(IDEA-004) 바꾼다. 각 부분 변경 효과가 없다면 섞지 않는다.
- **셋째, 결합 이득 시험:** 유효했던 변경만 합쳐 `A+B` 와 `A`, `B` 및 기존 v290을 **동일 시간/iterations/Native source**에서 비교한다. 결합 정책의 기록에는 중복 Native 호출·cache 키·planner CPU/메모리·case 생성 I/O·동적 예산 충돌을 남긴다.
- **넷째, 일반화 검증:** 8개 DPS 전문화 × 2개 총량/상한·초기 순서를 바꾼 홀드아웃 시나리오에 대해 전문화 내 DPS 개선율과 각 5/10분 실측 확인 후보를 평가한다. 기존에 실험한 시나리오에서 규칙을 튜닝한 뒤 같은 결과를 독립 검증으로 다시 계산하지 않는다.
- **성과 미달의 처리:** 개선폭이 명목 95% 내라면 우위 미확정으로 유지한다. 테스트를 실패하거나 실측 원본이 부족한 조건은 집계에서 숨기지 않는다. '아이디어를 많이 등록했다'는 자체 성공 지표로 사용하지 않는다.

## 누락분 보완 3개 신규 아이디어의 실험 분리 (2026-11-11)

| 아이디어 | 어떤 한 가지만 달라지는가 | 먼저 필요한 실증 | 기존과 합치는 순서 |

| IDEA-005 짝비교 | 최종 후보 A/B에 실제로 양의 seed-block 공분산이 존재하는지 | SimC 재현성·쓰레드·seed별 차이 분포; 독립 비교보다 관측 오차 반폭/시간이 개선돼야 함 | IDEA-001의 유망 최종 후보 확인에만 제한적으로 |

**별도의 측정 인프라 비용:** IDEA-005는 seed 블록별 실제 A/B 실측이 필요하므로 실증 전 제품에 넣지 않는다. IDEA-006은 기존 원본 9906개의 지역 holdout **오프라인 적합 검토**를 먼저 하되 이를 신규 전문화 실측이나 최적화 PASS로 표시하지 않는다. IDEA-007은 기존 v291의 정책별 완전 고정 실행 순서·audit를 수정해야 하므로 독립 비교 시험을 대체하지 않는다.

**중복 측정 방지:** IDEA-001~007의 모든 반복 Native가 끝난 것처럼 한꺼번에 '동일 캐시 공유 실험'하지 않는다. 실제 새로운 source SHA, SimC binary/build, (candidate, iterations, seed·thread mode), 환경/전투 설정이 다르면 캐시 정체성이 달라질 수 있다. 실험 설계에서 각 arm은 독립 오리지널 SimC 비교군으로 관리한다.
