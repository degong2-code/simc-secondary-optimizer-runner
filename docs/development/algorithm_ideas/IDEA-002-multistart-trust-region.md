# IDEA-002 — 다중 시작점 신뢰영역 탐색 (Multi-start Trust Region)

- **제안:** 현재 대화, 2026-11-11. **상태:** `V328_V1_REAL_NATIVE_PILOT_HOLD` (원본 v329 267 Native, 우위 미입증). 기존 v303/v306 재사용, 제품 미승격. v303/v305의 기존 지역/반경 코드는 재사용 검토 대상이지 이 제안의 PASS가 아니다.
- **가설:** 서로 떨어진 여러 시작 영역을 유지하고, 실측 개선 방향에 따라 각 영역의 탐색 반경을 조절하면 단일 대리모델보다 전문화별 비선형 DPS 지형에 안정적으로 적응할 수 있다.
- **후보 절차:** 넓은 전역 표본으로 4–8개 분리된 지역 시작 → 지역별 치/가/특/유의 두 스탯 이동(총 B와 고정 하한 유지) → 실제 SimC 개선·SEM·정체 정도로 반경 확대/축소 → 일정 시간마다 무관측 영역에 새 시작점 배치.
- **지역 예산:** 개선 유망 지역에 추가 Native를 할당하되 전역 탐색의 일부 예비 예산을 유지; 단일 관측 최고 DPS에 예산을 몰아주지 않는다.
- **초기화:** 기존 캐릭터 최고점·완성형 프로필·Native 캐시로 seed하지 않음; 해당 시나리오에서 새로 만든 source만 사용.
- **구현 재사용:** v290 정수 rating·경계, v303-v306 후보/반경·탈출 모듈, v291 원본 SimC·SEM·cache/취소·재개; 메커니즘 재구현 없음.
- **평가:** 동일 시나리오와 시간/iterations 예산에서 v290·v312·IDEA-001/003과 각 시간 시점의 최고 확인 DPS, 지역별 발견 다양성, runtime overhead, 명목95 기준을 비교한다.
- **위험:** 고정된 4–8 지역이 실제로는 하나의 봉우리를 중복 탐색할 수 있음; 신뢰영역 반경이 너무 빨리 줄면 비국소 최고점을 놓침. 다중 시작점과 최소 전역 예비 예산은 분리 시험.
- **승격:** 여러 전문화/2가지 T·상한에서 우위 확인 전까지 기본 v290 교체·전역 최적 입증 주장 금지.

## 사전 타당성 심사 — 2026-11-11

- **떠올린 이유/실측 문제:** 기존 v305의 좁은 지역 확대만으로는 이전 v290이 발견한 더 멀리 떨어진 유망 좌표에 도달하지 못한 근거가 있었다. 또한 매번 같은 전문화에서 동일 봉우리를 발견하는 결과는 범용 탐색력을 증명하지 않는다.
- **기존 기능과 중복:** **매우 높음**. v303은 이미 `initialize_regions`, 지역별 반경·배분량·reserve, v306은 비국소 escape, v312는 서로 다른 지역 중심을 갖는다. '여러 영역 탐색' 자체를 독립 새 엔진이라고 부르면 중복 개발이다.
- **장점:** 지역마다 반경을 독립적으로 조절하므로 기울기가 급한 전문화와 완만한 전문화에서 같은 전역 반경을 강제하지 않는다. 재사용 가능한 pairwise 후보·v291 원본 Native 캐시/취소/재개 구조에 소규모 수정으로 시험 가능하다.
- **단점/실패 조건:** 35-iteration 측정 노이즈를 '개선 없음'으로 해석하면 반경을 잘못 줄일 수 있고, 여러 중심이 같은 고점을 중복 측정하면 탐사 예산을 낭비한다. 잘못된 지역 선정 시 넓은 단체의 고점은 여전히 놓친다.
- **효율적으로 작동할 합당한 이유:** 기존 v305의 좁은 지역 실패가 **탐색 반경 선택/탈출** 문제였으므로, 실제 개선과 SEM을 반영한 반경 조절·최소 지역 분리를 실험하면 해당 원인을 직접 검증한다. 단, 모든 전문화가 같은 다봉 지형이라는 주장은 하지 않는다.
- **통합 우선안:** **v303/v306 위에 반경 확대·축소 신뢰 판정만 붙이는 `ablation`**. IDEA-003의 층화 공간 커버리지는 중복 없이 '새 시작점 요청'에만 활용 가능. v312의 무조건 8/5/3 고정 배분을 바꾸는 실험은 별도 비교.
- **기각/보류 기준:** 단일 지역 집중/현 상태 v303-v306 대비 독립 시작점 수·고점 발견 속도·총 iterations와 planning CPU overhead가 개선되지 않거나, 동일 영역 중복 Native가 증가하면 채택하지 않는다.
- **심사 결론:** `REUSE_AND_ABLATE` / v303-v306의 기존 코드 재사용 우선. **새 구현·성능 우위는 아직 없음.**
