# IDEA-005 — 동일 시드 쌍별 실측의 *조건부* 분산 감소 (Paired-Seed / Common-Random-Numbers Probe)

- **제안일:** 2026-11-11 (이전 누락 제안 보완 1/3). **상태:** \`IDEA_ONLY · HOLD_FOR_FEASIBILITY\`. 기존 v291 Native 경로를 수정하거나 SimC를 실행하지 않았음.
- **분류:** 후보 좌표 생성기가 아닌 **후보 두 개 간 실제 SimC DPS 차이의 측정 방법**. 이론상 탐색에서 재측정 비용을 줄일 수 있으나 자동 도입 금지.
- **관측된 문제와 발상 이유:** v313 냉기 마법사·분노 전사 실측에서 v290과 v312의 정밀 확인 DPS 차이는 각 후보 SEM으로부터 산출한 명목 95% 반폭보다 작았다. 작은 차이를 식별하려면 여러 번 확인할 수 있지만 반복 SimC 비용이 커진다. v291은 \`simc_seed\`를 원본 JSON2에서 읽고, 서로 다른 seed인 두 결과를 독립 비교 형태로 표시하고 있다.
- **외부 확인 및 제한:** SimulationCraft [StatisticalBehaviour 문서](https://github.com/simulationcraft/simc/wiki/StatisticalBehaviour)는 \`seed\`가 있더라도 **장비·가속 변경으로 행동과 난수 소비 순서가 달라지므로 동일 시드가 유리한 짝비교를 보장하지 않는다고 명시**한다. [SimC Issue #9818](https://github.com/simulationcraft/simc/issues/9818)은 \`seed\`와 \`deterministic\`, 다중 스레드 재현성에 관한 실제 의문을 제기했다. **동일 seed로 실행했다는 사실만으로 공분산이 양수이거나 기존 95%가 개선됐다고 판단하면 안 된다.**
- **메커니즘:** 한 프로필에서 이미 고른 인접 두 후보 A/B를 같은 64~128회 이하의 seed-block 목록으로 **각각** 측정하되 순서·thread 수·소스·전투조건을 고정하고 각 블록별 *관측 평균 DPS 차이* \`d_b=DPS(B,b)-DPS(A,b)\`를 보존한다. 이후 블록 간 \`d_b\`의 실측 표본분산을 계산하고, 독립 결과의 \`Var(A)+Var(B)\`와 비교한다. \`Var(B-A)=Var(A)+Var(B)-2Cov(A,B)\`이므로 실제 양의 공분산이 충분히 관측될 때만 짝비교 이익 가능.
- **이론적 장점:** 작은 DPS 차이를 판정하는 후보에서 불필요한 반복을 줄일 가능성; 기존 v291의 진짜 seed/Native 영수증과 통합할 수 있고 새로운 DPS·발동 엔진 불필요.
- **단점·위험:** 실제 스킬·proc·가속 변화가 난수 소비 순서를 바꾸면 공분산이 0이나 음수일 수 있음; seed 고정/threads=1이 SimC 성능을 떨어뜨릴 수 있음; 후보당 블록 2개 실행 및 JSON I/O가 늘어 **실행시간이 더 길어질 수도** 있음. v291은 현재 블록 단위 짝비교용 개별 런/분산 로그가 없으므로 단순 플래그 전환으로 구현 불가. 변경한 실행 조건은 같은 이전 캐시로 재사용 금지.
- **기존 아이디어와의 관계:** v290의 \`_precision_action\` 및 IDEA-001의 여러 iterations 재확인과 **일부 중복**. 그러나 \`IDEA-001\`은 **어떤 후보에 몇 회 반복할지**, IDEA-005는 **동일 비용으로 두 후보의 차이 분산을 낮출 수 있는지** 검증한다. IDEA-004 KG의 학습 불확실성 가정과 다르다.
- **통합 판단:** \`HOLD\` → 독립 엔진 금지. 한 SimC 빌드·동일 전투조건·실제 차이 공분산이 검증될 경우에만 **v291의 최종 확인 A/B 측정 선택옵션**으로 시험. 모든 후보에 적용하지 않으며 표준 독립 SEM+95 경로는 유지한다.
- **반증 시험(실제 Native 실행 전 계약):** (1) 동일 입력·동일 seed·threads1의 재현성과 서로 다른 입력의 seed별 실제 pair-difference를 2개 다른 DPS 전문화에서 먼저 측정; (2) seed 블록을 최소 8개 이상 사용해 **공분산 및 pair-difference 신뢰구간을 원본 DPS 실측**으로 확보; (3) 동일 총 SimC iterations 및 wall 시간에 대해 독립 표본 대비 **관측되는 차이 CI 폭이 줄지 않으면 즉시 보류**; (4) 전투순서/스탯 차이에 따라 공분산 부호가 바뀌면 보편 기능으로 승격 금지. 숫자 64/128/8은 사전 실험 제안, 검증된 최적 설정 아님.
- **효율이 생길 *필요조건*:** seed를 맞추는 것 자체가 아니라 **실제 양의 짝공분산의 크기**가 추가 seed·1-thread·I/O 비용보다 충분히 커야 한다. 현 데이터에서는 이 조건이 증명되지 않았다.
- **증거/표기:** 아이디어 문서만 등록. Native 0회, 향상된 정밀도/95% 우위 0건 주장. 95% 표기만 사용하고 선택 편향·familywise 미보정 구분.
