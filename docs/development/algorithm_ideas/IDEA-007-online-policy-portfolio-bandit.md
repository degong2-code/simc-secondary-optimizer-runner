# IDEA-007 — 다중 후보 생성 정책의 온라인 포트폴리오 (Budgeted Strategy Portfolio / Bandit)

- **제안일:** 2026-11-11 (이전 누락 제안 보완 3/3). **상태:** \`IDEA_ONLY · INTEGRATE_WHEN_SINGLE_MODULES_WORK\`, 실행/Native 검증 0회.
- **분류:** 기존 v290·v303·v312 같은 **탐색 전략들 사이에 이번 신규 프로필의 남은 실제 SimC 예산을 어떻게 배분할지** 결정하는 상위 정책. 전문화별 이전 최적 좌표나 다른 프로필 DPS를 가져오는 메타러닝이 아니다.
- **관측된 문제와 발상 이유:** 하나의 Warlock 프로필에서 v312가 v290보다 못했고, v313 여러 전문화에서는 서로 다른 스탯 분포에 따라 탐색 품질을 검증 중이다. 특정 전략을 26개 DPS 전문화 모두의 기본값으로 단정하기 어렵다. 한 전문화에 약간 유리한 정책이 다른 전문화에는 불리할 수 있으므로 **한 번의 새 프로필 내에서 여러 생성기의 장단점을 조기 관측하여 배분**한다는 가설을 고려할 가치가 있다.
- **메커니즘:** 사용자 입력으로 만든 **단 하나의 신규 SimC 소스와 동일 실행 조건** 안에, v290 전역 maximin/pairwise, v303 지역 탈출, v312 모델 기반 탐사 등 **후보 생성기만** 배치한다. 초기에는 각 생성기에 미리 정한 최소 탐사 예산을 지급하고, 실제 Native로 검증된 후보 DPS의 *기존 최고 확인 DPS 대비 개선분 / 소모 SimC iterations·시간*을 지연 보상으로 측정한다. UCB/exp3 등 단순한 보수적 bandit 할당으로 남은 예산을 갱신하고, 통계적으로 구분되지 않는 작은 차이는 과도한 승자독식으로 취급하지 않는다. 최종 정밀 확인은 한 번의 공통 v291 책임으로 처리.
- **효율적으로 작동할 합당한 이유:** 각 전략에 고정 1,008회를 모두 실행하는 것이 제품 기본 동작이라면 낭비일 수 있다. 새 프로필에서 빨리 유효 후보를 찾는 생성기에 더 할당하고, 일부 전역·실패 전략 예비 예산을 보장하면 **전문화별 DPS 지형과 가용 시간에 적응**할 수 있다. 단, 초기 reward는 희소하고 불확실해 조기 결정이 잘못될 수 있다.
- **장점:** 어떤 한 정책이 항상 최고라는 가정 불필요; 이미 있는 후보 생성기를 재사용; 성능이 떨어지는 전략에 5~10분 예산 전체를 소비할 위험을 분산할 수 있다.
- **단점·실패 조건:** 생성기 v290/v312는 각각 **단일 정책 순서·metadata·SHA 봉인**으로 v291에서 정확 재개를 검증한다. 이들을 별도 수정 없이 섞으면 journal drift/캐시 충돌·재시작 실패가 생긴다. 보상이 정밀 확인 전에 너무 희소하여 bandit이 추정 실패할 수 있고, 탐사 전략이 같은 후보를 중복 내면 실제 효율은 오히려 낮아진다. 모델/CPU가 무거운 v312를 항상 호출해선 안 된다.
- **기존 아이디어/정책 중복:** v303은 **각 지역 사이**에 예산을 배분하고, v312는 고정 8 UCB/5 region/3 uncertainty로 **후보 유형**을 배분한다. IDEA-007은 **서로 다른 생성기/정책 사이**의 예산 배분이므로 의미가 다르지만, 전체 자원 배분 기능은 높게 겹친다. IDEA-003(전역 셀), IDEA-002(지역 반경)는 포트폴리오에 담길 생성기의 내부 로직일 수 있다.
- **통합 판단:** \`EXTEND\`이지만 **시기상 후순위**. v291 위에 또 하나의 Native 실행기를 쓰지 않는다. 초기에는 기존 v290 vs v312 두 **후보 생성기만 분리된 pure propose 함수**로 재구성할 수 있는지 확인하고, 원본 SHA·프로필·단일 Native 캐시/중복 방지·취소/재개와 per-generator 메타데이터를 하나의 연구용 세션으로 봉인한다. 독립 A/B 실험에서는 **정책별 세션을 계속 분리**해 공정 비교로 사용한다.
- **반증 시험:** (1) 상태 재구성/seed/캐시/중복/취소 회귀를 **Native0**으로 먼저 보장; (2) 후보 배분 방법을 균등/고정(예: v312 8/5/3)/보수적 bandit으로 ablation; (3) 8 DPS 전문화×2 신규 조건에서 **독립 정책 단독 실행** 대비 동일 wall(5·10분) 및 총 iterations 예산에서 320+ 확인 최고 DPS·SEM·시간별 AUC·worst-case loss를 평가; (4) 실패/정체한 정책이 CPU/메모리·Native 예약을 더 많이 쓸 경우 철회.
- **효율이 생길 *필요조건*:** 서로 다른 정책이 **실제 상보적인 유망 좌표**를 제안하고, 초기 Native 관측이 남은 예산에 대한 상대 정책 효과를 어느 정도 예측해야 한다. 이미 v290 하나가 일관되게 우세하거나 정책들이 거의 같은 벡터를 내면 포트폴리오 오버헤드는 불필요.
- **증거/표기:** 아이디어 등록만, 독립 정책 시험 외 신규 Native 0회. 95는 실제 SimC에서만 판단하며 후보 생성기 보상값이나 UCB confidence를 임상/95% 근거로 표시하지 않음. 제품 26전문화 범용성/전역 최적 보장 금지.
