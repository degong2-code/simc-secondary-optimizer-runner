# IDEA-008 — 사전 고정 최종 후보의 독립 Native 홀드아웃 확인 (Post-Selection Holdout Confirmation)

- **제안:** 2026-11-11, v313 8/8·v314 15/16 실제 신규 프로필 결과 확인 후.
- **상태:** `IDEA_ONLY / INTEGRATE_FINAL_DECISION_ONLY`. 구현 0, 해당 아이디어 신규 Native 0, 사용자 기본 v290 불변.
- **책임:** 탐색 좌표 생성이나 SimC 효과·DPS 재구현이 아닌 **최종 관측 1순위·실질적으로 다른 근접 대안의 선택편향을 통제한 확인 측정 정책**이다. 전역 최적 증명은 아니다.

## 1. 관측 원인 및 고유한 문제

- 신규 v313 8조건에서 v290 관측6/v312 2; 신규 v314 16조건 중 정확히 15조건 완전 완료(v290 11/v312 4), 1조건 시간 상한 부분 완료. 완전 완료한 23조건에서 선택쌍 명목 95% 분리는 **0**. [v313 Actions](https://github.com/degong2-code/simc-secondary-optimizer-runner/actions/runs/42843524976), [v314 Actions](https://github.com/degong2-code/simc-secondary-optimizer-runner/actions/runs/42846073820).
- 현재 v291의 `confirmed_selected_pair_95` 및 v316의 checkpoint 최고점은 **측정값을 관측하고 상위 후보를 선택한 뒤 동일한 값으로 비교**한다. 이 경우 최고점의 우연한 상승을 포함하는 선택편향, 후보 전체 다중 비교를 제거하지 못한다. 이 문제는 v312 예측 RMSE나 v290 다중 측정 횟수 증가만으로 해결되지 않는다.
- 기존 벤치마크의 *별도 신규 프로필/초기 seed로 알고리즘 일반화 검증*은 **동일 세션에서 선정한 우승 CHMV 벡터 자체의 새로운 SimC 확인**과 목적이 다르다.

## 2. 아이디어 — 2단계 결정과 검증 분리

1. **탐색(현행 유지):** v290/v312의 기존 원본 Native 측정, 가능하면 v316 요청별 비용 계측에서 정밀 확인 후보들을 축적한다. 5~10분은 목표 시점이나 종료/기각의 강제 한계로 두지 않는다.
2. **결정 봉인:** 추가 Native 확인을 시작하기 *전에* 현재 관측 1순위와, 사용자에게 의미 있게 다른 CHMV 분배의 근접 대안 최대 K개를 **사전에 고정**한다. 동일 후보를 반복 과대계수하지 않으며 지정된 벡터·L/O/E·총량·상한·원본 프로필/바이너리·전투조건·호출 순서·seed 계획을 새 검증 매니페스트로 봉인한다. K는 소규모로 시작하되 고정값이 검증된 최적 설정인 양 표시 금지.
3. **독립 실측 홀드아웃:** 선택 단계에서 한 번도 사용하지 않은 별도 실제 SimC 난수 시드/반복을 각 사전 고정 후보에 실행한다. **이미 관측한 탐색 결과를 이 확인 표본으로 재사용 금지**. SimC JSON2 원본 DPS·SEM과 정확한 iterations·seed·SHA·실행시간·cache identity를 기록한다. 정확한 SimC 별도 seed/threads 문법과 상관구조는 먼저 원본으로 검증하며 임의 가정하지 않는다.
4. **95% 의사결정:** 동일 프로필 내 각 **미리 지정된 비교**의 독립 확인 차이, SEM, 명목 95%를 계산한다. 여러 대안 비교 시 사전 고정된 비교 집합과 95% 가족단위 조정(예: Bonferroni 또는 Holm을 적용할 수 있는 독립/보수적 비교 조건)을 명시하고, 계산하지 못했다면 **관측 최고 / 명목95 / 다중선택 미검증**만 표시한다. 승자가 통계적으로 구분되지 않아도 최고 관측 벡터와 근접 대안을 제공한다.
5. **결과 불일치 시:** 홀드아웃에서 순위가 뒤집히면 독립 확인 결과를 보고하되, 그 결과를 보고 더 좋은 새 후보를 다시 고르고 **그 같은 홀드아웃을 새 승자의 독립 검증으로 재사용하지 않는다**. 재선택은 추가 검증 계획 및 별도 미사용 표본이 필요하다.
6. **비용 관리:** 한 후보에 최소 얼마의 추가 iterations가 필요한지 실측 뒤 결정. 후보 전체가 아닌 **소수 shortlist**에만 발동하며, 시간·CPU/I/O·Native 허용량 대비 확인 정보 가치가 낮으면 `UNCONFIRMED_OBSERVED_BEST`로 종료 가능. 10분 초과 자체는 탈락 사유가 아니다.

## 4. 작동 이유·장점

- 많은 후보를 관측한 뒤 같은 측정으로 최고를 정하면, 관측 1순위는 확률적으로 상향 편향될 수 있다. 사전 봉인한 shortlist의 새 SimC 확인값을 사용하면 **선택에 사용하지 않은 표본**으로 후보 DPS를 평가할 수 있다.
- 결과는 더 높은 DPS를 반드시 찾는 아이디어가 아니라 **잘못된 승자 확정과 불안정한 근접 대안 제시를 줄여 사용자가 실제로 따를 목표의 신뢰도를 높이는 아이디어**다.
- 26 DPS 전문화/다양한 새 프로필에 확장될 가능성은 있으나 현재 확증되지 않았다.

## 5. 단점, 반증 및 승격 조건

- **단점:** 새 Native·iteration·wall·JSON2/I/O·저널/캐시·상태관리 증가. 독립 시드의 재현성/분산과 SimC thread/시드 동일성 검증 필요; 선택과 홀드아웃을 잘못 섞으면 편향 교정 주장 자체가 무효. 전역 최적/95 확정 자동 보장 없음.
- **최소 오프라인 실증:** 이미 존재하는 v313/v314 원본 정밀 결과를 이용해, 사후 선택에서 같은 값을 독립 확인으로 재활용하는 것이 왜 무효인지 synthetic replay로 차단하는 계약 테스트. 이 단계 신규 Native 0.
- **최소 실제 Native:** **v317 단일 프로필 계측 검증 이후에만** 후보 두 개를 사전 봉인하고 별도 seed/iter로 재확인하는 소규모 opt-in. 기존 정확 캐시/봉인/취소·재개를 깨뜨리지 않아야 한다. 비용 동일 기준에서는 reserve에 할당한 반복을 다른 탐색에서 제거한 효과도 포함.
- **공정 평가:** 동일 총 iterations 비교, 동일 실제 wall과 더 긴 실행 시점 비교를 분리. 독립 결과의 CHMV ranking 안정도, 순위 역전 비율, CI 및 비용 대비 제대로 구분 가능한 비율; 전문화별 다름을 기록. 5/10분 이후에도 효율적인 추가 확인은 허용.
- **보류/반증:** 작은 shortlist 확인이 종종 승자를 뒤집어도 실제 근접 대안 품질/신뢰도 개선을 입증하지 못하거나, 추가 비용이 크고 신뢰도/결정 효용이 개선되지 않으면 HOLD. 독립 신규 시드가 검증되지 않거나 데이터 누출이 있으면 결과 차단.
- **증거 등급:** `IDEA_ONLY`. 최초 신규 실측 이전에 95% 가족단위 판정 확정이나 실제 DPS 향상이라고 표현하지 않는다.
