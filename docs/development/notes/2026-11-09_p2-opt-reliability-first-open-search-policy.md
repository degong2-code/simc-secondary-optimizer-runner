# P2-OPT · 신뢰성 우선, 알고리즘 비고정 탐색 원칙 (2026-11-09)

- **Capability:** `OPTIMIZER.POLICY`
- **Keywords:** CHMV absolute rating, SimC noisy DPS, 탐색 품질, 알고리즘 교체, 거리/해상도, 95%, CPU, Native.
- **Prior evidence:** [P3-HW](2026-11-08_p3-hw-real-optimizer-multiscale-architecture.md) v290 다중 해상도 제안기·v291 영속 실행기, [P3-HAE](2026-11-09_p3-hae-short-budget-precision-contract.md) 실제 8×35 scout+2×320 confirm Native10, [HAI 최신 상태](../../PRODUCT_CANONICAL_STATUS_20261109_P3_HAI.md). 현재 알고리즘의 구현·부분 실측은 최적화 품질의 일반적 우월성이나 전역 수렴 증명이 아님.
- **Decision:** `POLICY_DOCUMENTED / REUSE → COMPARE → REPLACE_IF_BETTER`. **고정 목표는 SimC DPS를 기준으로 신뢰할 만한 최적 CHMV 절대 rating과 의미 있는 대안을 찾아 사용자에게 근거·불확실성을 정확히 전달하는 것. 고정하지 않을 것은 그 목표를 달성하는 탐색 알고리즘·스케줄·거리 척도·임계값·반복수·종료 기준의 구현이다.** 특정 방식을 '이대로 구현'하는 정책이 아니며, 반례·실측 또는 더 설득력 있는 대안이 확인되면 설계를 수정·대체한다.
- **목표 우선순위:** ① 후보 발견의 충분성·결과 신뢰성·누락 위험의 적절한 표현 ② 유망 후보/실질적으로 다른 대안의 탐색·판별 품질 ③ 품질을 보존하거나 개선하는 데 드는 계산 자원 ④ 로컬 PC 실행시간·사용자 경험. 호출 수 감소, SEM 감소 또는 CPU-second당 후보 수 증가만으로 품질 향상을 인정하지 않는다.
- **탐색 아이디어의 지위:** 전역→국소→정밀화, 간격을 점차 줄이기, 유망 후보만 미세 탐색, 복수 anchor, 비균등 샘플링은 **비구속적 후보 전략**이다. 반드시 이 순서·단계를 따르거나 기존 v290 다중 해상도를 고수할 필요 없음. 대체·혼합·중간 생략·역순 재탐색까지 증거 기반으로 허용.
- **거리 예시:** 후보 `x,y`의 `L1(x,y)=Σ_{s∈CHMV}|x_s-y_s|`와 단일 스탯 차이 10, L1 50/100/200 등은 **설명용**이며 확정 임계값·스텝·종료 조건이 아니다. T/B, 고정 L/E/O, 스탯별 엄격한 `c_final[s]<T/2` 등 실제 제약은 보존한다.
- **거리의 한계:** 같은 L1 거리라도 어느 스탯에서 어느 스탯으로 이동했는지, 현 위치·경계·비선형 상호작용에 따라 DPS 변화는 다를 수 있다. 거리≠DPS 손실, 근접≠대체 가능, 작은 이동≠무가치. 거리만으로 후보를 일률 배제하거나 탐색 종료를 인증하지 않는다.
- **누락 가능성:** 한 최상위 후보 주변만 좁히면 이격된 봉우리·평탄 영역·경계 인접 후보를 놓칠 수 있다. 탐색 다양성/재시작/교차 검증 등은 유효한 수단이지만 필수 구현 목록은 아님. 미탐색 영역의 개선 확률을 검증 없이 수치화하거나 '미발견=부재'로 단정하지 않는다.
- **대안 개방:** 적응형 메시·좌표/방향 탐색·확률적 제안·서로게이트/베이지안 제안·경쟁 후보 순차 재측정·다양성 보강·다른 정지 규칙 등은 모두 **탐구 예시**이지 의무 기능이나 신규 개발 Gate가 아니다. 데이터가 유리함을 보이는 접근으로 이동할 수 있어야 한다. SimC가 유일한 DPS/효과 판정자이며 예측 모델 출력은 실제 SimC DPS 증거가 아님.
- **추가 계산 가치:** 개선 가능성, 아직 확인하지 않은 영역의 정보 가치, 순위 변동·선택 편향, 95% 제한 판정, 유의미하게 다른 후보, 사용 가능한 계산 예산을 종합해 판단하되 특정 산식/임계값을 선승인하지 않는다. 충분한 탐색 증거 없는 조기 종료, 반대로 근거 없는 무조건 2000회 소비 모두 피한다.
- **결과 표현:** 관측 1순위, 추가 확인의 범위, 통계적으로 구별되지 않는 후보, 95% 비교의 대상·다중선택 한계, 전역 최적 미증명을 구별한다. SEM/좁은 신뢰구간은 평가된 후보의 정밀도이지 탐색 공간의 포괄성 입증이 아님.
- **동등조건 평가:** 동일 SimC 실행 바이너리/프로필·장비/옵션·시즌 예산·전투조건·후보 제약 및 정당하게 비교 가능한 Native/iterations 예산에서 기존 대비 best observed/재확인 DPS, 후보 다양성·미탐색 영역 대응, 순위 재현성, 제한된 95% 판별, 계산량을 함께 비교한다. 잠정 최선 벤치마크는 '확인한 후보집합의 최선'이지 전역 oracle이 아니다. 선택 편향을 고려한 독립 확인 없이 발견 품질 승리 선언 금지.
- **PC 차이:** 웹 UI는 입력·출력, Native SimC는 사용자 **로컬 CPU**. CPU-second/벽시계/메모리는 하드웨어·동시 실행 영향이 크므로 PC 간 절대 순위 지표로 삼지 않고, 가능하면 같은 환경·동일 예산 비교 또는 보조 효율 지표로 사용한다.
- **변경 선택:** 먼저 INDEX/기존 v290/v291·v094/실 Native 영수증·정확 SHA 캐시를 `REUSE`; 현재 부족한 정보가 연결만의 문제면 `CONNECT`, 효과 근거가 있는 부족분만 `EXTEND`. 새 방법이 더 나은 신뢰성·탐색 품질 또는 동등 품질에 더 낮은 비용을 보이면 과거 설계와 달라도 `REPLACE`를 적극 검토한다. 현재 방법에 맞춰 대안 평가 기준을 왜곡하지 않는다.
- **Changes:** 이 문서는 향후 P2 설계·평가의 **판단 원칙**만 갱신. v290 다중 해상도·v291 정밀화·기존 테스트/로그/영수증·P1-WEB 우선순위·제품 제약을 수정하지 않음.
- **Verification:** GitHub 문서 기록만 수행. **코드 실행/오프라인 테스트/CI/새 Native/DPS 실측 모두 NOT_RUN**; 기존 Actions/Native는 출처 명시된 역사 증거로만 인용.
- **Remaining:** P1 웹 source→session E2E 병목 연결과 분리하여, P2 시 기존 알고리즘의 실패 양상·품질 기준·실제 대안 비교 실험을 작은 범위로 설계. 일정한 고정 스텝/거리/95% Gate를 먼저 코드로 박지 말 것.
