# P2 · 속도 적응형 22점·복수 영역 정밀화 실험 (2026-11-10)

- **Capability:** `OPTIMIZER.POLICY`, `DEV.CONTINUITY`.
- **Keywords:** SimC actual NEW_NATIVE scout timing, 22 percentage points, multi-region, 3D CHMV simplex, diagonal transfer, measured discovery trajectory, equal iterations, 95% selected pair.
- **Prior evidence:** [승인 기준점·비례 정규화 설계](2026-11-10_p2-percentage-grid-proportional-normalization.md), [v298 opt-in 및 실패 반례/합성6형상](2026-11-10_p2-percentage-grid-opt-in-engine.md), [v290 reliability-first](2026-11-09_p2-opt-reliability-first-open-search-policy.md), [기존 Native10](2026-11-09_p2-real-native-ten-case-region-audit.md).
- **Decision:** `EXTEND` — 단순 격자 전역후보 교체가 좁은 off-axis 고점에 불리했던 사실은 **격자+복수 영역 정밀화 전체 방안의 실패가 아니다**. v290 기본 탐색/95%/캐시·취소·재개는 무변경. 이번 새 코드는 실험적 opt-in: `v298`은 SimC 실제 신규 scout 소요시간·현재 남은 시간·scout/confirmation iterations 비율을 이용하여 11→15→**22**→31→41 기준점을 선택할 수 있다(빠른 200-call 세션에서도 22 접근 가능). 근거 없이 최댓값을 확대하거나 격자 전체를 SimC로 실행하지 않음.
- **Changes:** (1) v298 `choose_points_from_throughput`는 최소 3건의 `NEW_NATIVE` scout 실측과 명시 wall-time budget 없으면 11점을 유지. 향후 정밀 호출 수에 20% 보수적 여유를 가정하고 실제 confirm/scout iteration 비율로 wall-time forecast; headroom이 충분할 때 22/31/41이 가능하며 이는 초기 휴리스틱이다. (2) v299 새 순수 제안기는 총 budget 중 약 40%(상한200, 남은 정밀화 예산 확보)를 **초기 전역 조사**에 사용, v290 저불일치 샘플과 v298 백분율 격자 후보를 함께 maximin 평가. (3) 이후 관측 평균 DPS-SEM으로 정렬하되 총 B의 10% 이상 멀리 떨어진 최고 관측점들을 최대 5개 지역으로 보존하고 최고 지역을 조금 더 자주 방문하는 순환 정밀화. 기존 양 축 이동에 더해 2개 상승+2개 하강 **대각선 정수 이동**으로 격자 축에 고정되지 않음. (4) v291 `multiregion_percent_grid=True`는 명시적 `percentage_grid_points=11/22/"auto"`와 함께 사용될 때만 opt-in; 새 source SHA가 기존 별도 봉인에 추가되므로 기존 v290/v298 세션·같은 binary/scenario/iterations Native cache를 의도하지 않게 재해석하지 않음. (5) 후보 요청/선택 95%는 SimC 증거로만 평가하며 synthetic 함수값을 SimC DPS로 표시하지 않음.
- **Verification:** 초기 코드 반영 후 offline focused test와 한 번만 실행하는 synthetic six-shape 비교의 실제 결과를 확인하고 본 노트·EVIDENCE_INDEX를 보강. 신규 Native 수행 전 실 계산시간 재측정 근거 없음; GitHub Actions 실행시간을 후보당 SimC 속도로 오용 금지.
- **Remaining:** multi-region 탐색의 각 지역 위치·빈도·최적화 예산은 아직 연구용 경험칙이다. 초기 40%, 10% 분리 거리, 최대5지역, 20% confirmation reserve, 22/31/41 threshold **모두 자동 공식 채택 불가**, 실제 multi-spec Native 탐색 속도/유의미한 새로운 고점 발견률/동등 총 iterations와 사용자 허용 시간에서 비교 후 결정. 특정 스탯 rating 고정 기능·일반 웹 활성화 미구현; 전역 최적/선택 편향 family-wise 95% 미입증.
- **Efficiency:** 코드가 한 번에 한 후보만 제안·실제 Native 중복 호출0; 이전 v298 bounded lattice cache 재사용, 정확한 후보 B/하한/상한·고정 O 회계 재사용. regional centers는 기존 observations로만 도출해 별도 영구 DB 불필요, 취소·재개 시 determinism 보호. CPU/메모리 및 hidden Native 예산 증가 여부를 비교에서 계속 기록.
