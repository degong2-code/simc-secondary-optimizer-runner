# P2 · 적응형 백분율 기준점과 비례 정규화 설계 (2026-11-10)

- **Capability:** `OPTIMIZER.POLICY`, `DEV.CONTINUITY`.
- **Keywords:** percentage reference grid, adaptive resolution, proportional normalization, bounded redistribution, exact integer CHMV, SimC throughput, multiple regions, user-pinned stat.
- **Prior evidence:** [v290/v291 신뢰성 우선 원칙](2026-11-09_p2-opt-reliability-first-open-search-policy.md), [실 Native10](2026-11-09_p2-real-native-ten-case-region-audit.md), [합성 다봉형 비교](2026-11-09_p2-multimodal-equal-count-offline-audit.md), [사용자 상한·격자 조합](2026-11-10_p2-user-configurable-final-stat-cap-and-grid-study.md), [비율 경계 후보](2026-11-10_p2-fractional-bounded-neighbor-proposals.md). 기존 실측/캐시만 재사용하며 새 Native 증거는 없음.
- **Decision:** `EXTEND / DESIGN_APPROVED_NOT_IMPLEMENTED` — 사용자 승인으로 기준점 격자와 비례 정규화를 다음 P2 비교 설계로 채택. 초기 `m=11`(각 스탯 허용 구간의 양 끝 포함, 10개 백분율 간격)은 시작값일 뿐 고정 정책이 아니다. 실제 SimC 평균 처리시간·iterations·병렬 처리량·메모리/CPU·허용 시간/Native 예산으로 해상도를 늘리거나 줄인다. 절대 rating 간격 금지.
- **Changes:** ① 각 스탯의 자유분배 B 가능 구간 `[lo_i,hi_i]`를 L/E 하한, 사용자 최종 T 상한, 고정 O 및 기타 고정 조건으로 계산하고 그 구간을 동일한 백분율 기준점 `m`개로 나눈다. 구간이 고정된 축은 한 점만 가진다. ② 기준점 벡터 `r` 중 합계가 B를 넘지 않는 가장 큰 격자 합계 `S*=max(sum(r)≤B)`를 기준 shell로 선택한다. 각 shell 벡터를 `B/S*`로 비례 확대해 목표 자유분배 총량 B에 대응시킨다. 예: T=B=2000, cap60%, 각 축 0~1200, m=11이면 간격120, S*=1920; `(1200,360,360,0)` → `(1250,375,375,0)`. 단순 대칭 조건의 기준 shell 조합은 745개(경계 보정·정수화·중복 제거 전)이며, 실제 수는 축별 L/E/O·고정치·상한·해상도에 따라 달라진다. `S*=0` 또는 양의 shell이 없으면 해상도를 올리거나 결정적 feasible seed로 대체해 0 나눗셈을 금지한다. ③ 확대 후 상한/하한을 넘는 축을 경계에 고정하고 남은 총량을 아직 여유가 있는 축에 원래 기준점 비율로 재배분한다. 새 경계에 닿는 축을 다시 고정하는 bounded proportional water-filling을 반복한다. 양의 기준점 가중치가 모두 소진되거나 0인 경우에는 남은 가용 용량을 이용한 결정적 fallback으로 처리하며, 실제 feasible capacity가 없을 때만 그 후보를 제외한다. ④ O는 B 바깥 고정치로 절대 확대/재배분하지 않고 `c_final=c_base+o`; L/E는 B 내 하한으로만 보호하며 중복 가산하지 않는다. 최종 cap은 설정 가능한 inclusive `floor(pct*T/100)` 기준. ⑤ largest-remainder 정수화와 경계 확인으로 합계 B를 정확히 맞추고, 동일한 최종 정수 rating 후보는 SimC 실행 전에 deduplicate하되 원본 격자 provenance는 보존한다. 작은 소수점/반올림 차이만으로 전체 시나리오를 차단하지 않는다.
- **Verification:** 문서/설계 갱신만 수행. 테스트/Actions는 수동 실행·dispatch하지 않고 Native·외부 시즌 수집도 실행하지 않는다. `docs/development/**` 변경은 저장소의 path-filtered offline focused CI를 자동 트리거할 수 있으며, 실행 시 그 영수증은 offline 범위로만 해석한다. 745는 T=B=2000, 네 축 0~1200, m=11, 120 단위 격자에서 S*=1920인 단순 조합론 예시이지 실 DPS나 일반 조건의 고정 후보 수가 아님.
- **Remaining:** bounded normalization·zero-weight fallback·largest-remainder·candidate provenance/dedup는 아직 코드 미구현·미검증. `m`의 자동 선택 규칙과 초기 후보 예산은 실제 전문화/iterations별 SimC throughput pilot 후 결정. 격자 방식이 v290보다 높은 고점을 더 잘 찾는지 동등한 Native/iterations 예산에서 비교해야 한다. 특정 최종 스탯 rating 고정은 향후 확장 제안: 해당 축을 equality constraint로 축소하고 O를 제외한 잔여 B를 나머지 축에 분배; 현재 제품 입력 기능은 아님.
- **Efficiency:** 기준점 조합 열거/비율·정수 계산은 SimC Native보다 매우 저렴하지만 조합 수는 해상도에 따라 빠르게 증가(4축·합계 shell은 대략 `m^3` 규모). 작은 pilot로 평균 wall-clock/CPU-second와 병렬 처리량을 재고 목표 계산 예산에 맞춰 `m` 및 실행 후보 수를 조절한다. 초기 전 영역 분산 탐색 후 서로 다른 복수 유망 영역과 미탐색 영역을 함께 세분화하며, 한 방향 우위·단일 고점 집중을 가정하지 않는다. 예측/격자 자체는 DPS 증거가 아니며 최종 판단자는 SimC다.
