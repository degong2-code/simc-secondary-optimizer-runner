- **Decision:** `REUSE`: v291 원본 Native 경로를 유지하고 **`case_timing_trace=False` 기본값**의 별도 opt-in 시간 계측만 추가. 독립 최적화 엔진·새 SimC 발동 모델·새 G/J/F/O 수집·기존 v313/v314 실측 수정 없음.
- **Changes:** [계측 모듈](../../../runner/v316_optin_case_time_trace.py)은 실행기 요청별 `plan_pending_seconds`(후보 계획+pending 저장), `request_preflight_seconds`(프로필 입력 요청 구성·회수/캐시 여부 확인), `engine_execute_seconds`(v065 호출 시간 **SimC 순수 시간 아님**), `native_json_ingest_seconds`, `journal_checkpoint_seconds`를 추가 append-only `V316_CASE_WALL_TRACE.jsonl`에 저장. `invocation_elapsed_seconds`는 **해당 프로세스 단위의 monotonic 시각**이며, `uuid` 기반 프로세스 invocation 구분과 원본 `V291_SESSION.json` 바이트 SHA/원본 case 키·input/Native SHA·iterations·phase에 결속된다. 디폴트에서는 파일 생성, V291 저널·세션 봉인·case identity·cache 키 변형이 없음.
- **5/10분 검증:** 로그의 모든 row가 단일 프로세스에서 최초 케이스부터 단조 시간으로 확인돼야 `300`/ `600`초 시점 **이미 완료된 precision 확인 후보**의 관측 최고 DPS·SEM을 출력한다. 중간 재개·캐시 데이터·누락 시간·다른 invocation이면 **`UNAVAILABLE_PARTIAL_OR_RESUMED_OR_CACHE_TIMINGS`**로 표시한다. 프로필/시즌 환경 생성 전처리 시간은 포함되지 않으며 end-to-end 사용자 클릭 체감 시간으로 과장하지 않음. 두 선택 정밀 후보의 명목 95%는 다중선택/승자편향을 보정하지 않고, 전역 최적 입증을 제공하지 않는다.
- **크래시 대응:** 원본 journal/progress 커밋 뒤 trace를 기록한다. 중단/디스크 오류가 그 사이 발생하면 **원본 Native를 중복 호출하지 않고** trace 행 누락을 드러낸다. 계측 파일의 SHA·시간·시퀀스가 변조되면 opt-in에서 차단하고, 디폴트 원본 결과 replay는 그대로 가능하다. cache-only 재개는 과거 원본을 새 실행시간으로 재측정하지 않는다.
