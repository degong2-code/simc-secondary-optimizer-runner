# v380 — v274 전체 카탈로그 컴파일 입력과 제품 필수 G/J/F/O 증거 분리

- **Capability:** `ENVIRONMENT.SEASON`, `SOURCE.SEAL`, `BUDGET.GJFO`, `PRODUCT.E2E`, `DEV.CONTINUITY`.
- **Keywords:** v380, v274, v275, v241, catalog compiler dependency, 9 inputs, existing source producer, optional enchant, no gate, no full season item proof.
- **사용자 직접 결정:** 수집기/검증기는 제품이 **실제 사용하는 사실과 선택 기능**에 충분한 증거가 있으면 다른 아이템이나 WSE의 미해석을 전체 완료 Gate로 삼지 않는다. 과거 기술지도와 실 Native 영수증을 재사용하고 기존 엔진을 중복 재구현하지 않는다.
- **실제 코드 확인:** `v274.NEEDED` 9개는 `v191→v211→v213` **완전 카탈로그 아티팩트의 입력 조건**이다. `v191`은 v167 장비/정확 13×5 v168 티어/v189/v190/SimC generated3을 요구하고 `v211`은 봉인된 SimC6+manifest를 필요로 한다. `v212.compile_fresh_installed_environment`는 `v213.verify_catalog`를 실행하므로 해당 카탈로그를 임의로 생략하고 설치할 수 없다. **하지만 영구 마부/임시 마부 카탈로그 파일의 존재가 G/J/F/O 선택값·품질·시즌 소속을 각각 독립 인증한다는 뜻은 아니다.** base 예산은 기존 v222 G/J/F/O 소유자, 선택 UI 품질은 v196/v220 별도 증거로 처리.
- **기존 해결 구현 재발견:** `v275_pinned_simc_compiler_inputs.py`는 이미 v229/v189 SHA 영수증과 pinned Git tree를 재사용하여 v211 6원본 및 generated permanent/temporary/gem을 v217으로 봉인하고 캐시한다. `v216.collect_wago_new_season_source`가 v275와 `v276_sealed_tier_compiler_source`를 호출하고, `v274.discover`가 그 출력으로 9입력 조립한다. v275의 기존 합성 테스트는 동일 원본 재사용시 신규 HTTP 0을 확인. 과거 P3-CD의 'v211/permanent producer 미완료'는 당시 상황이고 현재 구현 누락으로 재단정하면 안 된다.
- **v380 변경:** `v274.COMPILER_INPUT_OWNER`에 9입력의 실제 기존 공급자/소비 목적만 기록, `compiler_input_impact`가 pending 및 complete 단계 결과에 `catalog_input_missing`, `full_catalog_compilation_pending`과 '이 결과 자체는 G/J/F/O numeric proof/UI 품질 승인 아님'을 명시. 미사용 아이템 전수 시즌 소속이 필요하다고 추론하지 않음. `v274.discover/compile_collected` 원래 판정/실제 컴파일 호출/원본 SHA/Native/API/캐시 그대로. `tests/test_v274_zero_history_source_compiler_wiring.py`에 9개 초기 누락, 완료, 영구 마부 파일만 누락, 기존 v275 공급자 확인/READY 미승격 회귀 추가.
- **검증:** Windows 2026-11-12 ZIP의 `v274` Git blob SHA `e941edee87e5b85c5284191a14227243876e608b`가 현재 격리 브랜치 원본과 일치함을 확인. 동 바이트에 동일 수정 적용한 blob SHA `3513838ad7d9255e8056708c50b4363dd1ca7443`가 GitHub 수정 blob과 일치. Python `py_compile` 및 실제 `v274.discover` 사용 로컬 합성 **17 assertions PASS/0 FAIL**, Native/실 HTTP 0. **새 전체 pytest/Actions/Windows 실사용 v216/실 시즌 READY 미실행**, 기존 v275 테스트 PASS는 새로운 PASS로 재기재하지 않음.
- **중요한 남은 과제:** 사용자 v163 434후보 JSON에는 `source_compilation.status/missing` 또는 `zero_history_build`가 없으므로 *실제* 첫 미완료 입력은 이 파일만으로 확인 불가. 9입력 중 선택하지 않은 품목에만 관련된 원본이 부족할 경우, 현재 `v212` 완전 카탈로그 의존성을 최적화해 base 설치를 분리할 수 있는지는 정확한 원본/필수 계약에서 판단해야 함. 지금 임의로 bypass하면 인증되지 않은 catalog을 READY로 승격하므로 하지 않음. 다음은 실제 Windows Build 원본 영수증의 `missing` vs `G/J/F/O owners`를 대조해 **필수 부족/컴파일 전용 결손** 중 실제 병목부터 연결할 것.
- **비용/권한:** 새 수집기/AI/Native/대량 파일 분석/캐시 폐기 0, 기존 소형 소스와 정확한 blob 재사용. 격리 브랜치만 변경하고 main/Project UI/주 개발 채팅 권한 불변.
