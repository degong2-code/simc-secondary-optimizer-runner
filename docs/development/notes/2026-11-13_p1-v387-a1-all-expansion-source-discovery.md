# v387 — A1 현 시즌 자동 발견: WCL 확장팩명 하드코딩 제거와 동일 출처 조인

- **Capability / ID:** `ENVIRONMENT.SEASON` / A1 (A2·A3 연관). [최신 사용자 일반화 PASS 정책](../POLICY_ZERO_SOURCE_AUTODISCOVERY_GENERALIZATION_20261113.md) 및 [v386 최신 단일 인계](../../CHAT_CONTINUITY_HANDOFF_20261113_P1_V386_ZERO_SOURCE_GENERALIZATION.md).
- **Prior evidence:** v385에서 `v155.select_midnight_expansion`은 `"midnight"` 문자열 기반이며 `v163`은 `wcl.midnight_zones`만 소비. v242→v216은 이 원본의 빌드·source stage를 봉인하지만 현재 활성 시즌을 이름만으로 인증하지 않음. 기존 v343/v344는 70783 동일 조건 Windows 성공, v347 무키 보류. [WCL GraphQL 스키마](https://www.warcraftlogs.com/v2-api-docs/warcraft/worlddata.doc.html)는 `zones(expansion_id: Int)` 생략 시 전 확장팩 zone 반환, [Zone 스키마](https://www.warcraftlogs.com/v2-api-docs/warcraft/zone.doc.html)는 `expansion: Expansion!` 및 `frozen: Boolean!`을 명시.
- **Decision:** **CONNECT/EXTEND**. 새 시즌 발견 서비스/새 AI 실행/하드코딩된 현재 날짜·이름을 만들지 않는다. 기존 WCL 확장팩 인덱스 + 단일 모든-zone 조회로 원본 후보만 수집하고, 기존 v163 동일 빌드 DB2/raid/M+ 관계가 유일하게 식별될 때까지 `READY` 금지. WCL expansion ID ≠ DB2 ItemSparse expansion ID.
- **Changes 1 — v155:** `runner/v155_season_api_probe.py`에서 `select_midnight_expansion` 제거. 기존 4 Blizzard + 최대 2 WCL bounded 요청 유지. 모든 확장팩 `zones { id name frozen expansion { id } encounters { id name journalID } }`를 **한 번** 조회해 `wcl.zones[].expansion_id`를 포함하고, 같은 응답의 `expansions[].id`에 존재하는지 검증. 빈 목록/중복/잘못된 ID/누락 확장팩·무효 zone은 보류. 새 원본 `zone_source_scope=ALL_WCL_EXPANSIONS`이며 **source candidate only**. 예전 `midnight_zones`를 새 원본으로 만들지 않는다. 단일 응답 원래 1.5MB 제한, 신규 후보 행 상한 1500·encounter 행 80 유지; limit 초과 시 fail closed.
- **Changes 2 — v163:** `runner/v163_zero_seed_db2_join.py`에서 신규 `wcl.zones` 우선, 구 역사 `midnight_zones`는 이전 영수증 **읽기 호환**만. 현행 WCL M+ zone과 raid zone의 `expansion_id` 일치 조건을 적용해 다른 확장팩의 raid가 섞이는 오류를 방지. WCL 확장팩 ID는 `wcl_expansion_id`, 실제 DB2 장비 expansion은 별도 `expansion_id`; `season_membership_completely_verified=False` 유지. 동일 raid명 타 확장팩 구별을 위해 `named_zone(...,wcl_expansion_id=...)` 선택 검증.
- **Changes 3 — v242/v216:** `runner/v242_authenticated_season_source_stage.py`에서 `provider_zone_scope=ALL_WCL_EXPANSIONS_PENDING_DB2_JOIN`, `runner/v216_environment_build_coordinator.py` 기존 `v163.build_index`에 선택된 `wcl_expansion_id` 연결. v217 봉인/기존 v212 수치/고정 예산/SimC/승인 Gate는 우회하지 않는다.
- **Tests written:** 새 `tests/test_v155_all_expansion_autodiscovery.py`: 다른 확장팩 이름/ID, 전체 WCL query/2회 호출 계약, 손상·목록 미존재/중복·비밀키 비노출. 기존 `tests/test_v163_db2_zero_seed.py` synthetic CSV 통합에 다른 확장팩의 동일 raid·교차 확장팩·원본 ID 누락 차단 조건 추가. 기존 v385 `tests/test_v113_local_web_api_offline.py`의 동일 빌드 이벤트 안전 차단 테스트도 유지. **전체 Python unittest·Actions/Windows/정상 키 실제 HTTP ZERO-SOURCE 시험은 이번에 수행하지 않았다.**
