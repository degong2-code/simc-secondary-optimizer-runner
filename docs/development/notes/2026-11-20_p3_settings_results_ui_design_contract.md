# P3 — 환경 설정·결과 확인 UI 디자인/행동 계약 (2026-11-20)

**상태: 사용자 제시 방향을 반영한 구현 기준안 — 화면 코드 미수정 / 새 ZIP 미배포.** 최신 사용자 요청: 환경 설정·결과 확인의 과도한 전체폭 구분선을 줄이고 정렬·가독성을 개선하며, ‘공식 업데이트 확인’에서 발견한 무반응형 피드백 오류를 같은 화면의 기타 기능에도 예방한다. 이 문서는 시각적 취향뿐 아니라 **기존 기능과 실제 사용자 행동 계약을 보존하기 위한 구현 규칙**이다. 사용자와의 추가 디자인 세부 피드백이 오면 최신 직접 결정 우선.

## 1. 검증한 기존 코드와 근본 원인

- 실제 소스: `runner/webui/index.html`의 `#view-settings`(시즌 원본·API credentials·SimC manager), `#view-results`(실행 현황/세션 복원/최종 DPS·SEM·95%·CHMV 및 대안), `runner/webui/styles.css`, `runner/webui/app.js`.
- `styles.css`의 v361/v363 스타일 재정의 및 후속 v364 배치 규칙 때문에 `#view-settings .panel`, `#view-results .panel`, `.section-head`, `.fold`, `.fold[open]>summary`, `.field input`, `.btn`, `.metrics>div`, `.result-footer`, `.alt-row`, `.alt-metric` 등에 `border-bottom` 또는 `border-right`가 중복 결합된다. 화면 폭을 따라 늘어나는 구분선과 연결되지 않은 선의 정렬감 문제가 발생한다.
- `#view-settings .simc-update-actions .btn`는 `flex:1 1 145px`을 사용하여 세 버튼 각각이 가로로 길게 늘어나는 조건도 있다.
- v643 `공식 업데이트 확인` 인라인 진행 상태 수정은 이미 적용됐고 사용자 PC에서 상태 및 TLS fallback이 실제 관찰됐다. 원격 TLS 실패가 UI 응답 실패를 뜻하지는 않는다. 새 디자인은 해당 상태/대체 링크·기능을 그대로 보존한다.

## 2. 최종 UI 원칙

**목표:** 최소한의 장식으로 사용자 선택, 현재 상태, 다음 행동 및 SimC 결과를 명확히 보여준다. 골드 강조의 다크 테마를 유지하되, 모든 항목을 상자/테두리로 감싸거나 모든 행을 밑줄로 구분하지 않는다.

1. **의미 있는 계층만 구분:** 페이지 제목 > 핵심 섹션(시즌 환경 / SimulationCraft / 실행 현황 / 관측 결과) > 접을 수 있는 하위 그룹 > 필드/수치 > 보조 설명. 같은 그룹의 연속적인 장식 선 삭제. 큰 섹션 경계에만 희미한 단일 구분선 **필요 시 1개**. 하위 `summary` open border/패널 border/버튼 border가 동시에 겹치지 않도록 한다. `border-bottom`을 모든 요소의 기본 장식으로 사용하지 않는다.
2. **여백과 타이포를 우선:** 데스크톱 큰 섹션 간 24~32px, 하위 그룹 14~20px, 필드 그룹 8~12px을 시작 기준으로 삼고 반응형에서 적절히 축소한다. 제목 16~18px, 설명/본문 12~14px, 필드 라벨 12~13px, 힌트 11~12px 가독성을 기준으로 조정한다. 실제 레이아웃에 맞게 수치 조절 가능. 장식적 대문자 영문 라벨은 위계를 보조할 때만 유지.
3. **최대 가독 폭·열 정렬:** 내용 폭을 데스크톱에서 약 1080~1160px 범위 내로 제한하는 시안을 우선 비교하되 전체 제품 헤더 폭은 바꾸지 않는다. `.two`/계절 field grid는 좌측 라벨/입력 시작선이 정렬되도록 하며 줄바꿈 가능한 `minmax(0,1fr)`와 overflow-wrap을 적용. 모바일(~680px)에서는 1열, 긴 경로·SHA·상태문은 자연스럽게 줄바꿈. 가로 스크롤이나 뷰포트 밖 액션 없을 것.
4. **입력과 버튼 자체가 인터랙티브하게 보일 것:** 모든 필드에 긴 밑줄을 일괄 적용하는 대신 얇고 낮은 명도의 입력 배경 또는 짧고 명확한 경계를 사용. 명확한 focus ring, hover, invalid, disabled 시각 상태 보존. 액션은 기본적으로 내용 폭에 맞춘 단정한 버튼(인접 8~10px 간격), 의미 있는 Primary와 Secondary 분리; 3개 버튼이 각각 1/3 폭의 긴 선이 되지 않도록 한다. 좁은 화면에서만 자연스러운 줄바꿈/세로 배치. 클릭 영역은 가능하면 40px 이상.
5. **상태는 해당 액션 바로 근처:** 클릭 즉시 진행/대기/성공/실패/다음 행동을 같은 기능 패널에 표시한다. `#notice`는 보조 요약일 뿐 유일한 오류 표시 경로가 아니어야 한다. 이미 진행 중이거나 선택 불가일 경우 이유를 설명; 비활성 요소는 실행 상태 또는 필수 조건을 나타낸다. 실제 진행률을 알 수 없을 때 임의 %를 표시하지 않는다.
6. **결과 숫자 우선, 통계 의미 보존:** 관측 DPS, SEM, **관측 1순위와 95% 우위 판정 분리**, 절대 CHMV rating·비율, 의미 있게 다른 근접 대안, 전역 최적해 보장 아님을 먼저 쉽게 파악할 수 있어야 한다. 각 수치 행마다 긴 separator는 삭제; 제한된 부제·여백·타이포와 필요한 표/차트만 사용. 95%를 다른 확률 기준으로 대체하거나 자동 ‘확정’ 표시하지 않는다. 결과 없을 때의 empty 상태 및 저장 세션 불러오기 경로 유지.
7. **보안과 기능 연결 불변:** `id`, `name`, `data-view`, `data-view-panel`, `type`, `value`, `hidden`, `required`, `disabled`, `aria-live`, `aria-* rules`, 시뮬레이션 요청 포맷 및 서버 API 변경 금지(명시적 UX 결함 교정 시 별도 최소 수정 가능). `label for`와 `details/summary`, `role=status`, 키보드 focus/Enter 및 keyboard navigation 유지.
8. **CSS 누적 예외 축소:** v361/v363 등 기존 상충 규칙의 실제 사용 위치를 먼저 기록하고 중복 border 정의를 우선 통합·삭제한다. 단순 최종 파일 끝에 추가 `!important` override를 쌓아 문제를 감추지 않는다. 스타일 변경은 **`#view-settings`, `#view-results` 범위에서 우선**, `#optimizer-form`의 기존 UI·레이아웃 회귀 금지.

## 3. 페이지별 구성

### 환경 설정
- 페이지 소개/상단 안내는 제목·설명·하나의 동작을 기준선에 배치, 실선 장식보다 여백 사용.
- 1영역: 시즌 환경. 승인 상태와 `시즌 환경 확인·설치`이 가장 잘 보이게. 인증정보·시즌 변경·Native 고급 옵션은 기존 접기 항목으로 보존. `#season-build-running`, `#season-build-stage`, `#season-build-summary`, 미완료 진단을 같은 영역의 상태 계층으로 연결. 비동기 수집은 실제 단계/경과만.
- 2영역: SimulationCraft. `#binary` 경로를 데스크톱에서 독립 행(긴 경로를 줄바꿈/가로 스크롤 정책 결정), `#revision`과 선택 정적 캐시를 정돈된 2열/모바일 1열로 배치. 업데이트는 기존 `#simc-update-panel` 접기 아래 **현재 관리 상태 → 업데이트 확인/확인한 버전 설치/이전 버전 복원 버튼 → 바로 아래 `#simc-update-candidate` 상태와 다음 행동 → 수동 .7z 경로**의 순서로 조정하는 것을 기본안으로 삼는다. 직접 지정한 외부 `simc.exe`와 앱 관리 버전은 의미가 다른 상태이므로 혼동하지 않게 안내.
- 외부 인증 오류는 ‘TLS 검증 실패 · 자동 설치 중지 · 공식 다운로드/수동 .7z 사용 가능’처럼 짧은 문구를 기본으로 하고 필요 시 세부 설명/링크로 분리. **TLS 검증을 우회하지 않으며 원격 파일 자동 받기 활성화하지 않는다.**

### 결과 확인
- 1영역: 실행 상태(현재 세션 ID/진행 Native 회수/현재 작업 상태/중단·재개) + 복원/세션 목록은 보조 접기. 실행 중 버튼/단계는 바로 근처 상태 문구 표시. 결과가 없더라도 세션 복원 경로 노출.
- 2영역: 핵심 결과. `#dps`·`#sem`을 명확한 2열 핵심 지표, `#conf95`을 별도 통계 판정으로 구분; `#budget`과 `#stat-bars`의 **절대 rating·비율**은 정확하게 유지. `#alt-count`와 `#alt-list` 대안은 각 대안별 묶음/공백으로 구분하고 과도한 테두리 삭제.
- 결과의 ‘관측 1순위/95% 미확정/전역 최적해 미입증’ 문구를 임의로 삭제하거나 과장하지 않음. 성능·캐시 관련 데이터는 표현만 정리.

## 4. 단계별 실제 수정 계획 / Acceptance

**Phase A — 계약·선/구성 목록 정리 (이번 요청)**  
기존 DOM ID/JS 바인딩/사용자 action-state 표 작성, CSS 겹치는 selector 확인, 위 디자인 계약 문서화. **HTML/CSS/JS 제품 파일 변경 0**, ZIP 새 배포 0. 판정 기준: 범위·시각 위계·동작·보안·검증 원칙이 문서로 남을 것.

**Phase B — 환경 설정 UI 소규모 스타일 수정**  
관련 CSS 중복선 정리 → 필요 최소 HTML grouping/접기 순서 조정 → 보이는 상태/진행/오류와 버튼 연결 QA. 기존 `id` 보존; 실제 업데이트/시즌 준비/API credential 코드는 필요한 연결 결함만 수정. PC 브라우저 데스크톱/모바일 폭·키보드 및 Node DOM event tests 확인. 문제가 없다면 추가 Gate 신설 금지.

**Phase C — 결과 확인 UI 소규모 스타일 수정**  
실행 영역/결과 지표/CHMV·95%/대안 스타일과 정보 위계 통일. 기존 `renderResult`, `progress`, 세션 저장·재열람/취소·재개·95% 표현의 실제 DOM 바인딩 유지·회귀; 선 정리로 숫자·단위/표가 더 읽히도록.

**Phase D — 전역 ‘무반응’ 액션 경로의 필요한 부분만 보완**  
기존 주요 액션의 ① 이벤트 연결 ② 클릭 즉시 로컬 상태 ③ 성공/오류의 같은 위치 표시 ④ busy 이유 ⑤ 작업 후 이동 및 데이터 흐름을 정적/모의 시험으로 확인하고, *실제 누락 또는 UX 불능*만 수정. 이미 올바른 시즌 빌드 진행률/상태·신규 SimC v643 인라인 피드백은 중복 구현하지 않음. 장기 탐색 등 미지원 범위 확대 금지.

**Phase E — 배포 확인·종료**  
Windows 기존 ZIP workflow, local HTTP/Node UI 테스트와 변경 selector의 UI 확인; 기존 Native64, Blizzard/WCL/DB2 시즌 원본 수집 및 26 DPS 전수 반복하지 않음. 새 ZIP에서 실제 같은 기능·요소 값이 표시되고 화면/입력이 깨지지 않으면 STOP. 회귀 항목·수정 완료·기존 역사 영수증·미검증 실 PC를 분리 기록. 작업은 격리 브랜치만; main/v003/Project UI/Work OS/공식 상태 승격 금지.
