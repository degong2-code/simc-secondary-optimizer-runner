2026-11-23 KST · 격리 브랜치 `probe/chat-cache-v035-20261024`.

## 최신 사용자 직접 결정

- **사용자 PC에서 v677 자동 T 준비·DPS 실측은 지금 수행할 수 없으므로 보류한다.** 앞으로 일반 개발을 그 시험 완료까지 중단하거나 반복해서 PC 캡처를 요구하지 않는다. 사용자가 PC 사용 가능 상태를 알리면 그때 기존 설치본 `검증 환경 1 → 선택 환경 검증·준비` 한 번으로 확인한다.
- 그 대신 PC 없이 진행 가능한 다른 제품 과제를 이어간다. 첫 작업은 사용자 화면에서 **어느 단계가 실제로 실패했고, 무엇이 확인되었으며, 다음 조치와 기술 진단은 무엇인지** 직접 읽히도록 하는 것이다.
- 미검증을 READY로 표시하거나, 필요 이상 Native·시즌 원본·효과 인증을 추가하지 않는다.

## 실제 기존 결손

- v677 read-only `/api/v1/environment/installed-budget`는 409 `EXISTING_INSTALLED_BUDGET_SOURCE_NOT_VERIFIED` 아래 여러 서로 다른 원본 검증 실패를 합쳐, 사용자에게 첫 실패 위치를 식별할 근거가 없었다.
- UI는 전역 `요청 차단 또는 오류`와 별도 버튼 비활성 사유가 있었으나, 이번 기존 설치본 예산 단계·장비 선택 단계 및 B8·기름 선택 실패를 `단계 / 확인된 사실 / 다음 조치`로 일관되게 설명하지 못했다.

## 변경한 실제 사용자 소비 경로

1. 서버의 **기존** v677 조회 함수가 실행하는 원래 검사 순서를 그대로 따라, 처음 실패한 체크 범주만 `detail.check`에 고정된 코드로 제공한다. 요청 조건, 동일 빌드 원본 디렉터리, v216 설치 조회, v212/v113 원본, 영약·기름 물리 원본, v113 프로필 입력, 기본4보석, O=0, G/J/F/O·B/T 회계의 어느 검사를 통과하지 못했는지 분류한다. 별도 인증 Gate·추가 원본 조회·Native 없음. 동시 설치본 상호 동등성 검증 없음. API 기존 409/422 `code`와 성공 schema·예산은 불변.
2. 브라우저 API에서는 허용된 `detail.check`만 읽는다. `기존 예산 GET`과 `같은 SHA 장비 후보 GET`의 실패 시점을 구분하고, 환경 준비와 최적화 실행 실패에 대해 **차단 단계 / 확인된 문제 / 다음 조치** 한국어를 화면 가까이에 표시한다. 코드·HTTP·안전한 예외 유형은 사용자가 펼쳐 보는 기술 진단 또는 상단 차단 안내에서 확인할 수 있다. 프로필·SHA·원본 경로·비밀키 원문을 노출하지 않는다.
3. `WEB_SELECTED_B8_EXACT_STATIC_VARIANTS_PENDING`과 `WEB_SELECTED_B8_PROFILE_SOURCE_PENDING`은 기름 실패와 분리한다. 기름 물리 입력 오류, `LOCAL_SESSION_PRECHECK_BLOCKED`은 별도 안내하며 내부 원인이 응답에 없으면 **원인 미확정**을 명시한다.
4. 변경된 사용자 선택은 이전 차단 설명을 현재 사실로 계속 표시하지 않는다. 정확히 재검증되면 이전 진단이 사라지며, 사용자 입력·세션·캐시·예산 권위 및 SimC 실행 허용 기준은 변경되지 않는다.
5. 기존 v568의 독립 클릭 핸들러 시험에서 새 UI 상태 직접 참조로 발생한 첫 실패는 독립 실행 조건을 유지하도록 국소 교정했다. 추가 staged-budget/실제 JS 분류 회귀를 기존 API/Windows 오프라인 CI에 연결했다. 신규 사용자 PC 실측 **0회**.
